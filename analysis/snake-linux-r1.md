## 1. 需求理解（SCQA）

### 1.1 情境（Situation）
需求方是工程背景的独立开发者，此前已在流水线中投放并通过了笼统的「贪吃蛇游戏」需求（snake-game，已归档）。本需求是那次评审的延续与细化：需求方进一步明确了运行平台（Linux 终端）、实现约束（Python 从零实现、仅标准库、不依赖第三方游戏框架）、玩法基线（经典贪吃蛇）与交付要求（README、干净退出、单命令启动）。需求方最终目标是要一个**可直接运行、可玩、可维护**的终端游戏产物，而非仅一份设计文档。

### 1.2 冲突（Complication）
贪吃蛇虽是最经典的游戏类型之一，但「Linux 终端 + Python 标准库从零实现」这一组合缺乏现成的、完全对齐的参照物：市面主流终端贪吃蛇要么是 C/C++ 实现（如 nSnake 基于 ncurses、bsdgames 的 snake），要么依赖图形界面或第三方框架。同时终端程序有独特的质量陷阱：退出后终端状态（光标/回显/颜色）若未恢复会破坏用户体验，非 TTY 环境下直接运行会报出晦涩错误，这些在需求原文中已被需求方显式点出，说明其对「终端程序特有质量」有明确预期。

### 1.3 问题（Question）
如何将「Linux 终端 + Python 标准库从零实现的经典贪吃蛇」这一原始需求，分解为结构完整、边界清晰、验收可测的功能需求与非功能需求，供评审确认与后续实现对齐？

### 1.4 结论（Answer）
本需求的核心价值是：交付一个**零第三方依赖、单命令启动、干净退出、经典可玩**的 Linux 终端贪吃蛇（Python 实现），并以「从零实现 + 完整 README」使其同时具备玩具趣味与教学参考价值；本分析文档则将该价值固化为 15 项可测试的 FR 与 6 项可度量的 NFR。

## 2. 需求范围（MECE 边界）

### 2.1 做什么
- 在 Linux 终端（TTY）内运行的贪吃蛇游戏，Python 实现，仅使用标准库；
- 经典玩法闭环：方向控制、吃食物增长、撞墙/撞自身判定结束；
- 单命令启动、tick 间隔可配置；
- 干净退出：恢复终端原始状态（光标、回显、颜色），Ctrl+C 安全中断；
- 交付 README：运行方式、键位表、配置项、已知限制；
- 非 TTY 环境下给出明确报错而非晦涩异常。

### 2.2 不做什么
- 不做图形界面/浏览器/移动端版本（平台明确限定 Linux 终端）；
- 不做 Windows/macOS 平台适配（curses 跨平台兼容与 windows-curses 等不在范围内，需求方已明示 Q1 答案）；
- 不做网络对战、多人在线、排行榜服务器等联网能力；
- 不做音效、动画特效等多媒体能力；
- **不做技术选型与实现方案论证**（如 curses 与裸 ANSI 转义序列的取舍、代码文件划分、数据结构设计等均属 How，超出分析师职责红线；需求层面约束见第 4 节 NFR 与第 6 节假设）；
- 不做第三方游戏框架/引擎集成（需求方明确「从零实现」）。

## 3. 功能需求（FR，MECE 分组）

分组维度声明：按**游戏生命周期阶段**（启动初始化 → 游戏主循环 → 输入控制 → 结束清理 → 交付物）归组，各阶段互不重叠、合起来覆盖「从启动到退出」的完整用户旅程。

### 3.1 启动与初始化
| 编号 | 功能点 | 描述 | 优先级 | 验收标准 |
|------|--------|------|--------|----------|
| FR-01 | 单命令启动 | 在 Linux 终端执行单一命令（如 `python3 snake.py`，文件名以交付为准）即进入游戏，无需安装任何第三方包 | 高 | 干净 Linux 环境（仅系统 Python 与标准库）下执行启动命令，游戏界面 3 秒内出现，无报错 |
| FR-02 | 非 TTY 环境报错 | 在非终端环境（如管道、重定向、无 TTY 的 cron）运行启动命令时，输出人类可读的明确错误信息（说明需在终端中运行）并以非零退出码结束 | 高 | `python3 snake.py < /dev/null`（或等价非 TTY 场景）输出明确中文/英文错误提示且退出码 ≠ 0，无 traceback 之外的无意义输出 |
| FR-03 | tick 间隔可配置 | 游戏帧间隔（tick）可通过启动参数或配置项调整 | 高 | 支持至少一种配置方式（参数/配置文件）设置 tick；配置值在 50ms–1000ms 范围内生效；不配置时使用默认值 |
| FR-04 | 终端能力检查 | 启动时检测终端尺寸是否满足最低可玩要求，不满足时给出提示 | 中 | 在 ≤ 20×10 的终端中启动，输出可读提示且不产生乱码界面 |

### 3.2 游戏主循环
| 编号 | 功能点 | 描述 | 优先级 | 验收标准 |
|------|--------|------|--------|----------|
| FR-05 | 蛇的移动 | 蛇按 tick 间隔自动沿当前方向前进一步 | 高 | 不操作输入时，蛇每 tick 前进 1 格，方向保持不变 |
| FR-06 | 方向控制 | 支持 WASD 与方向键（↑↓←→）两种方式控制蛇头方向 | 高 | 游戏中按下 W/↑ 蛇向上、S/↓ 向下、A/← 向左、D/→ 向右，响应时间 ≤ 1 个 tick |
| FR-07 | 反向移动禁止 | 蛇不能直接 180° 掉头撞向自身（如当前向右时按左键无效） | 高 | 蛇向右移动时按 A/←，蛇保持向右，不死于「反向自杀」 |
| FR-08 | 食物生成 | 每局开始生成 1 个食物；食物被吃后在新位置重新生成；食物不与蛇身重叠 | 高 | 食物吃掉后 1 个 tick 内出现新食物，且新食物坐标与蛇身全部坐标均不同 |
| FR-09 | 吃食增长与得分 | 蛇头到达食物所在格时：蛇身长度 +1，得分 +1，并实时刷新显示 | 高 | 连续吃 N 个食物后蛇身长度 = 初始长度 + N，显示分数 = N，全程界面无闪烁错位 |
| FR-10 | 碰撞判定与结束 | 蛇头撞到墙壁边界或自身身体时游戏结束 | 高 | 蛇头越界或与身体任意一节重叠后，游戏进入结束状态，不再继续移动 |
| FR-11 | 结束画面 | 游戏结束后显示结果信息（如最终得分、按任意键退出提示） | 中 | 游戏结束后界面稳定显示得分与退出提示，无残留蛇身残影 |

### 3.3 输入控制
| 编号 | 功能点 | 描述 | 优先级 | 验收标准 |
|------|--------|------|--------|----------|
| FR-12 | 暂停/继续 | 游戏中可随时暂停与继续，暂停时画面冻结、蛇不移动 | 中 | 按暂停键后蛇停止移动且无输入误触发；再按一次恢复；暂停期间 tick 计时不累计 |
| FR-13 | 安全退出 | 任意时刻按退出键（如 q）或 Ctrl+C 均可退出游戏 | 高 | 游戏任意状态下（含暂停、结束画面）触发退出，进程在 1 秒内干净结束，无残留子进程 |

### 5.3 差异化机会
1. **机会：零依赖 + 单命令启动**。nSnake 需编译、bsdgames 需安装，本需求「纯标准库 + `python3 snake.py`」把运行门槛降到最低，适合极客尝鲜与教学场景（来源：nSnake README 需编译安装、本需求原文明确标准库约束）。
2. **机会：终端卫生（干净退出）作为一等公民**。显式要求恢复光标/回显/颜色、非 TTY 友好报错，这一质量维度在多数开源终端游戏中未被系统化承诺，是差异化卖点（来源：需求原文明确约束）。
3. **机会：从零实现的教学参考价值**。代码职责分离、可读性好、README 完整，可作为「用标准库写终端游戏」的入门范例——这是 C/C++ 竞品难以直接提供的价值（来源：需求原文验收标准）。
4. **风险：功能丰富度远低于 nSnake**。关卡系统、多种模式、皮肤定制等 nSnake 特性不在本需求范围（见 2.2），若需求方后续扩展预期未管理好，会形成「功能少」的观感；需在评审中确认功能边界（来源：nSnake README 特性列表）。
5. **风险：终端兼容性长尾**。不同终端对光标/颜色的支持存在差异（SSH、老旧终端），「行为一致」的 NFR-06 需要明确覆盖矩阵（见 Q-07）。
