# 机制改进方案与问题跟踪（zteam）

> 2026-09-11 制定（v1.0.0 复盘产出）。每项含：**问题 → 机制维度 → 文字约束维度 → 触发时机 → 状态**。
> 设计规范见 `docs/mechanism-checklist.md`（触机三要素 + 上线下四步）。

---

## P1-1　假修复（FO 标 fixed 但源码零改动）

- **机制**：`issue fix` 命令入口校验——扫描该单归属模块 `code/{模块}/` 下是否有 **mtime > 提单时间**的文件；
  无则**拒绝**（rc=1）并提示；确有正当理由（纯文档/环境类）走 `issue fix --force <理由>`（留审计 + 告警人工复核）。
- **文字**：`roles/fo.md`「标 fixed 前自证：改动文件:行 + 逐条对应复测建议」；`roles/mto.md`「复测必核 mtime 与调用点」。
- **触发时机**：`issue fix` 调用瞬间（命令入口，不可绕过）｜**触发者**：命令入口｜**兜底**：不登记则单停留 open → tick 续派。
- **依据**：SOCSIM-05/06 复测方代码核证「调用点仍 1 处」「常量仍 4096」但单已被标 fixed。
- **状态**：✅ 已实施（2026-09-11，含真实验证）

## P1-2　FO 无拒绝通道（沉默 → 死循环空转）

- **机制**：新增 `issue reject <iid> <理由>`——清归属回"待定" → 自动进 SE 分单队列；字段 `reject_count`、`owner_locked`
  （SE 复核后锁定，不可再拒）；`reject_count ≥ 2` 告警。配套：FO worker 完成时校验"负责单均非 open"（否则 tick 重派+告警）。
- **文字**：`roles/fo.md`「根因不在本模块**必须 reject**，禁止沉默不标、禁止硬改」；`roles/se.md`「复核 reject：认同改派/拆分；不认同打回并锁归属」。
- **触发时机**：`issue reject` 命令入口 + tick 检测待归属单｜**触发者**：FO / 调度器｜**兜底**：`reject_count` 告警 + 归属锁定防循环。
- **依据**：UARTIO-01 空转 34 轮、SOCSIM-05 三轮——FO 无法拒修只能沉默或假修。
- **状态**：✅ 已实施（2026-09-11，含真实验证）

## P1-3　UT 假绿（未锚定真链）

- **机制**：`module_checks.json` 配置化静态断言（必须存在的调用点 / 常量上限），`release_module it DONE` 门禁校验；
  IT 产物须含真链执行日志证据。
- **文字**：`roles/mto.md`「IT 必须含真引擎用例；mock 只算 UT」；`roles/te.md` 用例评审加「真链证据」检查项。
- **触发时机**：`release_module it DONE`｜**触发者**：命令入口｜**兜底**：拒绝登记（迭代不收口）。
- **依据**：SOCSIM-06 UT 用假监视器全绿但真链 503；SOCSIM-05 UT 只覆盖单路径。
- **状态**：✅ 已实施（2026-09-11，含真实验证）

## P1-4　长任务截断（FO/STO 反复被上下文/工具上限打断）

- **机制**：进度文件协议（`FIX进度.md` / `ST进度.md`）：worker 启动读、结束写；`release_module it DONE` /
  `release_st_v2 DONE` 时**校验进度文件存在且标"全部完成"**。
- **文字**：`roles/fo.md`（新增）、`roles/sto.md`（已有）写分轮次协议。
- **触发时机**：worker 启动（query 注入）+ 登记门禁校验｜**触发者**：worker / 命令入口｜**兜底**：登记被拒 → 下轮续跑。
- **状态**：✅ 已实施（FO query 加续跑指引；STO 分轮协议已在用）

## P2-5　通知噪音（正常兜底 vs 真故障混同）

- **机制**：alarms 加 `level`（INFO/ALERT）；`drain_alarms` 输出带前缀；INFO 合并/静默，ALERT 立即推。
- **文字**：docs 定义 INFO（正常兜底，如"worker 死亡已重置"）vs ALERT（blocked/停滞/门禁 FAIL）分类标准。
- **触发时机**：alarm 产生点 + tick 末 drain｜**触发者**：代码内联｜**兜底**：—
- **状态**：✅ 已实施（2026-09-11，含真实验证）

## P2-6　僵尸 worker（进程活着但无输出）

- **机制**：stale 恢复扩展——claim 进程存活但日志 >N 分钟无写入 → kill + 重置（长任务角色排除或阈值放宽至 60 min）。
- **文字**：roles 写「长任务须周期性写进度文件（既是续跑依据，也是活性心跳）」。
- **触发时机**：tick 巡检（每 5 min）｜**触发者**：调度器｜**兜底**：—
- **状态**：✅ 已实施（2026-09-11，含真实验证）

## P1-7　多引擎并发 504 假失败（4 vCPU 节点资源竞争）

- **机制**：真链测试全局文件锁 / 端口池（同时仅 1 个引擎实例）。
- **文字**：`roles/mto.md` / `roles/sto.md`「单实例串行，禁并行多引擎」。
- **触发时机**：测试脚本启动/退出｜**触发者**：脚本内锁｜**兜底**：—
- **状态**：✅ 已实施（2026-09-11，含真实验证）

## P0-8　机制"半通"复发（新机制只验前半段）

- **机制**：`docs/mechanism-checklist.md` 登记表 + `diagnose` 一致性检查（已登记机制是否声明触机三要素）；
  机制回归挂 `release_qa DONE` 门禁（**发布前必跑**）。
- **文字**：本规范四步法（回路验证 / 不变式 / 回归 / 同步）+ skill 收录。
- **触发时机**：`release_qa DONE` 门禁｜**触发者**：命令入口｜**兜底**：拒绝发布。
- **依据**：3 次半通（再激活未回 in_dev → 静默停滞、st 无续跑分支、FO 上下文截断）。
- **状态**：✅ 已实施（`docs/mechanism-checklist.md` 落盘 + `_mechanism_selftest` 挂 `release_qa DONE` 门禁）

## P1-9　判据与实现语义脱节

- **机制**：用例评审门禁要求用例含「实现依据」字段（引用的字段/常量/语义）；缺则拒。
- **文字**：`roles/te.md` + 用例模板「判据必须**数学可达**并引用实现依据」。
- **触发时机**：用例评审（`release_st_case` / `release_module case PASS`）｜**触发者**：命令入口｜**兜底**：拒绝 PASS。
- **依据**：STB-03「RSS 增幅 ≤20%」对有界缓存**数学不可达**，白判 FAIL 一轮。
- **状态**：✅ 已实施（2026-09-11，含真实验证）
