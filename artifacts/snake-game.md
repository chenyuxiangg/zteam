## 1. 需求理解摘要

需求方（Telegram 用户）要求从零开发一个基于 Python 的终端贪吃蛇游戏：纯命令行运行、不依赖图形界面，实现经典玩法（方向控制、吃食物增长、撞墙/撞自身判定结束），且不得套用现成游戏框架，需自主设计实现。交付物应终端可玩、控制流畅、代码结构清晰、可运行并附使用说明。技术选型（curses / 裸 ANSI 等）由分析师细化并经评审确认。

## 2. 功能需求（FR）

| 编号 | 功能点 | 详细描述 | 优先级 | 验收标准 |
|------|--------|----------|--------|----------|
| FR-01 | 游戏启动 | 在终端中以单一命令启动游戏，进入即显示游戏区域（场地边框、蛇、食物）与操作提示 | 高 | 在终端执行启动命令（如 `python3 snake.py`）后 ≤ 2s 内出现游戏界面，含边框、初始蛇与初始食物；非 TTY 环境（如管道/重定向）下启动则输出明确错误提示并以非零码退出 |
| FR-02 | 蛇的移动 | 蛇按当前方向以固定时间间隔（tick）自动前进一格；tick 间隔可配置 | 高 | 启动后蛇自动移动；默认 tick 间隔 ≤ 200ms，经配置文件或命令行参数可调（如 50–500ms 范围） |
| FR-03 | 方向控制 | 支持方向键与/或 WASD 控制蛇头方向；按任意键后当前 tick 内生效 | 高 | 上/下/左/右键或 W/A/S/D 可分别改变方向；同一 tick 内多次按键取最后一次有效输入；向当前方向的反方向按键被忽略（禁止 180° 掉头）；未知按键不报错、不影响游戏 |
| FR-04 | 食物生成 | 食物在游戏区域内随机生成，位置不与蛇身重叠；食物被吃掉后立即重新生成 | 高 | 每次生成位置均在场地边界内且不在蛇身任意一节上；吃掉食物后下一 tick 内新食物出现；场地内存在至少一个合法空位时食物必可生成 |
| FR-05 | 吃食物增长 | 蛇头移动到食物所在格时判定吃到：蛇身长度 +1、分数按计分规则累加 | 高 | 吃到一个食物后蛇长度增加 1 节；分数增加量符合计分规则（默认每食物 +1，见待确认 Q3）；增长表现为蛇尾不缩短、后续移动保持新长度 |
| FR-06 | 碰撞判定与游戏结束 | 蛇头撞到场地边界或自身任意一节时游戏结束；结束画面显示最终分数并给出操作选项 | 高 | 蛇头越出边界或与自身重叠时，1 个 tick 内进入结束状态；结束画面显示最终分数与"退出/重玩"提示；结束状态下蛇停止移动、输入不再改变游戏状态 |
| FR-07 | 退出与重玩 | 游戏中可随时退出；结束后可退出或重新开始 | 中 | 游戏中按退出键（默认 q）立即干净退出并恢复终端原始状态；结束画面按重玩键（默认 r）重置全部状态（分数清零、蛇复位、食物重新生成）并开始新一局；按退出键退出 |
| FR-08 | 暂停/继续 | 游戏中可暂停与继续，暂停期间蛇停止移动、输入不导致碰撞或误操作 | 中 | 按暂停键（默认 p）后游戏画面保持、蛇停止移动；再按一次继续；暂停状态在画面上有明确标识 |
| FR-09 | 使用说明 | 交付 README，说明运行方式、依赖、操作键位表、配置方式 | 高 | README 包含：运行命令、Python 版本要求、依赖安装方式（如有）、完整键位表、tick 间隔等配置方法、已知限制（如终端最小尺寸要求）；按 README 操作可在干净环境跑通 |

| NFR-06 | 可配置性 | 关键参数可调 | tick 间隔、场地宽高、初始蛇长（如实现）可通过命令行参数或配置文件调整，非法配置值给出明确报错并拒绝启动 |

## 4. 边界与异常场景

| 编号 | 场景 | 预期行为 | 对应 FR |
|------|------|----------|---------|
| E-01 | 终端窗口小于游戏场地（或最小尺寸要求） | 启动时检测并给出明确提示（如"终端尺寸不足，需要 ≥ 20x40"），不进入半渲染状态；运行中窗口缩小到不足时暂停或提示 | FR-01、FR-06 |
| E-02 | 非 TTY 环境运行（管道/重定向/脚本调用） | 检测到无可用 TTY 时输出错误信息并以非零退出码退出 | FR-01 |
| E-03 | 运行中终端窗口尺寸变化（resize） | 行为需定义：至少不崩溃、不产生乱码；推荐方案：检测 resize 后重绘或提示（见待确认 Q10） | FR-01、NFR-02 |
| E-04 | 蛇身占满全部场地（无空位生成食物） | 判定为胜利：游戏结束并显示胜利信息与最终分数，而非死循环或崩溃 | FR-04、FR-06 |
| E-05 | 同一 tick 内收到多次方向输入（含快速连按） | 取最后一次有效输入；反向输入被忽略，不允许因连按导致 180° 掉头穿身 | FR-03 |
| E-06 | 未知按键 / 非方向键输入 | 静默忽略，不影响当前游戏状态与画面 | FR-03 |
| E-07 | Ctrl+C（SIGINT）中断 | 捕获并执行与正常退出一致的干净退出（恢复终端状态），不残留脏屏 | FR-07、NFR-05 |
| E-08 | 非法配置值（tick 间隔为负/0、场地过小等） | 启动时校验并给出明确错误信息，拒绝启动 | NFR-06 |
| E-09 | 食物生成位置恰在蛇头即将到达的格子 | 属正常情况：按正常吃食物逻辑处理，无特殊分支需求 | FR-04、FR-05 |
| E-10 | 重玩时上一局遗留状态 | 重玩必须重置全部状态（分数、蛇长、位置、速度、食物），不得残留上局数据 | FR-07 |

## 5. 依赖与假设

**外部依赖**
- Python 3 运行时（最低版本见待确认 Q7，默认假定 ≥ 3.8）；
- 终端环境：默认目标 Linux/macOS（Windows 支持与否见待确认 Q1）；
- 技术选型（需求原文授权分析师细化，候选如下，最终经确认）：
  - 方案 A：标准库 `curses`（推荐首选——标准库零额外依赖、自带终端恢复与无缓冲输入、跨 Unix 平台成熟）；
  - 方案 B：裸 ANSI 转义序列 + termios/tty 手动处理输入与终端状态（依赖更少、可控性高，但终端状态恢复与输入处理需自行实现，出错风险高）；
  - 若需 Windows 支持，curses 需 `windows-curses` 可选依赖，或采用 ANSI 方案 + Windows 控制台 API 适配。

**假设**（原文未明确、按常理假定，均列入待确认问题）
- A-1：单机单人本地游戏，无网络、无多人、无排行榜联机需求；
- A-2：蛇初始长度 3 格、初始方向向右、蛇头在场地左侧中部（Q9 确认）；
- A-3：默认场地尺寸建议 40 列 × 20 行字符（Q4 确认）；
- A-4：默认 tick 间隔 150ms 左右、随吃食物可加速（Q4、Q6 确认）；
- A-5：计分默认每吃一个食物 +1 分（Q3 确认）；
- A-6：键位默认方向键与 WASD 均支持，q=退出、p=暂停、r=重玩（Q2 确认）；
- A-7：无需最高分持久化存储（原文未提，默认不实现，Q5 确认）。
