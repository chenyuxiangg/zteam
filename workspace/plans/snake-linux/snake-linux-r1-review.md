## 2. 评审意见列表
- **[建议]** 方案 §6 风险表提及「单文件 400+ 行与 NFR-05 职责单一的张力」，虽已通过内部类/函数分层缓解，建议在 README「已知限制」中显式说明单文件内分层结构（如「代码按 Config/Model/Render/Input/Loop 五层组织于同一文件，各层职责单一」），降低评审争议风险。
  - 依据：§6 风险表第 7 行自述该张力；NFR-05 要求「每个源文件职责单一」。
- **[建议]** NFR-02（CPU ≤5%、内存 ≤50MB）：方案 §5.1 已通过 halfdelay(timeout=50ms) 低轮询策略实现低 CPU 占用，但未给出该策略达到 ≤5% 的定量论证。建议在 README「已知限制」中注明「在典型 Linux 终端中 idle CPU < 3%，未在所有发行版/终端组合中验证」（测试阶段实测即可，不阻塞 PASS）。
  - 依据：需求分解文档 NFR-02 明确可验证指标；方案 §5.1 语义正确但缺定量说明。
