## 2. 评审意见列表
- **[建议]** 方案 §1 覆盖 FR-16「游戏区域规格」的功能（画布 40×20/可见边框/坐标不出界/撞边框结束）但全文未显式出现 "FR-16" 编号。建议在 §1「做什么」或 §3.2 Renderer 职责中补标 FR-16，方便逐条验收勾对（对齐检查清单第 1 项的可审计性）。
  - 依据：需求分解文档 FR-16 为本轮新增需求；方案内容完整覆盖但 ID 缺失。
- **[建议]** r1-review 建议①（README 已知限制中声明单文件内分层结构）与建议②（NFR-02 CPU 定量说明）尚未落地于方案文本中——建议在进入 code 阶段前更新 §6 风险表或 README 大纲以承接。
  - 依据：r1-review 评审意见列表建议项；本轮方案文本与 r1 相同，未见修改回应。
- **[建议]** §3.3 时序图中标注 "halfdelay/tick 粒度阻塞轮询"，但 §5.1 伪代码实际采用 `stdscr.timeout(50)`（毫秒粒度）——halfdelay 仅有 100ms 粒度、无法支撑 50ms 最小 tick。建议在 §5.1 或 §3.3 显式注明弃用 halfdelay 改用 timeout 的理由（如 "halfdelay 最小粒度为 100ms，改用 timeout(50) 以支持 50ms 最小 tick"），避免后续实现者照 §3.3 字样误用 halfdelay。
  - 依据：Python curses 文档 halfdelay 粒度为十分之一秒；方案 §5.1 伪代码正确但 §3.3 术语有歧义。
