## 1. 数据结构

### 1.1 用户数据目录路径（运行期派生，不落盘常量）

| 字段 | 类型 | 来源/规则 |
|------|------|-----------|
| OS 判定 | `sys.platform` ∈ {"win32", "darwin", "linux"/"linux2"} | Python 标准库；启动时一次性确定，不重复探测 |
| Windows | `os.environ["APPDATA"]` 或 `Path.home() / "AppData/Roaming"` | `%APPDATA%`（win32 必有），缺失则 fallback |
| macOS | `Path.home() / "Library/Application Support"` | XDG 不适用 |
| Linux/Unix | `os.environ.get("XDG_DATA_HOME", str(Path.home() / ".local/share"))` | XDG Base Directory 规范 |
| 应用子目录 | `"SnakeGui"` | 固定名（与 v1.x 终端版 "Snake" 不复用——产品名升级） |
| 完整路径 | `{用户数据目录}/SnakeGui/` | mkdir(parents=True, exist_ok=True) 幂等 |

### 1.2 数据文件

**最高分文件 `highscore.json`**：

```json
{
  "schema_version": 1,
  "high_score": 1234
}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| schema_version | int | 是 | 数据格式版本号；当前 = 1（FO 写常量） |
| high_score | int | 是 | 最高分；≥0；无历史时 = 0 |

**偏好文件 `preferences.json`**（预留，本迭代不写，读则返回空字典；迭代 3 皮肤系统使用）：

```json
{
  "schema_version": 1,
  "skin": "classic"
}
```

> 本迭代 2 仅落地 `highscore.json`；`preferences.json` 的接口预留由 storage 模块提供（load/save/reset），但 game-app 暂不调用。

### 1.3 内存缓存模型（运行时）

| 对象 | 字段 | 类型 | 说明 |
|------|------|------|------|
| `HighScoreStore` | path | Path | JSON 文件绝对路径（构造期计算并 mkdir） |
| HighScoreStore | _cache | int | 内存中的最高分（构造期 load 一次；save 后更新） |
| HighScoreStore | _dirty | bool | True=有未持久化变更；进程崩溃兜底参考 |
| HighScoreStore | _lock_path | Path | 同目录下的 `.highscore.lock`（同进程内互斥，不需要 fcntl 跨进程） |

## 2. 数据传递方式

| 场景 | 方式 | 说明 |
|------|------|------|
| 路径获取 | 函数返回值 `Path` | `get_user_data_dir()` → `Path`；调用方 `str()` 转字符串 |
| 最高分加载 | 同步函数 `int` 返回值 | `HighScoreStore.load() -> int`；缺文件/损坏返回 0 |
| 最高分保存 | 同步函数 None | `HighScoreStore.save(score: int)`；内部原子写 |
| 重置 | 同步函数 None | `HighScoreStore.reset()`；删除文件并清缓存 |
| 错误反馈 | 自定义异常 | `StorageError`(IO/JSON/路径)；让 game-app 走 NFR-03 可读错误提示路径 |
| 进程内互斥 | 模块级 `threading.RLock`（预留）；本迭代单线程不实装 | 迭代 2 单线程不需要；预留 import 行不报错 |

## 3. 对外接口

### 3.1 `get_user_data_dir() -> Path`

| 项 | 内容 |
|----|------|
| 签名 | `def get_user_data_dir() -> Path` |
| 语义 | 返回三平台用户数据目录下的 SnakeGui 子目录；不存在则创建 |
| 入参 | 无 |
| 出参 | 绝对路径 Path 对象 |
| 副作用 | mkdir parents=True exist_ok=True；首次调用创建目录 |
| 异常 | `StorageError`（mkdir 失败：权限/只读盘） |
| 线程安全 | 是（纯函数 + mkdir 幂等） |
| 单测要点 | monkeypatch `sys.platform` + `os.environ` 三平台各验证一次 |

### 3.2 `class HighScoreStore`

| 方法 | 签名 | 语义 | 异常 |
|------|------|------|------|
| `__init__` | `(path: Path | None = None)` | 初始化 store；path 为 None 时取默认 `get_user_data_dir() / "highscore.json"`；构造期 mkdir + load | StorageError |
| `load() -> int` | 同步 | 返回当前最高分；缺文件/损坏返回 0；正常返回 _cache | 无 |
| `save(score: int)` | 同步 | 写入新最高分；只有 score > 当前值才更新（避免并发降分）；原子写 | StorageError（IO/权限） |
| `reset()` | 同步 | 删除 highscore.json（如存在）并清 _cache = 0 | StorageError |
| `path -> Path` | 属性 | 返回文件绝对路径（供 UI 展示） | — |

**关键语义**：
- `save(score)` 内部比较：只在 `score > self._cache` 时落盘；调用方无需自行比较。
- `save` 触发原子写流程：`tmp → fsync → os.replace`；`fsync` 仅 fd 不强制目录项（Linux 文件系统语义）。
- 损坏恢复：`load()` 检测到 JSONDecodeError / KeyError / ValueType 错误 → 备份为 `.corrupt-{ts}` 后返回 0；不抛异常（最高分丢了不影响游戏本体）。
- 多进程：迭代 2 单进程不实装 fcntl；预留接口说明。

### 3.3 异常类

```python
class StorageError(Exception):
    """平台存储模块异常基类（用户数据目录/IO/权限错误）"""
```

> 模块包名 `platform_storage`（下划线，避开 PEP 8 hyphen 限制与目录同形便于引用）。

### 4.2 流程：`save(score)` 原子写

1. 取 `_lock = threading.RLock()`（预留），`with self._lock:` 进入临界区。
2. 比较 `score <= self._cache` → 直接 return（无需 IO）。
3. 序列化：`_payload = json.dumps({"schema_version": 1, "high_score": int(score)})`。
4. 写入临时文件：临时路径 = `self.path.with_suffix(self.path.suffix + ".tmp")`。
5. 打开临时文件 `open(tmp, "w", encoding="utf-8")`，写入并 `f.flush(); os.fsync(f.fileno()); f.close()`。
6. `os.replace(tmp, self.path)`（POSIX/Windows 均为原子替换）。
7. 更新 `_cache = score; _dirty = False`。

### 4.3 流程：`load()`

1. `with self._lock:`。
2. 不存在 → `_cache = 0` 返回 0。
3. 读 + `json.loads`：
   - `KeyError` / `ValueError` / `TypeError` / `JSONDecodeError` → 备份损坏文件 + `_cache = 0` 返回 0；
   - 正常 → 校验 `high_score` 是 `int` 且 `>= 0` → `_cache = high_score` 返回；
   - 否则备份损坏 + 返回 0。
4. 损坏备份路径：`self.path.with_suffix(f".corrupt-{int(time.time())}.json")`。

### 4.4 流程：`reset()`

1. `with self._lock:`。
2. `self.path.exists()` → `self.path.unlink()`（missing_ok 兼容；本迭代用 try/except FileNotFoundError 避免依赖 3.8+）。
3. `_cache = 0`。

### 4.5 路径定位 `paths.py`

```python
APP_DIR_NAME = "SnakeGui"

def get_user_data_dir() -> Path:
    sysname = sys.platform
    home = Path.home()
    if sysname == "win32":
        base = Path(os.environ.get("APPDATA") or home / "AppData/Roaming")
    elif sysname == "darwin":
        base = home / "Library" / "Application Support"
    else:  # linux / linux2 / 其他 unix
        xdg = os.environ.get("XDG_DATA_HOME")
        base = Path(xdg) if xdg else home / ".local" / "share"
    target = base / APP_DIR_NAME
    try:
        target.mkdir(parents=True, exist_ok=True)
    except OSError as e:
        raise StorageError(f"无法创建用户数据目录 {target}: {e}") from e
    return target
```

## 5. DFx / 可测试性 / 鲁棒性 / 韧性

### 5.1 可测试性（Testability）

- **零副作用单测**：`tmp_path` fixture 注入 `path=`；不污染用户真实目录。
- **平台分支覆盖**：monkeypatch `sys.platform` + `os.environ`，三平台全路径断言；新增 `test_linux_with_xdg` 与 `test_linux_without_xdg` 两个用例。
- **原子写可验证**：tmp 路径断言（`save` 后不存在 `.tmp` 残留）、并发写断言（多线程并发 `save`，最终值 = max，且文件内容合法）。
- **损坏恢复**：手工写入非法 JSON / 缺字段 / 类型错 / 负数 → `load` 返回 0 + 备份文件存在。
- **pytest + unittest 双兼容**：使用 stdlib `unittest`（与 v1.0.0 对齐）；pytest 仅作 runner。

### 5.2 鲁棒性（Robustness）

| 失败场景 | 处理 | 是否抛异常 |
|----------|------|-----------|
| 用户目录不存在 | mkdir parents=True | 否 |
| 目录权限拒绝 | StorageError | 是（让 game-app NFR-03 提示） |
| 高分文件不存在 | load 返回 0 | 否 |
| 高分文件 JSON 损坏 | 备份 + load 返回 0 | 否（不阻塞游戏） |
| schema_version 不识别 | 当前 = 1 不识别 → 备份 + 返回 0 | 否 |
| 高分是负数/字符串 | 备份 + 返回 0 | 否 |
| 写过程断电 | 原子写保证旧文件完整 | 否 |
| 临时文件残留 | 构造期清理 `*.tmp` 残留 | 否 |
| 跨平台路径分隔符 | `pathlib.Path` | 否 |

### 5.3 韧性（Resilience）

- **降级策略**：最高分丢失不影响游戏可玩性；`load()` 永远不抛异常给上层（仅 `__init__` 在 mkdir 失败时抛）。
- **可观测性**：所有 StorageError 带原始异常 `from e`；game-app 可统一捕获并展示 NFR-03 风格提示。
- **进程崩溃兜底**：原子写 + 不留 `.tmp`（步骤 4.2 已确保）；临时文件残留兜底清理（构造期）。

### 5.4 可维护性 / 可扩展性 / 可部署性

| DFx 维度 | 设计 | 备注 |
|----------|------|------|
| 可维护 | 模块 4 文件 < 200 行/文件；无循环依赖 | 与 v1.0.0 terminal_io 同款 |
| 可扩展 | `HighScoreStore` 接口预留 `save/load/reset`；偏好文件 `preferences.json` 接口预留但本迭代空 | 迭代 3 皮肤系统直插 |
| 可部署 | 纯标准库 + Python 3.8 兼容；PyInstaller `--onefile` 无需特殊 hook（无 C 扩展、无动态库） | 与架构对齐 |
| 可观测 | 自定义异常带原始错误链 | game-app 一处 try 即可 |

### 5.5 安全 / 隐私

- **NFR-06 无网络**：模块不 import `socket`/`urllib`/`http` 等（FO 落实时检查）。
- **数据最小化**：仅存最高分整数；不存时间戳/设备指纹/IP。
- **可清除**：UI 重置入口 + `reset()` 接口；文档告知用户手动删除 `~/.local/share/SnakeGui/` 等。

## 6. 资源评估

| 资源 | 用量 | 评估 |
|------|------|------|
| CPU | save 一次 = 1 次 JSON 序列化 + 1 次 fsync ≈ < 5ms | 极轻，可忽略 |
| 内存 | _cache 一个 int ≈ 32B；JSON 字符串 < 50B | 极轻 |
| 磁盘 | highscore.json < 100B；损坏备份文件 < 100B | 极轻 |
| 启动开销 | `__init__` 内一次 `mkdir + load`，预计 < 10ms | 不影响启动性能 |
| 外部依赖 | 无（纯标准库） | 与架构 §技术选型 一致 |
| 平台特性 | Windows APPDATA / macOS ~/Library / Linux XDG | 三平台官方推荐路径 |

### 7.2 测试组织

- **框架**：`unittest`（stdlib，与 v1.0.0 对齐）+ `pytest` 作 runner。
- **运行命令**：`cd workspace/snake-linux/code/platform-storage && python3 -m unittest discover -v tests/` 或 `pytest tests/ -v`。
- **覆盖率目标**：≥95%（核心逻辑模块）。
- **fixture**：`tmp_path`（pytest）→ `tempfile.TemporaryDirectory`（unittest 兼容）；所有 IO 操作走临时目录，不污染用户真实目录。

### 7.3 桩 / Mock 规范

- `monkeypatch.setattr(platform_storage.paths, "sys", fake_sys)` 模拟三平台。
- `monkeypatch.setenv("XDG_DATA_HOME", str(tmp_path))` 验证 XDG 优先级。
- `monkeypatch.setattr(os, "replace", fake_replace)` 验证原子写异常路径。
- 禁止 mock `pathlib.Path`（影响面太大，断言路径值即可）。
- `os.fsync` 可 mock，但同时必须断言 "save 流程中调用过 fsync"。

### 7.4 断言规范

| 类型 | 规范 |
|------|------|
| 路径 | 断言 `Path` 对象相等；不混用字符串以避免平台分隔符差异 |
| IO 副作用 | 断言文件存在 / 不存在 / 内容；用 `tmp_path / "file"` 而非 `os.path.join` |
| 异常 | `assertRaises(StorageError)`；同时断言 `exc.value.__cause__ is not None` 验证异常链 |
| 原子性 | 断言 `save` 后不存在 `.tmp`；断言 `*.corrupt-*` 备份存在；构造期断言无残留 |
| 并发 | `threading.Thread(5)` 并发 `save` 不同分值 → 最终 = max；FO 用 threading 验证 |

### 7.6 与 game-app / game-core 的 UT/IT 边界

- **本模块 UT**：仅覆盖 platform-storage 自身逻辑（路径、JSON 读写、原子写、损坏恢复）。
- **不在本模块覆盖**：与 game-app 的集成（最高分→HUD 渲染/重置按钮）由 IT 在 game-app 迭代 2 覆盖。

## 8. 风险与已知限制

| 项 | 限制 | 后续 |
|----|------|------|
| 多进程并发 | 迭代 2 单进程不实装 fcntl；多进程同时写最高分理论上有竞态 | 迭代 N 增加；若实测无需求可不动 |
| 大小端/编码 | 仅 UTF-8 JSON | 不变 |
| 路径超长（>260） | Windows 长路径需前缀 `\\?\`；当前默认构造不启用 | 若实测触发，再补 win32 长路径处理 |
| 云盘同步目录 | 用户数据目录若在 OneDrive/iCloud/Dropbox 内 → 同步过程可能 fsync 抖动 | 文档说明"建议非云盘目录"；不主动检测 |
