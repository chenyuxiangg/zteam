## 数据结构

### 1.1 基础值对象

| 类型 | 字段 | 说明 |
|------|------|------|
| `Point`（值对象） | `x: int`、`y: int` | 网格坐标。y 向下、0,0 为左上角，沿用 v1 约定 |
| `Direction`（枚举） | `UP=(0,-1)` / `DOWN=(0,1)` / `LEFT=(-1,0)` / `RIGHT=(1,0)` | 4 向；`opposite()` 工具方法返回反向 |
| `GameStatus`（枚举） | `RUN` / `PAUSED` / `OVER` | 运行态机；迭代 1 仅 RUN/OVER，PAUSED 枚举先占位但不允许进入 |
| `Difficulty`（枚举） | `EASY` / `MEDIUM` / `HARD` | 难度档位，绑定 `base_tick_ms`（迭代 2 起改走 `speed_curve`） |

### 1.2 难度参数表（单一数据源）

```python
from typing import Dict
from enum import Enum

class Difficulty(Enum):
    EASY = "easy"
    MEDIUM = "medium"
    HARD = "hard"


# 单一数据源：迭代 2 加 speed_curve(score) 时仅替换本 dict 的内容/形态
DIFFICULTY_PARAMS: Dict[Difficulty, Dict[str, int]] = {
    Difficulty.EASY:   {"base_tick_ms": 250},
    Difficulty.MEDIUM: {"base_tick_ms": 160},
    Difficulty.HARD:   {"base_tick_ms": 100},
}
```

> 迭代 1 仅落 `base_tick_ms`。加速曲线（`speed_curve(score) -> tick_ms`）放迭代 2；迭代 1 内部不出现 score→tick 的换算逻辑，UI 层直接用 `difficulty.base_tick_ms`。

### 1.3 核心实体

**`Snake`**
- 字段：`body: Tuple[Point, ...]`（**不可变 tuple**，蛇头 = `body[0]`，蛇尾 = `body[-1]`）
- 不变量：`len(body) >= 1`；相邻两节点必须 4-邻接
- 派生：`head -> Point`、`len -> int`
- 关键方法（生成新对象，不修改自身）：
  - `with_head(new_head) -> Snake`：在头部插入新节点（移动未吃食）
  - `without_tail() -> Snake`：去掉尾部（移动未吃食，与 `with_head` 配对）
  - `with_head_no_tail_drop(new_head) -> Snake`：仅头部插入（吃食后不丢尾）
  - `contains(p) -> bool`：判断点是否在蛇身

**`Food`**
- 字段：`pos: Point`
- 不变量：`pos not in snake.body`

**`GameState`**
- 字段：
  - `width: int`（网格宽，列数；建议默认 20）
  - `height: int`（网格高，行数；建议默认 15）
  - `difficulty: Difficulty`
  - `snake: Snake`（初始 3 节，居中朝右：body=[(W//2, H//2), (W//2-1, H//2), (W//2-2, H//2)]）
  - `direction: Direction`（初始 RIGHT）
  - `pending_direction: Optional[Direction]`（**同帧多输入合并用**：每个 step 取一次最终方向，规避一帧内连按 WASD 跳过反向的漏洞）
  - `food: Food`
  - `score: int`（**每节长度+1 = 1 分**；迭代 1 不引入复杂计分）
  - `status: GameStatus`
  - `rng: random.Random`（注入，便于 UT 确定性，**禁止隐式全局 random**）
  - `_last_step: Optional[int]`（节拍序号，用于事件订阅；迭代 1 可不暴露）

> 迭代 1 不引入 `events` 队列、`on_score` 回调（事件机制放迭代 2 与 `platform-storage` 接入时一起做）；得分判定由调用方读 `state.score` 即可。

### 1.4 不变量清单（FO 实现必须保证，UT 也要覆盖）

| ID | 不变量 | 违反后果 |
|----|--------|----------|
| INV-1 | `len(snake.body) >= 1` 且相邻节点 4-邻接 | 移动逻辑破坏 |
| INV-2 | `food.pos not in snake.body` | 同位 bug |
| INV-3 | `0 <= head.x < width` 且 `0 <= head.y < height` | 出界 bug（撞墙判定在 step 入口先做） |
| INV-4 | `status == OVER` 后所有 step/set_direction 不再改变 snake/food/score | 终态保护 |
| INV-5 | `pending_direction` 若非 None，则与 `direction` 非 opposite（受理时校验） | 反向移动禁止 |
| INV-6 | `rng` 始终是注入实例，模块内不出现 `import random` 后直接 `random.xxx` | 确定性测试前提 |
| INV-7 | `width >= 4` 且 `height >= 4`（初始布局需要至少 4 列宽度以容纳 3 节水平蛇） | 初始布局自洽 |

## 数据传递方式

| 通道 | 形态 | 用途 |
|------|------|------|
| **构造注入** | `GameState(width, height, difficulty, *, rng=None, initial_direction=RIGHT)` | 注入 RNG 与初始方向；UT 用 `Random(seed)` 复现 |
| **参数传入** | `set_direction(d: Direction)` / `step() -> GameState` | 不在类内维护隐式时间轴；调用方按节拍显式 step |
| **不可变快照** | `snapshot() -> Snapshot`（`@dataclass(frozen=True)`） | 供 gui-renderer 读、供 app 判定终态；禁止 renderer 改 state |
| **返回值** | `step()` **返回新 GameState**（不原地修改） | 纯函数语义，UT 断言前后状态对比；与 v1 就地修改的 API 不同，**这是 v2 设计改进** |
| **异常** | `DirectionError`、`InvalidStateError`（继承 `ValueError`） | 错误输入显式失败，不静默吞 |

> **关键决策（与 v1 的差异）**：`step()`/`set_direction()` 不修改入参对象，而是返回新 `GameState`。这让"上帧状态"在 renderer / UT 中天然可保留，回放/动画/对比都简单。FO 实现时须在 docstring 强调此点。

### 2.4 `GameState`

```python
import random
from typing import Optional

class GameState:
    def __init__(
        self,
        width: int,
        height: int,
        difficulty: Difficulty,
        *,
        rng: Optional[random.Random] = None,
        initial_direction: Direction = Direction.RIGHT,
    ): ...

    # --- 只读属性 ---
    @property
    def head(self) -> Point: ...
    @property
    def score(self) -> int: ...
    @property
    def status(self) -> GameStatus: ...
    @property
    def snake(self) -> Snake: ...
    @property
    def food(self) -> Food: ...
    @property
    def direction(self) -> Direction: ...

    # --- 命令式接口（返回新 GameState，不修改 self）---
    def set_direction(self, d: Direction) -> "GameState":
        """登记期望方向；同一节拍内多次调用以最后一次为准。

        规则：
          - 若 status==OVER，抛 InvalidStateError。
          - 若 d 与当前 direction 相同，直接返回 self（幂等）。
          - 若 d 与当前 direction 反向：
              * 蛇身长度 == 1 时允许（架构「长度 1 时除外」），按反向生效；
              * 蛇身长度 >= 2 时静默忽略（连续按 WS 不致死）。
        """

    def step(self) -> "GameState":
        """推进一个节拍（确定性规则，与 v1.0.0 保持一致）：
          1. 校验 status==RUN，否则抛 InvalidStateError
          2. 计算 d = pending_direction or direction
          3. 计算 next_head = head + d(d)
          4. 撞墙：next_head 越界 → status=OVER，蛇身/食物/得分不变，返回新 state
          5. 撞自身：判定 = new_head in set(body) AND NOT (new_head == 旧尾 AND NOT 吃食)
              即：撞旧尾且本 tick 不吃食（旧尾将移走）时允许让行；其余身段均视为撞 → OVER
              （与 v1.0.0 行为保持一致——v1 `nh in body and not (nh == self.snake[0] and not eating)`）
          6. 吃食：next_head == food.pos → score += 1，生成新 food（排除蛇身），蛇身 = [next_head, *body]
          7. 普通移动：蛇身 = [next_head, *body[:-1]]
          8. 提交 pending_direction → direction（每次 step 一次性消费）

        返回新 GameState。"""

    def snapshot(self) -> "Snapshot":
        """返回不可变快照：
          snake_body: Tuple[Point, ...]
          food: Point
          score: int
          length: int
          status: GameStatus
          difficulty: Difficulty
          tick_ms: int   # 当前应使用的节拍毫秒数（迭代 1 = difficulty.base_tick_ms）
        """
```

### 3.2 核心流程（step 内部）

```
set_direction(d):
  if status==OVER: raise InvalidStateError
  if d == direction: return self            # 幂等
  if d == direction.opposite():
      if len(snake) == 1:
          return self.copy(pending_direction=d)   # 长度 1 特例（架构约束）
      return self                              # 反向忽略（静默，不抛错）
  return self.copy(pending_direction=d)

step():
  if status != RUN: raise InvalidStateError
  d = pending_direction or direction
  next_head = Point(head.x + d.dx, head.y + d.dy)
  new_status = RUN
  body_set = set(snake.body)
  eating = (next_head == food.pos)

  # 撞墙
  if not (0 <= next_head.x < width and 0 <= next_head.y < height):
      new_status = OVER
      return self.copy(status=OVER, pending_direction=None)

  # 撞自身（v1 一致规则）：
  #   判定 = next_head in body_set AND NOT (next_head == 旧尾 AND NOT eating)
  #   含义：撞旧尾且本 tick 不吃食（旧尾将移走）→ 允许让行；其余身段 → OVER
  body_tail = snake.body[-1]
  if next_head in body_set and not (next_head == body_tail and not eating):
      new_status = OVER
      return self.copy(status=OVER, pending_direction=None)

  # 吃食
  if eating:
      new_snake = snake.with_head_no_tail_drop(next_head)
      new_food = spawn_food(rng, width, height, new_snake)  # 排除蛇身
      new_score = score + 1
  else:
      new_snake = snake.with_head(next_head).without_tail()
      new_food = food
      new_score = score

  return self.copy(
      snake=new_snake, food=new_food, score=new_score,
      direction=d, pending_direction=None, status=new_status,
  )
```

### 3.3 食物生成（`spawn_food`）

```
1. 收集所有空闲格 = {(x,y) for x in [0,W) for y in [0,H)} - set(snake.body)
2. 若空闲格为空（蛇填满全屏）→ 抛 RuntimeError("No space for food")  # 实际几乎不可能，但鲁棒性要兜
3. choice(rng, list(空闲格)) → 新食物点
```

> **性能注**：网格默认 20×15=300 格，set 差集 + 随机选对单步开销可忽略（<0.1ms）。不引入空间索引。

### 3.4 初始布局

- 蛇：3 节，居中朝右，body=[(W//2, H//2), (W//2-1, H//2), (W//2-2, H//2)]
- 食物：随机一个非蛇身位置
- direction = RIGHT
- score = 0
- status = RUN
- **网格下限**：`width >= 4` 且 `height >= 4`（W=3 时 W//2-2 = -1 蛇身 x 出界，违反 INV-7；新下限保证初始布局全部在界内）

### 3.5 状态机（迭代 1 子集）

```
       step (撞墙/撞自身)        step (正常/吃食)
NEW ───────────────────▶ OVER      RUN ────────────▶ RUN
       set_direction(OVER)→InvalidStateError
       set_direction(RUN)→生效（含长度 1 反向特例）
       step(OVER)→InvalidStateError
```

迭代 1 **不实现** PAUSED 转换；`toggle_pause` 不在本迭代接口列表中。GameStatus.PAUSED 枚举占位但不暴露入口。

### 3.6 与 v1 差异（FO 实现须知）

| 维度 | v1（snake-linux v1.0.0） | v2（本次） |
|------|--------------------------|------------|
| step 语义 | 原地修改 | 返回新对象 |
| 蛇身结构 | deque | tuple（不可变） |
| RNG | 全局 random | 注入 |
| 状态机 | run/over | run/paused/over（paused 迭代 2） |
| 加速曲线 | 无 | 迭代 2 落 |
| 反向移动 | 静默忽略（不抛错，长度 1 特例由 deque 单节默认放过） | 显式长度 1 特例：长度 1 允许反向、长度 ≥2 静默忽略 |
| 撞自身判定 | `nh in body and not (nh == snake[0] and not eating)` | **同 v1**：`new_head in set(body) and not (new_head == 旧尾 and not eating)` |
| 语法兼容 | Python 3.x | **Python 3.8 严格**：`Optional`/`Tuple`/`Dict`，不用 PEP 604 / 内置泛型 |

### 3.7 实现注意点

1. **纯函数化**：`step`/`set_direction` 必须返回新对象；用 `dataclasses.replace` 或自定义 `copy()` 简化。
2. **不可变 snake.body**：所有"移动/吃食"操作走 `with_head*` / `without_tail`；避免 list 原地 append。
3. **RNG 注入**：`__init__` 默认 `rng=random.Random()`（**非全局 random**），UT 显式传 `Random(42)`。
4. **不做计时**：core 不知道"时间"，仅按"节拍"推进。`tick_ms` 由 `Difficulty.base_tick_ms` 读取 `DIFFICULTY_PARAMS` 提供，渲染层/主循环按此定时。
5. **不做渲染**：core 不输出任何字符/颜色/图像，只产出 snapshot。
6. **不读盘/不写盘**：core 不引入任何 I/O，不读最高分，不写日志。
7. **import 约束**：本模块**仅可 import 标准库**（`enum`、`dataclasses`、`random`、`typing`），禁止 `import pygame` 等。**所有类型注解使用 `typing.Optional` / `typing.Tuple` / `typing.Dict`**——禁用 PEP 604 联合类型（`X | None`）与内置泛型下标（`tuple[...]`）。

## DFx / 可测试性 / 鲁棒性 / 韧性

### 4.1 可维护性（Maintainability）
- 每个公开类/方法有 docstring，标注对应 FR/NFR 编号（如 `"""FR-01~05 玩法核心。NFR-05 零 GUI 依赖。"""`）
- 关键不变量在代码中以注释 + UT 用例双标注
- 单一职责：state.py 只管状态推进；types.py 只管值对象；params.py 只管参数表

### 4.2 可扩展性（Extensibility）
- 难度参数集中在 `params.py`（单一数据源 `DIFFICULTY_PARAMS`），迭代 2 加 `speed_curve(score)` 时只改这一处
- `Difficulty.base_tick_ms` property 从 DIFFICULTY_PARAMS 读取 → 迭代 2 把 property 体改为调用 `speed_curve(score, difficulty)`，调用方无感
- `GameStatus.PAUSED` 枚举已占位，迭代 2 加 `toggle_pause()` 不破坏 API
- 食物生成抽象为内部函数，迭代 3 若需"特殊食物"可扩展

### 4.3 可部署性（Deployability）
- 纯标准库，PyInstaller 打包时**无需 hook**
- 单一包目录 `game_core/`，可独立 wheel 化
- 无 C 扩展、无平台特定代码

### 4.4 可测试性（Testability）
- **零 GUI 依赖**：UT 全部在内存里跑，无需显示器/窗口
- **RNG 注入**：UT 可固定 seed 复现
- **纯函数化**：`step` 返回新对象，UT 可断言 `old == snapshot_before` 不被改
- **可枚举**：`width × height ≤ 300`（默认网格），暴力枚举所有位置组合做穷举 UT 可行
- **无时间/IO**：不需要 mock time.sleep、不需要 tmp_path

### 4.5 鲁棒性 / 韧性

| 场景 | 处理 |
|------|------|
| 反向输入（长度 ≥ 2） | 静默忽略（连续按 WS 不致死） |
| 反向输入（长度 == 1） | 允许按反向生效（架构「长度 1 时除外」） |
| 同一节拍多次 set_direction | 取最后一次（pending_direction） |
| status==OVER 后继续 step | 抛 `InvalidStateError` |
| 状态推进中食物生成冲突 | 排除蛇身后随机；全屏填满抛 RuntimeError |
| 网格宽高 < 4 或 0 | `__init__` 抛 `ValueError`（保证初始布局在界内，INV-7） |
| 难度传入非法值 | `Difficulty` 枚举约束，构造时类型即拦截 |
| 初始 RNG 不传 | 默认 `random.Random()`（**实例，非全局**），UT 显式传入以保证可复现 |

### 4.6 错误处理矩阵

| 错误情形 | 行为 |
|----------|------|
| `set_direction` 时 status==OVER | `InvalidStateError` |
| `set_direction` 反向，长度 ≥ 2 | 静默忽略，返回 self |
| `set_direction` 反向，长度 == 1 | 允许（按反向生效），返回新 state |
| `step` 时 status==OVER/PAUSED | `InvalidStateError` |
| `__init__` width<4 or height<4 | `ValueError` |
| `__init__` difficulty 非 Difficulty 枚举 | `TypeError`（枚举自动） |
| 食物生成时空闲格为 0 | `RuntimeError("No space for food")`（极端情况，理论上 20×15 不可能触发） |

### 5.3 断言规范

- **不变量优先**：每个 UT 至少断言一条 INV（1~7）
- **纯函数性质**：先取 `before = state.snapshot()`，再 `after = state.step()`，断言 `before == state.snapshot()`（state 自身未变）
- **覆盖分支**：每个 step 内部分支（撞墙/撞自身/吃食/普通移动/终态）独立测试
- **参数化**：方向枚举、难度枚举用 `subTest` 循环（unittest 原生）或显式多条用例
- **UT 命名**：`test_{动作}_{场景}_{期望}`，如 `test_step_hits_wall_sets_over`
