# 架构设计：snake-linux v2.0.0（snake-gui）

> SE 产出 · 依据需求规格 `snake-linux/analysis/snake-gui-r1.md`（approved，2026-08-13 用户评审拍板 9 条已固化）
> 对齐约束：三平台免安装单文件可执行、零预装零配置、单机无网络、无音效、玩法与终端版 v1.0.0 一致

## 总体架构

```
┌─────────────────────────────────────────────────────────────┐
│  上层应用  game-app（装配/流程/输入/打包入口）                  │
│   事件循环 · 输入映射(WASD/方向键/P/ESC) · 界面流程(开始/难度/  │
│   暂停/结束/重开/退出) · 皮肤切换 · 错误提示 · PyInstaller 入口  │
├──────────────┬──────────────────────────┬────────────────────┤
│ 中间件        │ 中间件                    │                    │
│ gui-renderer │ platform-storage          │                    │
│ (Pygame渲染)  │ (跨平台本地持久化)         │                    │
│ 画面/动画/皮肤│ 用户数据目录/最高分原子读写 │                    │
├──────────────┴──────────────────────────┴────────────────────┤
│  基础平台  game-core（玩法核心纯逻辑，零 GUI 依赖）              │
│   蛇身模型/移动/吃食/碰撞/反向禁止 · 难度档位参数/加速曲线        │
│   状态机(run/paused/over) · 得分/最高分判定                     │
└─────────────────────────────────────────────────────────────┘
```

- **依赖方向单向向下**：game-app → gui-renderer / platform-storage / game-core；gui-renderer → game-core；platform-storage / game-core 无依赖（叶子）。
- **核心与界面解耦**（NFR-05）：game-core 为纯 Python 标准库实现，不 import 任何 GUI 库，可脱离界面做确定性单元测试；gui-renderer 只读 core 的状态快照（snapshot），不直接改游戏状态。
- **单需求单版本**：v2.0.0 承载 snake-gui 一个需求，独立于已 released 的终端版 v1.0.0（互不影响）。

## 技术选型

| 项 | 选型 | 理由 |
|----|------|------|
| 语言 | Python 3.8+（语法兼容 3.8，不使用 3.9+ 新语法） | 与 v1.0.0 同生态；core/storage 标准库零依赖，可测性好；PyInstaller 打包支持成熟 |
| GUI 框架 | Pygame（SDL2） | 游戏循环/帧率控制/逐帧渲染天然契合（NFR-01 ≥60FPS）；跨三平台行为一致（FR-15）；打包单文件体积适中；无外部运行时 |
| 打包 | PyInstaller `--onefile --windowed` | 业界通行"下载即用"形态（规格 §参考来源）；三平台各自产出单文件可执行（FR-14） |
| 持久化 | 标准库 JSON + 原子写（临时文件 + os.replace） | 最高分/偏好仅本地（NFR-06）；原子写保证异常退出不损坏（FR-13）；零第三方依赖 |
| 用户数据目录 | 手写三平台定位（%APPDATA% / ~/Library/Application Support / ~/.local/share） | 零依赖；便携式不写系统目录（NFR-07） |
| 构建矩阵 | Linux 构建机打 Linux 包；Windows/macOS 包在对应平台构建（或 CI 三平台矩阵） | PyInstaller 不支持交叉打包；规格验收要求三平台各跑通（FR-14/15、NFR-04） |

> 否决项：Tkinter（动画/帧率控制弱、打包体积大、跨平台观感不一致）、PyQt（许可与体积重、超出游戏需求）、Arcade（打包生态较 Pygame 弱）、Web 技术栈（规格明确不做 Web 版）。

## 模块组织与分工（与 modules.json 一致）

| 模块 | 类型 | 职责 | 依赖 | 迭代 |
|------|------|------|------|------|
| game-core | 基础平台 | 玩法核心纯逻辑：蛇身模型、移动/吃食/碰撞/反向禁止判定、难度档位参数（简单 250ms/普通 160ms/困难 100ms 基线节拍）+ 加速曲线、运行状态机（run/paused/over）、得分与最高分判定 | 无 | 1, 2 |
| platform-storage | 中间件 | 跨平台用户数据目录定位、最高分/偏好 JSON 读写、原子写防损坏、重置入口支撑 | 无 | 2 |
| gui-renderer | 中间件 | Pygame 画面渲染（蛇/食物/背景/HUD）、平滑插值动画、皮肤系统（≥3 套：经典/深色/色盲友好）、窗口等比缩放自适应、高分屏清晰 | game-core | 1, 3 |
| game-app | 上层应用 | 主入口与事件循环、输入映射（WASD/方向键/P/ESC）、界面流程（开始/难度选择/暂停/继续/结束/重开/退出）、皮肤切换、可读错误提示、PyInstaller 打包配置与发布物 | game-core, gui-renderer, platform-storage | 1, 2, 3, 4 |

## 需求分发

- snake-gui → **game-app**（上层应用承载需求主体；core/storage/renderer 为支撑模块，需求子集见分工表 §模块×需求）

## 模块间接口与数据流（代码检视依据）

### 接口清单（设计期定义，下游开发依赖）

**game-core（无依赖，纯逻辑）**
- `Difficulty`（枚举：EASY/MEDIUM/HARD）+ 参数表：`base_tick_ms`（250/160/100）、`speed_curve(score)`（随长度/得分加速，验收以"档位间可感知差异、困难 ≤ 简单 50%"为准）
- `GameState(width=..., height=..., difficulty=...)`：构造（**仅接受 keyword 参数**）；`set_direction(vec)`（含 180° 反向禁止）；`step()` 每节拍推进（移动/吃食/碰撞/得分）；`toggle_pause()`（暂停定格，暂停期方向输入不生效）；`snapshot()` 返回只读状态快照（蛇身坐标/食物/得分/长度/状态/难度/tick_ms）；`status`（run/paused/over）
- 事件/回调：`on_score(score)`（供 app 接最高分判定）

**platform-storage（无依赖）**
- `get_user_data_dir()`：三平台用户数据目录（Windows `%APPDATA%`/macOS `~/Library/Application Support`/Linux `~/.local/share`，追加应用子目录）
- `HighScoreStore(path)`：`load() -> int`、`save(score)`（原子写：临时文件 + os.replace）、`reset()`；异常退出不损坏历史

**gui-renderer（依赖 game-core）**
- `Renderer(window_size, *, skin=None, vsync=True, cell_size, grid_cols, grid_rows, enable_high_dpi=True)`：构造期不建屏（`init()` 建屏）；`enable_high_dpi=True` 启用 `pygame.SCALED`（高分屏清晰 NFR-04）；`render(snapshot, hud, *, interp=None)` 绘制一帧（蛇/食物/背景/HUD：得分/最高分/长度；interp 为可选插值上下文，None=瞬移，向后兼容）；`set_skin(name)`（查 SKIN_REGISTRY，不在表内抛 SkinNotFoundError，游戏中对局不中断）；`handle_resize(w, h)` 等比缩放（保持 grid_cols/rows，< 最小可玩尺寸抛 RenderError）；`skin_names()` / `current_skin_name`（皮肤切换 UI 用）；`fps_metric()` 帧率统计（P95 帧时间）
- 皮肤注册表：≥3 套（经典/深色/色盲友好——色盲方案不以颜色为唯一区分手段，叠加形状/纹理）

**game-app（装配）**
- `main()`：解析启动 → 初始化窗口 → 主循环（事件 → core 输入 → step → renderer 绘制）；`run()` 为 PyInstaller 入口
- 错误处理：图形环境缺失/初始化失败输出人类可读提示后退出（NFR-03），退出 1 秒内无残留进程（FR-11）

### 数据流

```
用户输入(WASD/方向键/P/ESC)
   │  game-app 事件循环
   ▼
game-core.set_direction / step / toggle_pause      ──得分事件──▶ platform-storage.save(最高分)
   │
   ▼ snapshot()
gui-renderer.render(snapshot)  ──▶ 屏幕
   ▲
   └─ 皮肤/缩放/动画参数（app 设置）
```

### 关键约束（规格 → 设计）

- 难度游戏中不可切换（FR-05）：难度在开局选择后固定于 GameState，无运行中切换接口；
- 反向移动禁止（FR-02）：set_direction 拒绝与当前行进方向相反（长度 1 时除外）；
- 食物不与蛇身重叠（FR-03）：step 内生成新食物坐标排除蛇身；
- 无任何网络行为（NFR-06）：全模块不引入 socket/http 依赖；
- 无音效（R-04）：不引入音频模块。

## 编译/构建/发布/配置

### 构建

- 开发态：源码模式 `python3 -m game_app` 直接运行（core/storage 可单独 `python3 -m unittest` 跑 UT，脱离 GUI）；
- 发布态：PyInstaller 单文件打包——Linux：`pyinstaller --onefile --windowed --name snake-gui entry.py`（Linux 构建机）；Windows：同参数 `.exe`（Windows 构建机）；macOS：`.app`（Intel + Apple Silicon 双架构，macOS 构建机，`--target-arch` 或 universal2）；
- 三平台版本号统一 v2.0.0（FR-15/R-07）。

### 发布

- 发布物清单：`snake-gui`（Linux ELF）/ `snake-gui.exe`（Windows）/ `snake-gui.app`（macOS）+ `SHA256SUMS`（校验和）+ `发布说明`（NFR-07）+ `用户指南`（FR-16：下载运行/键位表/难度/皮肤/暂停说明/平台差异/已知限制）；
- 便携式：运行/安装路径不写系统目录（NFR-07），最高分等数据写用户数据目录；
- 干净机器验收：无 Python/Node/Java 预装环境可直接启动（FR-14）。

### 配置模型

- **零配置文件**（规格约束）：无 ini/env 配置；难度/皮肤通过游戏内 UI 选择并即时生效；
- 持久化数据仅两类：最高分（FR-13，HUD/开始界面展示 + 重置入口）、皮肤/偏好（可选，存同目录）；仅本地（NFR-06）；
- 错误/诊断：可读提示 + 退出码，无裸 traceback（NFR-03）。

## 代码风格约定

- 与 v1.0.0 对齐：类职责分层（模型/存储/渲染/装配各司其职）、模块 docstring 标注对应 FR/NFR 编号；
- 语法兼容 Python 3.8（对齐 v1 保守策略：不用海象运算符/3.9+ 新语法；**dataclass 可用**——game-core/gui-renderer 已全量采用 frozen dataclass 值对象并通过评审，作为标准写法）；
- game-core 与 platform-storage **不 import 任何第三方库**（纯标准库，保可测性与打包精简）；GUI 依赖（pygame）仅限 gui-renderer / game-app；
- 坐标约定：沿用 v1 的 Point(x, y)，y 向下，0,0 为左上角；方向向量 UP/DOWN/LEFT/RIGHT；
- 测试：core 用标准库 unittest 确定性用例（对齐 v1 已验证模式）；性能指标留档脚本（NFR-01/02 回归）。

## 迭代计划

> 原则：先最小闭环再增量；有依赖的模块跨迭代串行推进，无依赖并行；每迭代以可运行形态收口。

- **迭代 1（最小闭环·可玩）**：game-core 玩法闭环（移动/吃食/碰撞/反向禁止/得分 + 难度参数表一次到位）；gui-renderer 基础渲染（蛇/食物/背景/HUD 静态绘制）；game-app 装配主循环 + 输入 + 开始/结束/重开/退出。**出口**：对齐验收 1（玩法闭环）、4（控制流程）可自动化验证。
- **迭代 2（体验功能）**：game-core 暂停状态机扩展 + 加速曲线落地；platform-storage 最高分持久化（原子写/重置）；game-app 难度选择界面、暂停/继续、最高分展示与重置。**出口**：验收 2（难度分级）、4（暂停/最高分）。
- **迭代 3（视觉增强）**：gui-renderer 平滑插值动画、皮肤系统（≥3 套含深色/色盲友好）、窗口等比缩放自适应；game-app 皮肤切换/设置界面（对局不中断）。**出口**：验收 3（GUI 呈现）。
- **迭代 4（交付打磨）**：game-app 三平台 PyInstaller 打包矩阵、可读错误提示完善、性能调优（≥60FPS/输入延迟 ≤1 节拍/内存 ≤300MB）；全模块回归 + 用户指南 + 发布物。**出口**：验收 5（开箱即用）、6（性能）、7（兼容矩阵）。

### 模块 × 迭代矩阵

| 模块 | 迭代 1 | 迭代 2 | 迭代 3 | 迭代 4 |
|------|:------:|:------:|:------:|:------:|
| game-core | ● | ● | | |
| platform-storage | | ● | | |
| gui-renderer | ● | | ● | |
| game-app | ● | ● | ● | ● |

迭代间串行依据：1→2 依赖 core 玩法闭环稳定；2→3 依赖体验功能收口（视觉增强在其上叠加）；3→4 依赖视觉基线稳定（打包/性能调优以最终形态为对象）。迭代 1 内三模块并行开发，通过 core snapshot 接口联调。
