# 需求规格：snake-gui（v2.0.0 建议）r1

## 背景与目标

**结论先行**：snake-linux 已有终端版 v1.0.0（已 released），验证了玩法闭环与交付链路；本需求是**形态升级**——从终端字符界面升级为美观的图形界面，并把覆盖范围从单一 Linux 终端扩展到 Windows / macOS / Linux 三大桌面平台，交付形态从"源码运行"升级为"下载即玩"。

- **业务背景**：终端版面向开发者/技术用户，启动依赖 Python 环境与终端；普通用户无法直接使用。本次要做"全新形态的版本，不再局限在终端"（需求原文），目标是让贪吃蛇成为**普通用户可安装、可运行、可玩**的产品级 GUI 游戏。
- **目标**：交付一个跨 Windows/macOS/Linux 的图形界面贪吃蛇游戏，满足四个核心诉求——界面美观、操作流畅、开箱即用、跨平台。

## 功能需求（FR，MECE 分解）

分组维度：按**用户旅程**（游戏玩法 → 界面呈现 → 控制与流程 → 安装交付）分组，组间互不重叠，合则覆盖"下载 → 玩 → 退出"全过程。玩法基线继承终端版 v1.0.0（经典贪吃蛇），本需求不改变玩法规则，只升级形态（见 A-01 / Q-01）。

### 3.1 游戏玩法核心（继承终端版经典规则）

| 编号 | 功能点 | 描述 | 优先级 | 验收标准 |
|------|--------|------|--------|----------|
| FR-01 | 经典玩法闭环 | 蛇按节拍自动前进；方向控制（WASD 与方向键 ↑↓←→）；吃食物蛇身 +1、得分 +1；撞墙或撞自身结束 | 高 | 不操作输入时蛇每节拍前进 1 格；方向键响应 ≤ 1 个节拍；吃 N 个食物后长度 = 初始 + N、分数 = N |
| FR-02 | 反向移动禁止 | 蛇不能 180° 掉头撞向自身（如向右移动时按左键无效） | 高 | 向右移动中按 A/←，蛇保持向右，不因反向自杀而结束 |
| FR-03 | 食物生成 | 开局生成 1 个食物；被吃后在 1 个节拍内于新位置重生；食物不与蛇身重叠 | 高 | 食物被吃后 1 个节拍内出现新食物，新食物坐标与蛇身所有坐标均不同 |
| FR-04 | 结束判定与画面 | 蛇头撞墙/撞自身 → 游戏结束，显示最终得分与"重开/退出"选项 | 高 | 触发结束条件后游戏停止移动，结束画面稳定显示得分与重开/退出入口 |

### 3.2 界面呈现（形态升级核心）

| 编号 | 功能点 | 描述 | 优先级 | 验收标准 |
|------|--------|------|--------|----------|
| FR-05 | 图形界面渲染 | 以图形（非字符）方式渲染游戏画面：蛇身、食物、背景、HUD 均为图形元素，无终端字符残留 | 高 | 游戏画面中不存在字符/文本终端式渲染（文字标签除外）；窗口标题、图标完整 |
| FR-06 | 平滑动画 | 蛇的移动带平滑过渡（逐帧插值移动而非整格跳变），视觉连贯不闪烁 | 高 | 蛇移动过程中无整格跳变、无画面闪烁/撕裂；观感连续（对齐 NFR-01） |
| FR-07 | 界面美观基线 | 视觉要素达到"美观"基线：配色主题、清晰的蛇/食物辨识度、整洁的 HUD 布局 | 高 | 蛇与食物在任意主题下可清晰区分；HUD（得分/长度）固定位置、字号清晰；整体观感无粗糙感（具体维度见 Q-09） |
| FR-08 | 窗口自适应 | 窗口可调整大小，游戏画面等比缩放适配；存在最小可玩尺寸 | 中 | 拖拽改变窗口大小后画面等比缩放无变形、无裁切；小于最小尺寸时给出提示而非画面错乱 |

### 3.3 游戏控制与流程

| 编号 | 功能点 | 描述 | 优先级 | 验收标准 |
|------|--------|------|--------|----------|
| FR-09 | 开始/重开/退出流程 | 有开始界面（按任意键/点击开始）；结束后可重开新局或退出；任意时刻可退出游戏 | 高 | 启动后进入开始界面；结束后重开可立即开始新局；任意时刻退出进程在 1 秒内干净结束、无残留进程 |
| FR-10 | 暂停/继续 | 游戏中可暂停与继续（建议 P 键/ESC 或窗口失焦自动暂停；见 Q-02） | 中 | **待 Q-02 确认后生效**；暂停时画面定格、节拍停止；继续后从暂停处恢复 |

### 3.4 安装与交付（开箱即用）

| 编号 | 功能点 | 描述 | 优先级 | 验收标准 |
|------|--------|------|--------|----------|
| FR-11 | 免预装直接运行 | 用户下载后**无需预装任何第三方运行时/框架**即可运行（如各平台免安装单文件可执行形态，具体交付形态见 Q-06） | 高 | 在无 Python/Node/Java 等预装环境的干净三平台机器上，下载后直接启动成功 |
| FR-12 | 跨平台运行一致 | 同一版本在 Windows / macOS / Linux 三平台可运行，玩法与核心体验一致 | 高 | 三平台各跑通 FR-01~FR-09 全部验收项；键位、玩法、界面布局无平台差异 |
| FR-13 | 用户指南 | 交付 README/用户指南：下载与运行方式、键位表、平台差异说明、已知限制 | 中 | 文档存在且四节齐全；按文档在三平台可复现启动（对齐 FR-11/FR-12） |

## 非功能需求（NFR）

| 编号 | 类别 | 需求 | 可验证指标 |
|------|------|------|-----------|
| NFR-01 | 性能 | 操作流畅、无卡顿（"流畅"的量化基线） | 默认节拍 ≤ 200ms；从按键到蛇转向生效的输入延迟 ≤ 1 个节拍；渲染帧率 ≥ 60 FPS，P95 帧时间 ≤ 25ms（渲染能力受限环境可降级，但不得卡顿超过 1 秒） |
| NFR-02 | 性能 | 资源占用轻量 | 运行时内存 ≤ 300MB、CPU 占用 ≤ 10%（单核，空闲画面），作为回归指标 |
| NFR-03 | 可用性 | 失败场景提示友好 | 图形环境缺失/驱动异常/平台不兼容等可预见失败输出人类可读错误提示而非崩溃静默/裸 traceback |
| NFR-04 | 兼容性 | 平台覆盖矩阵 | Windows 10/11、macOS 12+（Intel 与 Apple Silicon）、主流 Linux 桌面发行版（Ubuntu 22.04+/Fedora/Arch 之一）行为一致；高分屏（HiDPI）下界面清晰不模糊 |
| NFR-05 | 可维护性 | 代码职责分离 | 游戏逻辑 / 渲染 / 输入处理分层，GUI 层与平台解耦；核心玩法逻辑可脱离 GUI 独立测试（供 UT 使用） |
| NFR-06 | 安全与合规 | 本地单机、无隐藏行为 | 默认无网络上传；不收集用户数据；不含广告/捆绑安装（若 Q-05 确认联网能力则另行声明） |
| NFR-07 | 交付完整性 | 发布物规范 | 发布包含版本号、各平台包校验和（SHA256）、发布说明；安装/运行路径不写系统目录（便携式） |

## 边界与约束

### 做什么
- 三平台（Windows/macOS/Linux）桌面 GUI 贪吃蛇，玩法继承终端版经典规则；
- 图形界面（非字符）、平滑动画、美观基线（FR-05~FR-08）；
- 开箱即用：免预装运行时，下载即玩；
- 交付用户指南与发布物规范。

### 不做什么
- 不做移动端（Android/iOS）、不做 Web 浏览器版（"跨平台"限定为三大桌面平台，见 A-04）；
- 不做联网对战/全球排行榜/分享（本地单机，除非 Q-05 确认纳入）；
- 不做音效/音乐（默认，除非 Q-04 确认纳入）；
- 不改动终端版 snake-linux（独立交付，互不影响）；
- **不做技术选型与实现方案论证（GUI 框架/语言/打包工具选型均属 How，由 SE/实现阶段决策，本规格只固化需求约束）**。

### 约束
- 玩法规则与终端版 v1.0.0 保持一致（差异仅形态，见 A-01）；
- "开箱即用"的硬约束：**用户侧零预装、零配置**（A-05）；
- 三平台同一版本号、行为一致（FR-12）；
- 现有环境事实：snake-linux 项目 v1.0.0 已 released，本需求建议以 v2.0.0 独立交付（见 Q-07）。

## 验收标准

> 供后续 UT/IT/ST 使用；每条可独立验证。

1. **玩法闭环（FR-01~FR-04）**：自动化测试覆盖——方向控制、吃食增长、食物不重叠、反向禁止、撞墙/撞身结束，全部通过；
2. **GUI 呈现（FR-05~FR-08）**：启动后为图形界面且无字符渲染残留；蛇移动平滑无跳变；窗口缩放画面不变形；三平台截图对比核心布局一致；
3. **控制流程（FR-09，及 Q-02 确认后的 FR-10）**：开始→游玩→结束→重开/退出全流程可走通；退出 1 秒内无残留进程；
4. **开箱即用（FR-11~FR-13）**：在干净 Windows/macOS/Linux 三平台（无预装运行时）下载即运行；按指南可复现；
5. **性能（NFR-01~02）**：帧率 ≥ 60 FPS、输入延迟 ≤ 1 节拍、资源占用在指标内（性能脚本实测留档）；
6. **兼容矩阵（NFR-04）**：Windows 10/11、macOS 12+（双架构）、Ubuntu 22.04+ 各跑通 1~5 轮完整对局。

## 假设与待确认点

### 假设（默认成立，用户评审时若不同意请指出）
- **A-01**：玩法与终端版 v1.0.0 完全一致（经典贪吃蛇），本需求只升级形态不改规则；
- **A-02**：单机本地游戏，默认无任何网络能力；
- **A-03**：不做音效/音乐；
- **A-04**："跨平台"= Windows/macOS/Linux 三大桌面平台，不含移动端与 Web；
- **A-05**："开箱即用"= 用户无需预装任何运行时/框架/配置，下载即运行。

### 待确认点（请用户评审时逐条拍板）
- **Q-01 玩法范围**：仅继承经典玩法，还是允许新增能力（难度分级、障碍物、道具、皮肤等）？——建议本轮仅经典玩法，扩展后续迭代；
- **Q-02 暂停/继续**：是否需要？（FR-10 已按"建议纳入"编写，优先级中）——建议纳入；
- **Q-03 高分持久化**：是否需要本地保存最高分、重启不丢？——建议纳入（属轻量本地数据，不违反 A-02）；
- **Q-04 音效/音乐**：是否需要？——默认不做（A-03）；
- **Q-05 联网能力**：是否需要排行榜/分享等联网功能？——默认不做（A-02）；若做，需补充数据隐私声明（NFR-06）；
- **Q-06 交付形态**："开箱即用"是否按"三平台各自免安装单文件可执行（下载即跑）"理解？还是接受"安装包 + 依赖随包"形态？——默认前者（更贴合原文"下载/安装后可直接运行"）；
- **Q-07 版本号**：以 v2.0.0 作为本需求交付版本号？——建议是（独立于终端版 v1.0.0）；
- **Q-08 可访问性**：是否需要色盲友好配色/深色主题等选项？（竞品 Google Snake 标配色盲选项与多主题，作为"美观"加分项）——建议纳入皮肤系统；
- **Q-09 美观基线确认**：以"平滑动画 + 清晰辨识度 + 整洁 HUD + 多主题（含 Q-08）"作为 FR-07 的验收维度是否认可？
