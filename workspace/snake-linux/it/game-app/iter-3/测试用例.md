## 0. 范围与依赖

- **被测对象**：`game_app` 包（`App` / `AppConfig` / `AppConfigV3` / `AppScreen` / `InputAction` / `AppError` / `GraphicsUnavailableError` / `ConfigError` / `StorageUnavailableError` / `_load_cjk_font` / `menu.draw_menu` / `menu.draw_game_over` / `menu.draw_pause_overlay` / `storage.create_storage`）
- **协作模块契约**（IT 仅通过公开 API 触发，不重测内部）：
  - `game-core.iter2.GameState`：`set_direction` / `step` / `snapshot` / `toggle_pause`（RUN↔PAUSED；OVER 抛 InvalidStateError；PAUSED→RUN 清 pending_direction）/ `score_callback` 参数
  - `gui-renderer.iter3.Renderer`：**iter-3 新增公开 API**：`set_skin(name)`（不在注册表抛 `SkinNotFoundError(name, available)`）/ `handle_resize(w, h)`（< MIN_PLAYABLE_W/H 抛 `RenderError`）/ `skin_names()`（tuple[str, ...]）/ `current_skin_name`（属性）/ `render(snap, hud, *, interp=None)`（interp 非 None 时按 alpha 插值绘制；None=瞬移向后兼容）+ 沿用：`init()` / `shutdown()` / `fps_metric()` / 构造签名 `(window_size, *, skin=DEFAULT_SKIN, vsync=True, cell_size, grid_cols, grid_rows, **enable_high_dpi=True)`
  - `gui-renderer.iter3.InterpolationState`：frozen dataclass `(alpha, prev_snake_body, prev_food=None)` —— **r2-7**：`prev_food=None` 语义 = 吃食节拍食物瞬移渲染
  - `platform-storage.iter2.HighScoreStore`：`load()` / `save(score)` / `reset()`（iter-3 沿用不调用）
- **测试驱动**：pytest 9.x；pygame 副作用通过 fake 模块桩化（沿用 `code/game-app/iter-1/tests/test_game_app/conftest.py` 的 `fake_pygame` + `fake_storage` + `FakeEvent` + **iter-3 新增 `fake_renderer_iter3` 含 `set_skin`/`handle_resize`/`skin_names`/`current_skin_name`/`render(interp=)` 桩 + `make_resize_event` 工厂**）
- **隔离策略**：所有 pygame 调用走 fake；`Renderer` 在大多数用例中被 `fake_renderer_iter3` 替换（构造期 _init_pygame + 行为契约调用记录）；事件序列通过 `fake.event.get.return_value` / `side_effect` 注入；`HighScoreStore` 通过 `fake_storage` MagicMock 或 `tmp_path` 真实 IO
- **用例编号**：`IT-game-app-3-{NN}`，与整体测试方案 §2.3 编号体系对齐（其中 `IT-app-3-01` 整体测试方案已定义为"皮肤切换"，本 IT 拆为 SK-01~SK-08 多用例覆盖）
- **优先级映射**：
  - P0 = 皮肤切换 UI（FR-10）/ 窗口缩放（FR-09）/ 平滑插值（FR-07）/ 高分屏清晰（NFR-04）—— 发布阻塞
  - P1 = 输入屏态分发（PLAYING/PAUSED/GAME_OVER 透传）/ 状态机边界 / 跨迭代回归 / RenderError 兜底
  - P2 = 静态检查（无网络/Python 3.8 兼容/无音效）/ 字体回退
- **不重复测**：反向禁止/撞墙/撞身/吃食等核心玩法逻辑由 `game-core` IT 与 UT 覆盖；皮肤注册表/RESIZABLE 标志/插值渲染像素校验由 `gui-renderer` iter-3 IT 与 UT 覆盖；原子写/损坏恢复由 `platform-storage` IT 覆盖——本模块 IT 仅验证 **app 装配正确透传 + 跨模块契约调用关系** + **跨迭代回归无破坏**

## 2. 用例明细

### IT-game-app-3-01：皮肤切换 UI（G3-1）

**前置**：`fake_pygame` + `fake_storage` + `fake_renderer_iter3` 注入；`fake_renderer_iter3.skin_names.return_value = ("classic", "dark", "colorblind_friendly")`；`fake_renderer_iter3.current_skin_name = "classic"`；构造 App + `_init_pygame()`。
**步骤**：
1. 注入 `[KEYDOWN K_RIGHT]` → `app._drain_events()`；
2. 断言返回 actions 列表不含 `InputAction.SET_SKIN_NEXT`（MENU 态同步处理不入 dispatch）；
3. 断言 `fake_renderer_iter3.set_skin.call_count == 1` 且 `call_args == ("dark",)`；
4. 断言 `app._skin_index == 1`。

**预期**：MENU 态 → 键切下一皮肤 → `_drain_events` 内同步调 `set_skin` + 更新循环索引（G3-1 INV-16）。

### IT-game-app-3-02：皮肤循环边界（G3-1 INV-16）

**前置**：同 IT-game-app-3-01。
**步骤**：
1. 连续注入 `[K_RIGHT, K_RIGHT, K_RIGHT, K_RIGHT]` 各调一次 `_drain_events()`；
2. 断言 `app._skin_index` 序列为 `[1, 2, 0, 1]`（4 次 → 后回到 1，循环合法）；
3. 断言 `set_skin.call_args_list == [("dark",), ("colorblind_friendly",), ("classic",), ("dark",)]`；
4. 同样从 `_skin_index=0` 注入 `[K_LEFT]` → 断言索引变为 2（`(0-1) % 3 == 2`，反向循环）。

**预期**：`_skin_index` 在 `[0, len(skin_names))` 内循环；←/→ 不越界（INV-16）。

### IT-game-app-3-03：SkinNotFoundError 兜底（G3-1）

**前置**：`fake_renderer_iter3.set_skin.side_effect = SkinNotFoundError(name="bad", available=("classic",))`。
**步骤**：
1. 调 `app._switch_skin(InputAction.SET_SKIN_NEXT)`（直接调，绕过 _drain_events 屏态判定）；
2. 断言 `app._skin_index == 0`（不变）；
3. 断言 stderr 含 `"[警告]"` 与 `"切换皮肤失败"`；
4. 断言不抛异常（INV-16 兜底语义）。

**预期**：`SkinNotFoundError` 不中断游戏；`_skin_index` 维持原值；stderr 写入可读提示。

### IT-game-app-3-04：屏态透传（G3-1 FR-10 对局不中断）

**前置**：`app_in_playing` / `app_in_paused` / `app_in_game_over` 三个 fixture。
**步骤**（参数化三态）：
1. PLAYING 态：注入 `[KEYDOWN K_LEFT]` → `_drain_events()` → 断言 actions 含 `MOVE_LEFT`，不含 `SET_SKIN_PREV`；`set_skin.assert_not_called()`；
2. PAUSED 态：同上断言 `MOVE_LEFT`；
3. GAME_OVER 态：同上断言 `MOVE_LEFT`；
4. 三态均断言 `app._skin_index` 未变。

**预期**：PLAYING/PAUSED/GAME_OVER 态下 ←/→ 不调 `set_skin`（FR-10 对局不中断）；仅 MOVE_* 透传保持对局控制。

### IT-game-app-3-05：窗口缩放（G3-2 / r2-2 契约前置）

**前置**：`fake_pygame` + `fake_renderer_iter3` 注入。
**步骤**：
1. 构造 `make_resize_event(1024, 768)` → 注入 `fake.event.get.return_value`；
2. 调 `app._drain_events()`；
3. 断言 `fake_renderer_iter3.handle_resize.assert_called_once_with(1024, 768)`；
4. 断言返回 actions 列表为空（RESIZE 不入 dispatch）。

**预期**：VIDEORESIZE 在 `_drain_events` 内同步调 `Renderer.handle_resize`；不入 actions 列表（不入 dispatch）。

### IT-game-app-3-06：缩放兜底（INV-15 G3-2）

**前置**：`fake_renderer_iter3.handle_resize.side_effect = RenderError("尺寸过小")`。
**步骤**：
1. 构造 `make_resize_event(100, 100)`（< MIN_PLAYABLE_W/H）→ 注入；
2. 调 `app._drain_events()` 不抛异常；
3. 断言 stderr 含 `"[警告]"` 与 `"窗口缩放失败"`；
4. 断言 `app.screen` 不变（INV-15：缩放失败不中断游戏）。

**预期**：RenderError 兜底为 stderr 提示 + 维持当前尺寸 + 不抛、不退、不中断游戏。

### IT-game-app-3-07：同帧多事件（G3-2 / R3-1）

**前置**：`fake_pygame`。
**步骤**：
1. 注入 `[make_resize_event(1024, 768), KEYDOWN K_q]` 顺序；
2. 调 `app._drain_events()`；
3. 断言 `handle_resize.assert_called_once_with(1024, 768)`；
4. 断言 actions 含 `InputAction.QUIT`（K_q 在 MENU 态兜底转 QUIT 优先 break）；
5. 断言 actions 不含 `InputAction.RESIZE`。

**预期**：RESIZE 同步处理 + KEYDOWN 进 dispatch；事件按原顺序处理。

### IT-game-app-3-08：_tick step 前保存 _prev_snap（r2-1 修订）

**前置**：`app_in_playing`（MEDIUM 难度，初始 tick_ms=160）。
**步骤**：
1. 手动 `app._tick(160)` 触发一拍 step；
2. 断言 `app._prev_snap is not None`（r2-1 修订：step **前**保存，非 step 后）；
3. 断言 `app._prev_snap.snake_body[0]` == step 前蛇头位置；
4. 断言 `app.game_state.snake.body[0]` == step 后新蛇头位置（与 prev 不同）；
5. 再 `app._tick(160)` 第二拍 → 断言 `_prev_snap` 已更新为上一拍 step 前位置（即"上一帧 step 后位置 = 本帧 step 前位置"）。

**预期**：r2-1 修订：`_prev_snap` 在 `_tick` step **前**保存；下一帧 `_render` 构造 `InterpolationState.prev_snake_body` = 旧位置。

### IT-game-app-3-09：插值渲染调用（G3-3 r2-1 alpha 公式）

**前置**：`app_in_playing`；手动调 `app._tick(160)` 一次（建立 `_prev_snap`）。
**步骤**：
1. 设置 `app._tick_accumulator_ms = 80`（节拍半程）；
2. spy `fake_renderer_iter3.render`；
3. 调 `app._render()`；
4. 断言 `render.assert_called_once()` 且 `kwargs["interp"]` 是 `InterpolationState` 实例；
5. 断言 `interp.alpha == 0.5`（r2-1 修订：`elapsed/tick_ms = 80/160`）；
6. 断言 `interp.prev_snake_body` 与 `_prev_snap.snake_body` 转换的 `((x,y),...)` 一致。

**预期**：PLAYING 路径 `_render` 走 `interp=`；alpha 公式 = `(_tick_accumulator_ms % tick_ms) / tick_ms`（r2-1 修订）。

### IT-game-app-3-10：插值防御（r2-3 / r2-6 / r2-7）

**前置**：`app_in_playing`。
**步骤**（参数化 4 子用例）：
1. **r2-3 子例 1**：`app._prev_snap = None` → 调 `_interpolation_state(snap)` → 断言返 None（首帧瞬移渲染）；
2. **r2-6 子例**：调 `_interpolation_state(None)` → 断言返 None（snap 参数防御）；
3. **r2-7 子例**：构造 `snap.snake_body` 长度 = `_prev_snap.snake_body` 长度 + 1（吃食增长）→ 断言返 None（蛇身长度变化）；
4. **r2-3 子例 2**：构造 `_prev_snap.snake_body[0]` 与 `snap.snake_body[0]` Chebyshev 距离 > 1（蛇身跳变）→ 断言返 None。

**预期**：四类防御条件全部返 None；Renderer 走瞬移渲染（向 iter-2 兼容）。

### IT-game-app-3-11：_new_game 重置 _prev_snap（r2-3 修订）

**前置**：`app_in_playing`，手动设 `app._prev_snap` 为非 None（模拟旧局残留）。
**步骤**：
1. 调 `app._new_game(Difficulty.MEDIUM)`；
2. 断言 `app._prev_snap is None`（r2-3 修订：`_new_game` 首行重置）；
3. 断言 `_render` PLAYING 路径 `_interpolation_state(snap)` 返 None（新局首帧瞬移）。

**预期**：r2-3 修订防御新局开局蛇身漂移；新局首帧不读残留快照。

### IT-game-app-3-12：OVER→GAME_OVER 切换帧 _prev_snap=None

**前置**：`app_in_playing`。
**步骤**：
1. 手动 `app._prev_snap = mock_snap`；
2. 强制 `app.game_state.step` 返 `dataclasses.replace(game_state, status=GameStatus.OVER)`；
3. 调 `app._tick(160)` → 断言 `app.screen == AppScreen.GAME_OVER`；
