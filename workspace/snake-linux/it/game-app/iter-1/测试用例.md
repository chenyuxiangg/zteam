> MTO 产出 · 依据整体测试方案 `snake-linux/testplans/v2.0.0/整体测试方案.md` §2.1/§2.3 与测试套件框架设计 §2/§3
> 依据模块设计 `snake-linux/design/game-app/设计-r3.md`（SE r3 评审通过，FO TDD 已落）
> 模块代码 `snake-linux/code/game-app/iter-1/`（MDE 检视 PASS；FO 实现已落）
> 依赖模块：`game-core` 迭代 2（`code/game-core/iter-2/`，it_passed）、`gui-renderer` 迭代 1（`code/gui-renderer/iter-1/`，it_passed）；platform-storage 迭代 1 不接入
> 承载需求：FR-01~04（玩法闭环入口）/FR-05（难度选择入口）/FR-11（开始/重开/退出）/NFR-01（帧率）/NFR-03（错误提示最小集）

## 0. 范围与依赖

- **被测对象**：`game_app` 包（`App` / `AppConfig` / `AppScreen` / `InputAction` / `AppError` / `GraphicsUnavailableError` / `ConfigError` / `_load_cjk_font` / `menu.draw_menu` / `menu.draw_game_over` / `_DIFFICULTY_LABEL` / `_STATUS_LABEL`）
- **协作模块**：game-core（提供 `GameState`/`Difficulty`/`Direction`/`GameStatus`/`Snapshot`）、gui-renderer（提供 `Renderer`/`HudData`/`RenderError`/`DEFAULT_SKIN`）；IT 不直接测其内部，仅通过其公开 API 触发 app 行为
- **测试驱动**：pytest 9.x；pygame 副作用通过 fake 模块桩化（沿用 code/game-app/iter-1/tests/conftest.py 的 fake_pygame 模式）
- **隔离策略**：所有 pygame 调用走 fake；Renderer 在大部分用例中被 MagicMock 替换（仅 _init_pygame/错误路径用真 fake Renderer）；事件序列通过 `fake.event.get.return_value` / `side_effect` 注入
- **用例编号**：`IT-game-app-1-{NN}`，与整体测试方案 §2.3 编号体系一致
- **优先级映射**：P0 = 玩法闭环/发布阻塞；P1 = 输入分发/渲染/接口契约；P2 = 字体回退/常量化边界
- **不重复测**：反向禁止/撞墙/撞身/吃食等核心玩法逻辑由 game-core IT 与 UT 覆盖，本模块 IT 仅验证 app 装配与状态机协作正确

## 2. 用例详情（关键 P0）

### IT-game-app-1-01：App 构造无副作用

**前置**：fake_pygame 已注入；无 App 实例。
**步骤**：`App()`。
**预期**：
- `app.screen == AppScreen.MENU`
- `app._difficulty == Difficulty.MEDIUM`
- `app._high_score == 0`
- `app._renderer is None`（R3-10：构造期不构造 Renderer）
- `app._running is True`
- `app.game_state is None`
- `fake.init.call_count == 0`（不调 `pygame.init()`）
- `fake.display.set_mode.call_count == 0`（不创建窗口）

### IT-game-app-1-12：R3-1 _drain_events MENU 态 None→START

**前置**：构造 `app`（screen=MENU，fake_pygame 已注入）。
**步骤**：`fake.event.get.return_value = [FakeEvent(KEYDOWN, key=K_x)]`（K_x 未映射）；调 `app._drain_events()`。
**预期**：返 `[InputAction.START]`（MENU 态未映射 KEYDOWN → START）。

### IT-game-app-1-13：R3-1 _drain_events MENU 态方向键→START

**前置**：构造 `app`（screen=MENU）。
**步骤**：`fake.event.get.return_value = [FakeEvent(KEYDOWN, key=K_UP)]`；调 `app._drain_events()`。
**预期**：返 `[InputAction.START]`（**不是** MOVE_UP；满足"按方向键也能开始"）。

### IT-game-app-1-14：R3-1 _drain_events MENU 态保留键透传

**前置**：构造 `app`（screen=MENU）。
**步骤**：`fake.event.get.return_value = [FakeEvent(KEYDOWN, key=K_2)]`；调 `app._drain_events()`。
**预期**：返 `[InputAction.SELECT_MEDIUM]`（保留键不被 START 替换）。

### IT-game-app-1-25：_tick 累加 + 循环内重读 tick_ms

**前置**：构造 `app_in_playing`（已 _init_pygame + HARD 新局，初始 tick_ms=100）。
**步骤**：连续 `app._tick(170)` 一次。
**预期**：
- `step()` 被调用 1 次（170/100=1 余 70）
- `app._tick_accumulator_ms == 70`
- `app.screen == AppScreen.PLAYING`

### IT-game-app-1-28：_tick 循环内重读 tick_ms（吃食加速即时生效）

**前置**：构造 `app_in_playing`（MEDIUM 初始 tick_ms=160）。
**步骤**：伪造 snap.tick_ms 序列 `[160, 160, 100]`（吃食后加速）；`app._tick(420)`。
**预期**：
- 第 1 拍用 160：累加器 420-160=260
- 第 2 拍用 160：累加器 260-160=100
- 第 3 拍用 100（fake 已返回新值）：累加器 100-100=0，step 调 3 次
- 最终累加器=0

### IT-game-app-1-37：R3-2 渲染 MENU

**前置**：`app_with_mock_renderer`（_renderer=MagicMock，screen=PLAYING）；临时切回 `app.screen = AppScreen.MENU`。
**步骤**：`app._render()`。
**预期**：
- `fake.display.get_surface.call_count >= 1`（用 get_surface 取 surface）
- `app._renderer.render.call_count == 0`（MENU 态不调 renderer.render）
- `pygame.display.flip.call_count >= 1`

### IT-game-app-1-39：R3-11 渲染 PLAYING 共享 snap

**前置**：`app_with_mock_renderer`（_renderer=MagicMock，screen=PLAYING，game_state=MagicMock）。
**步骤**：`app._render()`。
**预期**：
- `app._renderer.render.call_count == 1`
- `app.game_state.snapshot.call_count == 1`（R3-11：取一次 snap 同时给 _build_hud）

### IT-game-app-1-42：R3-15 退出码 2 路径 shutdown 兜底

**前置**：fake_pygame 注入；`fake.display.set_mode.side_effect = RuntimeError("no display")`。
**步骤**：`App().run()`。
**预期**：
- 返回值 == 2
- `fake.display.set_mode.call_count >= 1`
- `fake.quit.call_count >= 1`（退出码 2 路径也尝试 shutdown 兜底，R3-15）
- `sys.stderr` 含"[错误]"与"图形"或"无法初始化"可读提示

### IT-game-app-1-46：端到端主链路

**前置**：fake_pygame 注入；构造 App；mock renderer。
**步骤**：
1. 注入事件：`[K_2, K_RETURN, ... 撞墙 (drive until status=OVER) ..., K_r, ... 撞墙 ..., QUIT]`
   - 用 fake.event.get.side_effect 序列逐帧注入
   - 撞墙通过直接 monkeypatch game_state.step 多次返回 OVER 触发
2. 调 `app.run()`。
**预期**：
- 全程最终退出码 == 0
- 经过的状态序列：MENU → PLAYING → GAME_OVER → PLAYING → GAME_OVER → break
- `fake.quit.call_count >= 1`
