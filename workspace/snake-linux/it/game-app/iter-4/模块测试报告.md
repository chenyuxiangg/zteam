## 缺陷详情（MTO-4-01，P0）

### 现象
SDL dummy + 真实 pygame 2.6.1 下，`game-app _render()` PLAYING 路径首帧即崩：

```
File "gui_renderer/renderer.py", line 337, in render
    screen.fill(self._skin.background)
TypeError: invalid color argument
```

### 根因
`gui_renderer/types.py` 的 `Color` 是自定义 frozen dataclass（`Color(r=18, g=18, b=24)`），
而 pygame 的 `Surface.fill()` / `pygame.draw.*` 系列 API 仅接受 tuple / str / pygame.Color，
不接受自定义 dataclass 实例（无 `__iter__` / 非 Color 可解析对象）。

### 复现
```bash
SDL_VIDEODRIVER=dummy PYTHONPATH=<四 code 目录> python3 -c "
import pygame; from gui_renderer import DEFAULT_SKIN
s = pygame.Surface((100, 100))
s.fill(DEFAULT_SKIN.background)   # TypeError: invalid color argument
s.fill((DEFAULT_SKIN.background.r, DEFAULT_SKIN.background.g, DEFAULT_SKIN.background.b))  # OK
"
```

### 影响面
- `Renderer.render()` 全路径（背景填充/蛇身/食物/网格/HUD 颜色）——真实环境首帧必崩
- `scripts/bench_fps.py` / `bench_memory.py` 的 `run_benchmark()`（内部调 `_render()`）——性能无法实测
- 皮肤系统（FR-10）在真实环境的视觉呈现不可达；NFR-03"可运行性"受损

### 为何 iter-3 IT 未暴露
gui-renderer iter-3 IT 全部走 fake 桩（`fake_pg.draw.calls` 断言调用参数），从未在真实
pygame 下执行 `render()`；本 IT 是首次真实集成（SDL dummy + 真实 Renderer + 真实 pygame）。

### 修复建议（gui-renderer 侧最小侵入，FO 决定）
`renderer.py` 内所有传给 pygame API 的颜色参数先转换：
`(c.r, c.g, c.b)`（tuple）或 `pygame.Color(c.r, c.g, c.b)`。
涉及字段：background / grid_line / snake_head / snake_body / food / food_outline /
hud_text / hud_accent，含插值绘制路径。改后本 IT 4-02/4-14/4-15 复测即可闭环。
