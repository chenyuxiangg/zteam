## 0. 范围与依赖

- **被测对象**：`game_core` 包（Point / Direction / Difficulty / GameStatus / Snake / Food / Snapshot / GameState / spawn_food / speed_curve / MIN_TICK_MS / ScoreCallback / InvalidStateError）
- **测试驱动**：pytest 9.x（与框架设计 §1 一致）；运行时零第三方依赖（NFR-05）
- **隔离策略**：RNG 注入 `random.Random(seed)` 实现确定性；模块不依赖文件系统/网络；无 GUI/SDL 初始化
- **用例编号**：`IT-game-core-2-{序号}`，与整体测试方案 §2.3（IT-game-core-2-01~03）编号体系一致
- **优先级映射**：P0 = 核心功能/发布阻塞；P1 = 鲁棒性边界；P2 = 接口契约细节

## 2. 用例详情（关键 P0）

### IT-game-core-2-01：toggle_pause RUN→PAUSED 字段冻结

**前置**：20×15 MEDIUM 状态 + 固定 seed。
**步骤**：构造 `gs`，调用 `paused = gs.toggle_pause()`。
**预期**：
- `paused.status == GameStatus.PAUSED`
- 字段冻结（INV-9）：`paused.snake.body == gs.snake.body`、`paused.food == gs.food`、`paused.score == gs.score`、`paused.length == gs.length`、`paused.direction == gs.direction`、`paused.difficulty == gs.difficulty`

### IT-game-core-2-02：toggle_pause PAUSED→RUN + INV-8 清 pending

**前置**：20×15 MEDIUM，先 `set_direction(UP)` 登记 pending，再连续两次 `toggle_pause()`。
**步骤**：`s1 = gs.set_direction(Direction.UP)`；`s2 = s1.toggle_pause()`（RUN→PAUSED）；`s3 = s2.toggle_pause()`（PAUSED→RUN）。
**预期**：
- `s2.status == PAUSED`
- `s3.status == RUN`
- `s3.pending_direction is None`（INV-8 关键：恢复时清空 pending，防止"暂停前按 UP、继续后第一拍 180° 撞尾"）

### IT-game-core-2-06：INV-8 核心防呆

**前置**：构造 5×5 网格 + 蛇身布局，使 set_direction(UP) 后第一拍将撞自身（避免误判通过）。
**步骤**：`s1 = gs.set_direction(Direction.UP)`；`s2 = s1.toggle_pause()`；`s3 = s2.toggle_pause()`；`after = s3.step()`。
**预期**：
- `s3.status == RUN`、`s3.pending_direction is None`
- `after.status == GameStatus.RUN`（未撞自身，因 UP pending 已被清空）
- `after.direction == Direction.RIGHT`（按原 direction 走，不是 UP）
- `after.snake.head` 按原 direction 前进

### IT-game-core-2-08：speed_curve score=0 三档基线

**步骤**：对每个难度调用 `speed_curve(0, d)`。
**预期**：
- `speed_curve(0, Difficulty.EASY) == 250`
- `speed_curve(0, Difficulty.MEDIUM) == 160`
- `speed_curve(0, Difficulty.HARD) == 100`

### IT-game-core-2-09：speed_curve HARD ≤ EASY*0.5

**步骤**：对 `score in [0, 100]` 循环（subTest），计算 `t_hard = speed_curve(score, HARD)`、`t_easy = speed_curve(score, EASY)`。
**预期**：所有 score 下 `t_hard <= t_easy * 0.5`（NFR-01 量化）。

### IT-game-core-2-13：Snapshot.tick_ms 走 speed_curve

**前置**：20×15 MEDIUM，固定 seed。
**步骤**：构造 `gs`，多次 step 直到 score≥3，记录每次 `snap.tick_ms`。
**预期**：
- `snap.tick_ms == speed_curve(snap.score, snap.difficulty)`
- 至少 1 次断言：`score=3` 时的 tick_ms **小于** `score=0` 时的 tick_ms（验证随得分加速）

### IT-game-core-2-14：on_score 回调触发

**前置**：构造 5×5 网格 + 把食物放到蛇头正前方一格；构造时 `score_callback=lambda s: events.append(s)`。
**步骤**：`after = gs.step()`（吃到食物）。
**预期**：
- `after.score == 1`
- `events == [1]`（回调收到 new_score=1）
- `len(events) == 1`（单 tick 最多 1 次）

### IT-game-core-2-17：回调异常不捕获 + pure-function 语义

**前置**：构造 5×5 网格 + 把食物放到蛇头正前方一格；构造时 `score_callback=lambda s: exec('raise RuntimeError("boom")')`。
**步骤**：`before = gs.snapshot()`；执行 `gs.step()` 期望抛错。
**预期**：
- 抛 `RuntimeError`（core 不捕获，向外传）
- `gs.snapshot() == before`（**旧 state 未被污染**——pure-function 语义：new_state 随异常一起丢失、不可达）
- 不依赖返回的 new_state（因异常已抛）

### IT-game-core-2-21：回归 iter-1 核心行为

**前置**：复用 iter-1 已落地用例的核心断言（移动/吃食/反向/碰撞/OVER 保护）。
**步骤**：在 iter-2 测试代码中**直接导入** `iter-1` 测试文件并运行（或手工跑关键子集）。
**预期**：iter-1 的所有 P0 断言在 iter-2 代码下仍通过（无破坏性变更）。
