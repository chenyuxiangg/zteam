## 2. 发现的问题（不阻塞 PASS，按优先级）

### P1-01 框架文档错误：conftest.py `ws_dir` fixture 路径定位错误（实现前必改）

框架设计 §3.1：`Path(__file__).resolve().parents[3]  # tests/v2.0.0 -> workspace/snake-linux`

- **错误**：conftest.py 位于 `workspace/snake-linux/tests/v2.0.0/conftest.py` 时，`parents[0]=v2.0.0、[1]=tests、[2]=snake-linux、[3]=workspace`——`parents[3]` 实际返回 **workspace 根**，而非注释声称的 `snake-linux`；
- **影响**：MTO 照抄实现会导致被测代码路径定位到错误层级，所有依赖 `ws_dir` 的用例无法找到被测代码（直接连锁失败）；
- **处置**：应改为 `parents[2]`（返回 snake-linux），或按 v1 已验证的"由测试目录上溯工作区"模式重新计算；MTO 写 conftest.py 前必须修正，TE 评审用例文档时核对。

### P2-01 覆盖缺口：NFR-02 CPU 占用 ≤10% 指标无断言口径

- 规格 NFR-02 含两项指标：内存 ≤300MB **与 CPU 占用 ≤10%（单核，空闲画面）**；
- 整体方案 §3.3 性能维度、ST-08 口径、框架 `perf_snake.py` 均只列 FPS/帧时间 P95/输入延迟/内存，**CPU 指标全程缺失**；
- 处置：`perf_snake.sh` 已有 pidstat 优先/ps 兜底（pidstat 可采 CPU），建议在性能脚本与 ST-08 补充 CPU 采样断言并留档。

### P2-02 文档结构：ST-07/ST-08 被引用但 §3.1 用例清单未定义

- §3.2/§3.3 引用 ST-07（兼容矩阵）、ST-08（性能基线），但 §3.1 用例清单仅列 ST-01~06，ST-07/08 无步骤要点/关键断言条目；
- 落点实际存在（checklist-system.md + perf 脚本），属清单不完整而非能力缺失；
- 处置：§3.1 补 ST-07/08 条目（或显式指向 checklist-system.md/perf_snake 脚本），避免 STO 执行时口径漂移。

### P2-03 技术细节：pytest 9.x 与 Python 3.8 基线冲突

- 框架选型 `pytest（9.x）` 要求 Python ≥3.9，被测代码基线为 3.8（架构约定"语法兼容 3.8"）；
- 测试侧依赖不影响被测代码 3.8 兼容性，但**若测试机/CI 用 Python 3.8 环境将无法安装 pytest 9.x**；
- 处置：明确测试机 Python ≥3.9（推荐，测试侧与产品侧基线分开声明），或降级 pytest 8.x（支持 3.8）二选一，写入 requirements-test.txt 约束。

### P3 观察项（不阻塞，执行时落实即可）

1. **打包构建无自动化冒烟**：PyInstaller 构建正确性仅靠 ST-01/07 人工验收；建议 IT-app-4 增加 Linux 本机构建冒烟（构建成功+产物可启动），Windows/macOS 侧维持人工矩阵；
2. **HiDPI 验证未显式编号**：框架 assets/expected 提及 HiDPI，但整体方案用例清单无对应条目；建议落 checklist-system.md 人工项明确化（NFR-04 高分屏清晰）；
3. **迭代出口验收 ↔ 用例无显式对照表**：分工表每迭代出口（验收 1/4、2/4、3、5/6/7）与用例的对应需从 §4 自行推导；建议执行期在每迭代收口记录中显式勾选。
