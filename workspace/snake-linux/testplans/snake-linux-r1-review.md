## 2. 评审意见列表
- **[建议]** 建议-01：TC-I-05（端到端玩法闭环）覆盖 FR-05~FR-11 共 7 项需求，步骤为「操控蛇吃 3 个食物 → 撞墙 → 观察结束画面」，建议在测试脚本落地时拆分为 3 个独立断言步骤（吃食增长验证、撞墙结束验证、结束画面验证），避免单用例断言过多导致定位困难。
  - 依据：§3.2 TC-I-05 预期结果含多个独立断言（蛇变长、得分增加、撞墙结束、结束画面），IT 落地时拆分可提高失败定位效率，但不影响本方案评审结论。

- **[建议]** 建议-02：§4 环境限制声明「终端矩阵实机需 4 种终端可用，若环境受限则按 GNOME Terminal ≥ xterm ≥ SSH ≥ Konsole 优先级缩减」，建议在 testplan 中或配套 checklist 文件中预留「缩减记录」字段（实际测试了几种、缺失原因），方便发布审计追溯。
  - 依据：NFR-06 要求「行为一致」，覆盖矩阵缩减后若未留痕可能导致评审/审计时无法判断该 NFR 是否充分验证。

- **[建议]** 建议-03：§6 风险表中「pexpect 时序脆弱」对策为「全部用 expect 屏幕内容轮询 + 超时重试」，建议在集成测试脚本落地时对超时阈值（expect 最大等待时间）和重试上限给出显式默认值，避免不同执行环境因隐式默认值差异导致假失败。
  - 依据：pexpect 的 timeout 默认值因版本而异，不给显式值可能在慢速 CI 环境触发误报。
