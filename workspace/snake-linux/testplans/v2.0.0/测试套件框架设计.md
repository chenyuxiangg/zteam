# 测试套件框架设计：snake-linux v2.0.0

> TE 产出 · 与《整体测试方案.md》配套；MTO/STO 按本文档落地测试代码
> 继承 v1.0.0 已验证模式：pytest 单元 + pexpect PTY 集成 + 性能基线脚本 + 人工清单；新增 GUI 层 headless 驱动

## 1. 技术选型与依赖

| 项 | 选型 | 说明 |
|----|------|------|
| 语言 | Python 3.8+ | 与被测代码同基线（语法兼容 3.8） |
| 单元/集成框架 | pytest（9.x） | 参数化（难度档位/皮肤）、marker 分级、junitxml 报告 |
| PTY 驱动 | pexpect + miniterm（复用 v1 资产） | 进程级端到端、信号/退出卫生测试 |
| GUI 渲染测试 | Pygame + SDL dummy 驱动 | `SDL_VIDEODRIVER=dummy` headless 渲染，可 CI；真实视觉走 ST 人工 |
| 事件注入 | 合成事件队列（pygame.event.post） | 驱动 game-app 主循环，确定性测试界面流程 |
| 依赖策略 | 测试侧依赖仅限测试目录；**被测代码运行时零第三方依赖不破坏**（core/storage 纯标准库） | 对齐 NFR-05 |
| 安装源 | 清华镜像（国内网络）：`uv pip install --index-url https://pypi.tuna.tsinghua.edu.cn/simple pytest pexpect pygame` | |

## 3. 公共设施（fixture / 驱动 / 断言规范）

### 3.1 conftest.py 核心 fixture

```python
# 被测代码定位（对齐 v1 模式：由测试目录上溯工作区，不硬编码绝对路径）
@pytest.fixture(scope="session")
def ws_dir():
    return Path(__file__).resolve().parents[3]  # tests/v2.0.0 -> workspace/snake-linux

@pytest.fixture(scope="session", autouse=True)
def sdl_dummy():
    os.environ.setdefault("SDL_VIDEODRIVER", "dummy")  # headless 渲染；真实视觉走 ST
    os.environ.setdefault("SDL_AUDIODRIVER", "dummy")

# 模块级 fixture：core / storage / renderer / app 各自提供被测对象实例
@pytest.fixture
def game(ws_dir): ...            # 构造 GameState（含初始蛇身/方向/食物可控注入）
@pytest.fixture
def store(tmp_path): ...         # HighScoreStore(tmp_path) 隔离目录
@pytest.fixture
def renderer(): ...              # Renderer(skin) + dummy 表面
@pytest.fixture
def app_driver(): ...            # game-app 装配：合成事件注入 + 帧推进
```

### 3.2 驱动模式

- **core/storage**：纯对象调用，确定性断言（无等待、无 sleep）；
- **renderer**：`SDL_VIDEODRIVER=dummy` 下 `render(snapshot)` 到离屏 Surface → 像素/结构断言（皮肤间差异、元素存在性、缩放后坐标映射）；帧率用 `fps_metric()` 采样统计；
- **app**：合成事件队列驱动（`pygame.event.post` 投递 KEYDOWN/QUIT/WINDOWRESIZED）→ 推进 N 帧 → 断言状态机迁移与 renderer 调用参数；退出用 pexpect 进程级验证（残留进程/退出码/1 秒内结束）；
- **进程级**：打包产物/真实环境用 pexpect 启动（复用 v1 `e2e_snake.py` 的 launch/read_frame/read_screen + miniterm 模式），信号测试（SIGINT/SIGTERM）与 termios 恢复断言直接沿用。

### 3.3 断言规范

- 一律用断言消息说明关联需求编号（如 `assert s.status == Status.OVER, "FR-04 撞墙结束"`）；
- 坐标断言：沿用 v1 约定 Point(x,y)、y 向下、0,0 左上；蛇头=s.north…（以实现为准，接口契约见架构设计 §接口清单）；
- 时间类断言（性能/帧率）：统计采样+分位数判定，不用固定 sleep 断言（v1 踩坑教训：轮询周期与 tick 相位锁定导致假失败，读取窗口 ≥1 个 tick 周期）；
- 随机类断言（食物生成）：重复 N 次采样断言性质（不与蛇身重叠），不断言具体坐标。

### 3.4 数据准备

- 难度/皮肤等参数表以架构设计 §接口清单为唯一事实源，测试内复制参数常量并在 setup 断言与实现一致（防参数漂移）；
- 最高分持久化用 tmp_path 注入，不触碰真实用户数据目录；
- 截图基线存 `assets/expected/`，皮肤/缩放/HiDPI 断言与人工比对共用。

## 4. 执行方式与报告

```bash
cd workspace/snake-linux/tests/v2.0.0
bash run_all.sh                          # 一键：UT + IT + ST 自动化 + 性能基线
python3 -m pytest -q core/ storage/      # 无 GUI 部分（无头 CI 可全跑）
python3 -m pytest -q -m "p0" --junitxml=report.xml   # P0 子集/门禁模式
```

- **退出码约定**：0 = 自动化全过（P2 SKIP 不计失败）；1 = 存在 P0/P1 失败（发布阻塞）；2 = 测试侧依赖缺失；
- **marker 分级**：`p0`/`p1`/`p2` 对应整体测试方案 §6 优先级；P0 失败阻塞对应模块迭代/版本；
- **报告**：pytest junitxml + 控制台结构化汇总（v1 模式：分模块列通过/跳过/失败）；性能基线写 `perf/基线-{日期}.md` 留档；
- **CI 集成**：无头 CI 跑 core/storage/renderer/app 全部自动化（SDL dummy 无需显示服务器）；ST 人工部分（三平台/观感/兼容矩阵）由 checklist-system.md 留痕，纳入发布就绪度判定（整体测试方案 §3.3）。

## 5. 与 v1.0.0 测试资产的衔接

| v1 资产 | 复用方式 |

| `miniterm.py` | 直接复用（PTY 屏幕重建，e2e/perf 共用） |

> 注意：v1 被测代码路径（curses 终端版）与 v2 不同，所有路径定位改指 v2.0.0 代码目录；v1 测试集保留不动（已 released 版本资产归档）。

## 6. 执行纪律（铁律）

1. **用例先评审后编码**：MTO/STO 用例文档 → TE 评审 PASS → 才可写测试代码（整体测试方案 §5）；
2. **被测代码路径只读**：测试不得修改业务代码；被测对象构造需可控注入（食物位置/蛇身/方向）——如实现不满足，打回 FO 补测试钩子而非绕过；
3. **无网络断言**：core/storage/renderer 测试不得触碰网络（NFR-06 静态检查并入 IT-app-4 或单独走查项）；
4. **随机/时序用例确定性化**：种子注入或性质断言，禁止依赖时序侥幸通过（v1 假失败教训）。
