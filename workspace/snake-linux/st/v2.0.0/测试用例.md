## 0. 范围与定位（ST 与 IT 的分工）

| 维度 | 模块 IT（MTO 已执行，9 个迭代全 PASS） | 本 ST（STO 执行） |
|------|----------------------------------------|-------------------|
| 验证对象 | 模块内部集成契约（core 玩法 / storage 持久化 / renderer 渲染 / app 装配各自内部） | **版本级端到端主链路**（用户旅程 ST-01~05）+ 跨模块协同（ST-07/08）+ 全量回归（ST-09）+ 发布就绪度（ST-13/14） |
| 驱动方式 | 各模块独立 pytest（真实依赖装配） | 真实四模块装配 + 事件注入端到端 + 进程级 + 全量 IT 回归重跑 + 性能脚本真实执行 |
| 关键差异 | 单模块真实成立 | **多模块串联的完整用户旅程是否成立**（开始→选难度→游玩→暂停→切皮肤→结束→重开/退出）、重启持久化、退出卫生、发布物齐备、性能基线 |

## 2. 用例明细

### ST-01：开箱即用（FR-14/FR-16/NFR-07）

**前置**：真实资产层文件 `snake-linux/{spec,scripts,release}/`；SDL dummy；PYTHONPATH 四 code 目录；XDG 隔离。
**步骤**：
1. 打包资产齐备：`spec/snake-gui.spec` 实存，含 `name="snake-gui"`、字体 datas（`SourceHanSansCN-Regular.otf`）、三包 hiddenimports（game_app/platform_storage/gui_renderer）、pathex 四目录；
2. 三平台构建脚本实存：`scripts/build_linux.sh` / `build_windows.bat` / `build_macos.sh` / `gen_sha256sums.sh`，bash 脚本 `bash -n` 语法检查通过；
3. 发布物实存：`release/USER_GUIDE.md`、`release/RELEASE_NOTES.md`、`release/SHA256SUMS`；SHA256SUMS 每行格式 `<64hex>  <file>`，对 USER_GUIDE.md/RELEASE_NOTES.md 重算 sha256 与记录一致（真实哈希校验）；
4. 源码模式启动链路成立（等价"免预装直接运行"的本机可验证近似）：子进程 `python -m game_app` 事件注入 QUIT → 退出码 0、stderr 无异常。

**预期**：发布物齐备且校验和可验证（NFR-07）；启动链路成立（FR-14 本机近似，真实干净机器验收归 ST-14 人工清单）；文档存在（FR-16）。

### ST-02：开始→选难度（FR-05/FR-11）

**前置**：真实装配 fixture（真实 Renderer SDL dummy + 真实 HighScoreStore(tmp)）。
**步骤**：
1. MENU 态注入 `SELECT_MEDIUM` → 断言 `screen==PLAYING`、`snapshot().difficulty==MEDIUM`、`snapshot().tick_ms==160`（参数表穿透 app）；
2. 重开新局 `SELECT_EASY` → tick_ms==250；`SELECT_HARD` → tick_ms==100（三档均开局可选且生效）；
3. 游戏中（PLAYING 态）注入 `SELECT_HARD` → 断言无难度切换效果（无切换入口，防规避 FR-05 约束）；
4. 注入 `TOGGLE_PAUSE` → 恢复后难度不变。

**预期**：三档开局可选、选档生效、游戏中不可切换（FR-05 验收 2）；开始/重开流程成立（FR-11）。

### ST-03：完整对局（FR-01~04/06~10/12）

**前置**：真实装配 fixture。
**步骤**：
1. `_new_game(EASY)` → 断言 PLAYING；注入 `MOVE_RIGHT` → `_tick(16)` ×N 循环真实渲染 `_render()`，吃到 ≥3 个食物 → 断言 `score>=3`、长度增长（FR-01 吃食增长）；
2. 暂停/继续：注入 `TOGGLE_PAUSE` → PAUSED + 记录快照 → 注入 `TOGGLE_PAUSE` 恢复 → 断言蛇位/得分/长度不变（FR-12 暂停原位恢复）；
3. 皮肤切换（PLAYING 态 `SET_SKIN_NEXT` 透传为 MOVE_RIGHT，对局不中断）：切换后 `current_skin_name` 变化且 `screen` 仍 PLAYING（FR-10）；
4. 持续 `_tick` 到撞墙 → `screen==GAME_OVER` + `status==OVER`，`_render()` 三态（PLAYING/PAUSED/GAME_OVER）真实绘制全程无异常（FR-04/06/07）；
5. GAME_OVER 态注入 `RESTART` → 新局 PLAYING；再结束注入 `BACK_TO_MENU` → MENU（FR-11 重开/退出）。

**预期**：端到端主链路完整成立——吃食增长、暂停原位、皮肤即时生效不中断、结束画面稳定、重开/退出可用（验收 1/3/4）。

### ST-04：最高分持久化（FR-13/NFR-06）

**前置**：`tmp_path` 隔离；真实 HighScoreStore。
**步骤**：
1. App A（真实装配，monkeypatch `create_storage` → `HighScoreStore(tmp/hs.json)`）：`_new_game` → 触发 `score_callback(120)` → 断言 `_high_score==120` + hs.json 实存且 JSON 含 120（真实落盘）；
2. App B（模拟重启，同 tmp 目录）：`_init_pygame()` → 断言 `_high_score==120`（重启保留，INV-12）；
3. `_dispatch_menu(RESET_HIGHSCORE)` → 断言归零 + 文件删除（reset 契约）；
4. 数据仅本地：断言全部写入均在 tmp 隔离目录内（NFR-06 本地性）；`import game_app` 运行期无网络模块（并入 ST-12 复核）。

**预期**：单局高分超过历史最高分时更新保存；重启后仍显示；重置归零；数据仅本地（FR-13/NFR-06 验收 4）。

### ST-05：退出卫生（FR-11）

**前置**：真实子进程（`python -m game_app`，PYTHONPATH 四目录 + SDL dummy + XDG 隔离）。
**步骤**：
1. PLAYING 中注入 QUIT → 断言退出码 0、耗时 < 1 秒；
2. PAUSED 中注入 QUIT → 断言退出码 0、耗时 < 1 秒；
3. GAME_OVER 中注入 QUIT → 断言退出码 0、耗时 < 1 秒；
4. 三种时机退出后 `ps` 检查无 `game_app` 残留进程。

**预期**：任意时刻退出 1 秒内干净结束、无残留进程（FR-11/IT-app-4-02 口径）。

### ST-06：用户指南走查（FR-16）

**前置**：`release/USER_GUIDE.md` 真实文件。
**步骤**：
1. 五节齐全：下载与运行 / 键位表 / 难度 / 皮肤 / 暂停 / 平台差异 / 已知限制（§1~§7）；
2. 键位表与实现一致：指南键位（WASD/方向键/P/ESC/←→ 皮肤切换）与 `game_app.input` 映射一一对应；
3. 难度三档（简单/普通/困难）与 `Difficulty` 枚举一致；皮肤说明（经典/深色/色盲友好）以中文口径核对（指南面向用户用中文名，英文标识符与实现 SKIN_REGISTRY 一致性由 ST-07d/ST-09 断言）；
4. 按文档可复现启动：`python -m game_app` 冒烟（与 ST-01 步骤 4 同路径，文档驱动验证）。

**预期**：文档五节齐全且可复现启动（FR-16 验收 5）。

### ST-07：跨模块契约锚点（§3.2 回归锚点）

**前置**：真实四模块导入。
**步骤**：
1. core `snapshot()` 返回 7 字段（snake_body/food/score/length/status/difficulty/tick_ms）——renderer/app 均依赖的接口契约；
2. 难度参数表：EASY 250 / MEDIUM 160 / HARD 100，且 `HARD.base_tick_ms <= EASY.base_tick_ms * 0.5`（档位差异可感知，NFR-01）；
3. storage 数据格式：`HighScoreStore` load/save 的 JSON schema（`high_score` 字段）与 app 落盘内容一致；
4. renderer 契约：`skin_names()` 3 套、`MIN_PLAYABLE_W/H` 常量存在、`set_skin`/`handle_resize`/`render(interp=)` 签名可用。

**预期**：跨模块接口契约无漂移（§3.2 关键回归锚点）。

### ST-08：全量自动化回归（§3.2）

**前置**：全部已实现 IT 测试集（9 个迭代）。
**步骤**：
1. 重跑 `it/game-core/iter-1`、`iter-2`、`it/platform-storage/iter-2`、`it/gui-renderer/iter-1`、`iter-3`、`it/game-app/iter-1~4` 全部测试文件；
2. 非白名单目录：断言 P0/P1 全部 PASS（无 skip、无 fail）；
3. **已知测试版本错位白名单**（代码目录是"活目录"，后续迭代演进更新先前迭代目录，历史迭代 IT 测试断言当时代码快照——失败为测试过时非产品回归）：`game-app/iter-1` 4 条（06 AppScreen 无 PAUSED/07 枚举 15 项/09 ESC→QUIT/22 _pause_hint_shown 属性，均被 iter-2 FR-12 暂停与 G2-7 ESC 修订合法变更）+ `game-app/iter-3` 1 条（r3_15 mock `app_mod.Renderer`，被 iter-4 G4-2 `_create_renderer_with_hidpi_fallback` 重构使 mock 目标失效；真实退出码路径由 iter-4 IT 4-06/07/08 覆盖）。**白名单精确匹配：失败集 == 已知集（多出 = 疑似新回归，阻塞）**；
4. 汇总通过/失败/跳过计数。

**预期**：全量回归通过——core 接口变更未破坏 renderer/app；难度参数表未漂移；storage 格式兼容（§3.2）；白名单外无任何失败。

### ST-09：皮肤系统端到端（FR-10）

## 5. 已知差异（ST 落地时记录，供 TE/QA 关注）

1. **三平台矩阵本机不可达**：Windows/macOS 实测需对应平台构建机/CI（PyInstaller 不支持交叉打包，架构设计 §技术选型已声明）。本 ST 在 Linux 本机执行自动化 + 资产齐备核对；三平台完整对局矩阵（ST-14）列入人工清单 `checklist-system.md` 由发布环境/QA 执行，ST 报告如实标注。
