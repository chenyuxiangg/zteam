# tetris — Linux 终端俄罗斯方块（Python 标准库从零实现）

需求：`tetris/tetris`（r1）｜依据方案：`plans/tetris/tetris-r1.md`（终版）｜轮次：r1
交付物：`code/tetris/tetris-r1/`（本目录）

## 一、运行方式

```bash
# 在 Linux 终端（TTY）中直接运行，无需任何安装步骤
python3 tetris.py

# 自定义下落间隔（毫秒）
python3 tetris.py --tick 300

# 单色模式（无颜色/单色终端可用，以形状辨识方块）
python3 tetris.py --no-color

# 查看全部参数
python3 tetris.py --help
```

游戏玩法：7 种标准方块（I/O/T/S/Z/J/L）从顶部下落，用方向键/WASD 移动与旋转，
填满整行即消除并得分，堆叠至顶部（撞顶）游戏结束。退出后终端状态（光标/回显/颜色）
完全恢复，屏幕无残留。

## 二、依赖

- **Python 3.6+**（仅标准库，无任何第三方包；curses 为 Python 标准库自带模块）。
- Linux 终端环境（GNOME Terminal / Konsole / xterm / SSH 会话均可）。
- 无需安装、无需编译、无需 root 权限。

## 三、键位表

| 按键 | 动作 | 对应需求 |
|------|------|----------|
| W / ↑ | 旋转（顺时针 90°） | FR-09 / FR-18 |
| A / ← | 左移一格 | FR-08 / FR-18 |
| D / → | 右移一格 | FR-08 / FR-18 |
| S / ↓ | 软降（逐格快速下落，按住持续下移） | FR-10 / FR-18 |
| 空格 | 硬降（瞬间落底并锁定） | FR-11 / FR-18 |
| P | 暂停 / 继续 | FR-19 |

| Ctrl+C | 安全中断（同一恢复路径） | FR-20 / FR-23 |

WASD 与方向键两套方案均生效；被边界或堆叠方块阻挡的移动/旋转会被拒绝（不越界、不穿透）。

## 四、配置项

| 配置项 | 方式 | 取值范围 | 默认值 | 对应需求 |
|--------|------|----------|--------|----------|
| 下落间隔 | `--tick <毫秒>` | 50–2000 | 500ms | FR-03 |
| 颜色开关 | `--no-color` | 开/关 | 颜色开启 | FR-26 |

- 非法 tick 值（越界/非数字/负数）输出可读错误并以退出码 2 结束。
- 等级曲线（FR-16，Q-04 默认）：初始 500ms（或 `--tick` 指定值），每消 10 行升 1 级，
  每级下落间隔 × 0.9，下限 100ms。
- 环境边界（NFR-04）：非 TTY（管道/重定向/cron）运行 → 可读错误 + exit 1；
  无 `TERM` 环境变量（curses 无法初始化）→ 可读错误 + exit 1；
  终端小于 42×26 → 尺寸提示 + exit 3。三者均无裸 traceback。

## 五、已知限制

### 5.1 技术选型论证：curses vs 裸 ANSI 转义序列（需求原文要求，对应分析 §2.2/Q-09 路径①）

**结论：采用 Python 标准库 curses**（与 snake-linux 已通过评审的方案 §2 结论一致，直接继承），
理由与取舍如下：

| 维度 | curses | 裸 ANSI 转义序列 |
|------|--------|------------------|
| 依赖（FR-01） | 标准库自带，零第三方依赖 | 同样零依赖，但全部能力需自研 |
| 终端状态恢复（FR-23） | `wrapper()` 自动保存/恢复原始状态（noecho/cbreak/光标/颜色），官方 HOWTO 明确承诺「restore the original terminal settings」 | 需自行实现 termios 原始模式 + 终端状态保存/恢复，且要处理信号安全（Ctrl+C 时刻与恢复竞争的雷区） |
| 方向键解析（FR-18） | `keypad(True)` 后 `getch()` 直接返回 `KEY_UP/DOWN/LEFT/RIGHT`，免手工解析多字节转义序列 | 需自行解析 `ESC[` 序列，且要处理 ESC 键与序列的时序歧义 |
| 终端 resize（FR-04） | 内置 `KEY_RESIZE` 事件 + `resizeterm` | 需自行实现 SIGWINCH 处理 |
| 颜色（FR-26） | `has_colors/init_pair` 支撑 7 方块 7 色，不支持时自动降级单色 | 需自行管理各终端颜色能力表 |
| 终端能力差异（NFR-06） | terminfo 抽象，自动适配各终端 | 需自建各终端能力表 |
| 字节级可控性 | 略弱 | 强（但对本需求无实际收益） |

**取舍结论**：本需求是 10×20 小场地、每 tick 全量重绘，ANSI 的「字节级自由度」无实际收益，
却把终端卫生（状态恢复/方向键解析/resize/颜色对管理）全部变成自研风险；curses 是
FR-23/NFR-03「干净退出」的最短实现路径。故选择 curses，放弃裸 ANSI。

### 5.2 规则口径（按需求分解文档 Q 表默认值落地，Q-01~Q-14 全部采纳建议默认）

- 计分：1/2/3/4 行 = 100/300/500/800；**软降/硬降不加分**（FR-17 作废，Q-01 默认）；
- 旋转：简化旋转——碰撞即拒绝、无 wall kick（Q-02 默认，SRS 为增强项）；
- 随机：纯随机（`random.choice`），无 7-bag、无 lock delay（Q-03 默认）；
- 场地：固定 10×20 格（不含边框），每格渲染 2 字符宽；最小终端 42×26（FR-04）；
- 撞顶即结束：新方块生成位置被占用 → 游戏结束，显示最终得分后按任意键退出，
  不自动重开（FR-13/24，Q-13 默认）；
- 无分数持久化/最高分（Q-12 默认）、无键位自定义（Q-08 默认）；
- 最低 Python 3.6+（Q-05 默认，代码避免 3.7+ 语法：无 dataclass/海象运算符/removeprefix）。

### 5.3 实现层限制

- **单文件交付**（Q-06 默认）：全部逻辑在 `tetris.py` 内按职责分层（Config/模型/输入/渲染/主循环），
  详见文件头注释；若后续评审要求拆包，按方案 §8 拆为 `tetris/` 包（成本 < 1h）。
- **软降手感依赖键盘重复率**（OS 级）：软降为事件式下移（每按一次下移 1 格），
  按住时速度取决于系统键盘重复设置；FR-10 验收口径为「明显快于自动下落 + 松开恢复」，
  事件式天然满足。若实测手感不佳，可在 InputHandler 内做「按住计时软降」增强（方案 §6 风险对策，局部改动）。
- **纯随机的连续同型方块**：Q-03 默认纯随机，连续出同型方块属正常现象；7-bag 随机
  作为增强项（改 spawn 一处即可），如需求方后续拍板可低成本纳入。
- 边框与方块全部使用 ASCII 字符（`+ - |` 与 `[]`），不使用 Unicode 制表符，兼容老旧终端/SSH。
- 颜色仅用 curses 8 基础色；终端不支持颜色时自动降级为单色（以形状辨识方块）。
