# 测试方案：gomoku（r1）

## 0. 元信息
- 需求：gomoku/gomoku｜依据方案：workspace/gomoku/plans/gomoku-r1.md（plan 阶段终版，2026-08-10 评审 PASS）｜轮次：r1（testplan 阶段新生命周期首轮）
- 测试要点一句话：全量覆盖 FR-01~12/NFR-01~07——对照表驱动禁手单测、AI 封堵 10 连测、输入 fuzz、计时/性能断言、Docker 冒烟。

## 1. 测试目标与范围

### 目标
验证 gomoku 成品满足需求分解文档（analysis/gomoku-r6.md）全部 FR/NFR 验收标准，重点证明四项核心能力：
1. 胜负判定横/竖/斜五连无遗漏（含边界/角部/平局，FR-09）；
2. 禁手判定（双三/双四/长连，含跳形缺口外侧红线形态）与成五优先规则正确（FR-07）；
3. AI 三档棋力可验证：中/强档必堵双三/冲四/活三威胁（10 连测）、弱档合法不送死、禁手规避（FR-06）；
4. 终端体验完整：渲染/输入/退出/重开（FR-03/04/08/10/11），性能达标（NFR-01/02）。

### 范围内/范围外（MECE）
**范围内**：
- 功能测试：初始化（FR-01）、规则配置（FR-02）、渲染（FR-03）、输入（FR-04）、回合（FR-05）、AI（FR-06）、禁手（FR-07）、上一步（FR-08）、胜负（FR-09）、重开（FR-10）、退出（FR-11）、README 交付（FR-12）；
- 非功能测试：AI 落子耗时（NFR-01）、刷新耗时/启动耗时（NFR-02）、终端/环境兼容（NFR-03）、健壮性 fuzz（NFR-04）、模块化与单测覆盖核查（NFR-05）、安全（越界/本地性，NFR-06）、配置外显（NFR-07）；
- 回归测试：禁手对照表 ≥15 例（含前生命周期 code r2 FAIL 的红线形态 A1~A4 回归）；
- 验收/系统测试：干净环境（Docker python:3.10-slim）整局冒烟、`pip install .` 安装验证。

**范围外**（明确不测，附理由）：
- 联机/双人对战、GUI/Web 形态、棋谱/存档/开局库（需求明确不做，analysis §2.2）；
- 竞赛级 AI 棋力（定位娱乐级偏强，H5；只验证 FR-06 底线与进攻构造局例）；
- 19×19 棋盘（plan 明确不提供，Q3）；
- 性能压力测试/并发测试（单线程单进程模型无并发面，plan §5.4；只做耗时断言不做压测）；
- 第三方库漏洞扫描/供应链审计（本地单机、依赖仅 rich，超出本需求验收范围，由安全门禁把关）。

## 2. 测试策略（分层）

| 层级 | 策略与侧重 | 工具/方式 | 通过标准 |
|------|-----------|----------|----------|
| 单元测试 | board 纯逻辑全覆盖：落子/undo/胜负/满盘/坐标解析（test_board）；禁手判定以对照表驱动逐例断言（test_forbidden，≥15 例）；AI 决策（test_ai：封堵连测/弱档/禁手规避/耗时）；config 解析 | pytest（plan 选型；unittest 可退化） | pytest 全绿；禁手对照表 15 例与预期结论 100% 一致；AI 封堵 10 连测全过；耗时断言过 |
| 集成测试 | main 回合循环端到端：脚本驱动 `python -m gomoku` 喂输入序列（人类/AI 交替、重开、退出），断言状态栏/终局横幅/重开行为；渲染计时（GOMOKU_TIMING）断言单次刷新 <200ms | 集成脚本（pipe 输入 + stderr 计时抓取）+ pexpect（pty 交互） | 整局脚本对弈完成无异常；重开流程正确；连续落子 30 次刷新 P95 <200ms |
| 系统/验收测试 | 干净环境整局冒烟（Docker python:3.10-slim）、`pip install .`、README 按文档操作跑通；CLI 各参数生效验证；终端尺寸/无彩色降级验证 | Docker + shell 脚本 + 人工走查 checklist | 干净环境完整对局可玩；安装可执行；README 步骤无遗漏可复现 |
| 回归测试 | 禁手对照表全部用例（尤其 A1~A4 红线形态、A11 成五优先、A12 同方向去重、A13 白方无禁手）进单测防回归；前生命周期 code r2 FAIL 用例固定为回归基线 | pytest 对照表驱动（数据表驱动用例） | 每次代码变更后对照表用例全过，无历史缺陷复现 |
| 验收测试 | FR 验收点逐条对应（需求映射表 §3.1 保证可追溯）；性能验收（NFR-01/02）以脚本断言 + 实测值记录 | 用例表 + 计时脚本 | 每条 FR/NFR 验收标准均有对应用例通过或明确"人工走查"项 |

**测试类型覆盖**：功能（全部 FR）、边界（坐标边界/棋盘边界/输入边界）、异常（非法输入/中断/终局后输入）、性能（NFR-01/02 计时断言）、兼容性（NFR-03：终端尺寸/无彩色/SSH/Python 版本）。性能与兼容性按 NFR 范围执行，不做过度压测。

### 环境限制与假设
- CI/自动化环境无真实 TTY → rich 渲染断言用 `Console(force_terminal=True, width=60)` 捕获文本结构断言（行数/坐标/字符），视觉观感由人工在真实终端抽查（验收 checklist 项）；
- 性能数据受硬件影响：按 plan H10，低于基线硬件实测值只记录不判 FAIL；CI 宽限 0.5s；
- 交互类用例（Ctrl+C、重开选择）依赖 pexpect 可用；若 pexpect 缺失则退化为人工走查 checklist（记录在测试文档）；
- 假设 code 阶段按 plan §4 接口签名实现（Board.place/undo/check_win/check_forbidden/is_full/parse_move、ai.choose_move、CLI 参数）；接口变更时本方案用例同步更新（见 §6 风险行）。

## 5. 自动化方案（如适用）

- **自动化范围**：全部单元测试（board/禁手/AI/config）+ 集成脚本（回合循环端到端、渲染计时、输入 fuzz、重开/退出流程）+ Docker 冒烟自动执行；**人工保留项**：渲染视觉观感抽查、README 可读性走查（自动化断言结构，观感人工）。
- **工具选型（有据）**：pytest（plan §2 选型：Python 测试事实标准）；pexpect（pty 交互驱动，Linux 标准方案）；Docker（干净环境隔离，与 plan T7 一致）；不做额外框架引入（避免测试侧依赖膨胀）。
- **执行方式**：
  - 单元+集成：`pytest tests/ -x -q`（本地与 CI 均跑；`-k forbidden` 可单独跑对照表回归）；
  - 端到端冒烟：`bash scripts/smoke.sh`（构建 Docker 镜像 → pip install → 脚本对弈整局 → 断言终局横幅/重开 → 连续落子延迟检测，对应 plan T7）；
  - 触发时机：code 阶段每次提交后本地跑单测；里程碑 M1~M4（plan §7）各验收点由对应测试套件支持；发布前跑全量 + Docker 冒烟。
- **数据驱动**：禁手对照表（§4 数据准备）与 AI 封堵棋局以 JSON 数据文件驱动参数化用例，新增用例不改测试代码只加数据。
