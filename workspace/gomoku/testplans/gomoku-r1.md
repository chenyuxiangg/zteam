# 测试方案：gomoku（r1）

## 0. 元信息
- 需求：gomoku/gomoku｜依据方案：workspace/gomoku/plans/gomoku-r1.md｜轮次：r1（首轮）
- 测试要点一句话：分层覆盖棋盘规则内核、AI 三档棋力、终端交互与退出恢复，性能与健壮性量化达标。

## 1. 测试目标与范围
- 目标：验证实现满足需求分解文档 FR-01~FR-12 与 NFR-01~NFR-07 全部验收标准（对应需求原文 4 条验收标准：终端可玩/渲染清晰输入流畅、AI 不下臭棋、获胜判定准确、职责分离+README 干净环境跑通），为 test-developer 提供可执行用例依据。
- 范围内（MECE）：
  - 单元：board.py（落子/胜负/禁手/坐标解析/满盘/undo）、ai.py（三档难度/封堵/禁手规避/时限/降级）、config 与 CLI 参数解析；
  - 集成：main.py 回合循环（回合切换/终局/重开/输入重试）、ui 输入循环与 board 联动；
  - 系统：终端渲染（尺寸/彩色降级/无残留）、Ctrl+C 与 quit 退出恢复、SSH/伪终端、禁手开关端到端、干净环境 README 冒烟；
  - 性能：AI 强档中盘耗时（NFR-01）、启动耗时与刷新耗时（NFR-02）；
  - 健壮性：100 次随机合法/非法混合输入（NFR-04）、strace 联网/写目录检查（NFR-06）。
- 范围外（明确不测，含理由）：
  - 不写完整测试代码的实现细节审查（评审者职责）；
  - 不测联机/网络对战、GUI、棋谱/存档、双人同屏（需求明确不做，方案 §1 范围一致）；
  - 不测竞赛级棋力（定位娱乐级偏强，分析 H5/Q2，验收底线即 FR-06）；
  - 不测 19×19 棋盘（方案明确不提供，分析 Q3）；
  - 并发：方案为单线程单进程无共享状态（§5.4），并发风险不适用——以 NFR-06 无越界/无崩溃用例替代；
  - 资源耗尽：仅覆盖"棋盘满盘（平局）"与"AI 超时降级"两类可触达场景，内存/句柄耗尽在纯本地单进程场景无触发面。

## 2. 测试策略（分层）
- 单元层：pytest 直测 board/ai 纯逻辑接口，快速全量回归；重点覆盖胜负判定 4 方向+边界、禁手三规则+成五优先级、AI 封堵验收用例（FR-06 10 连测）；PASS 定义：用例全绿，无跳过（除对照表依赖项，见 §6）。
- 集成层：以脚本驱动真实 CLI 进程（subprocess + 伪终端），覆盖回合循环/终局/重开/输入重试；PASS 定义：断言状态切换与界面提示符合预期，10 局连开无异常。
- 系统层：伪终端（pty/script）模拟真实终端交互，覆盖渲染/退出恢复/无彩色降级/SSH 场景；PASS 定义：输出断言（坐标标注齐全、字符区分、无 ANSI 残留）+ 进程退出码 0 + stty 回显未破坏。
- 验收层：Docker 干净环境（python:3.10-slim）按 README 执行安装与启动，跑完一整局；PASS 定义：可安装、可启动、整局完成无报错。
- 回归层：每次代码修改后全量重跑单元+集成；系统/性能用例在 M3/M4 里程碑及缺陷修复后重跑；PASS 定义：与基线一致的用例全绿，无新增 FAIL。
- 测试类型：功能（全部 FR）、边界（坐标/棋盘尺寸/满盘/禁手临界）、异常（非法输入/中断/超时）、性能（NFR-01/02）、兼容性（终端尺寸/无彩色/SSH/Python 版本）、安全（NFR-06 联网与越界）。

## 3. 测试用例设计（核心）

### 测试挂载点（需求能力 → 被测接口）
- 胜负/满盘/坐标/落子合法性/undo → `Board.place/check_win/is_full/parse_move/undo`
- 禁手（长连/双四/双三+跳活三/成五优先）→ `Board.check_forbidden` + 主循环落子路径
- AI 三档/封堵/禁手规避/时限 → `ai.choose_move(board, color, difficulty)`
- 回合/终局/重开/输入重试 → `main` 回合循环 + `ui.get_move`
- 渲染/退出恢复/终端尺寸 → `ui.render` + CLI 进程级验证
- 配置/CLI → argparse 参数 + `config.py`

## 4. 测试环境与数据
- 环境：Linux x86-64（参考基线：i5-12400 及以上四核、≥8GB RAM、Python 3.10+，对应分析 NFR-01 声明）；备测 Python 3.10 / 3.11 / 3.12 各跑一遍单元与系统用例（NFR-03）；依赖 rich（与实现同版本锁定）+ pytest（开发依赖）。
- 终端模拟：系统级用例用 Python pty / `script -qec` / tmux 提供伪终端；无彩色环境用 TERM=dumb 与 NO_COLOR=1 双路模拟；窄终端用 pty 指定列数模拟 <24×60。
- 干净环境验收：Docker python:3.10-slim 镜像，按 README 命令安装（`pip install .`）并启动（与方案 T7/M4 一致）。
- 数据准备：棋盘局面构造器（测试 fixture，直接操作 board 摆盘，避免手工落子长序列）；禁手对照表（方案 T3 交付物，参数化用例输入）；随机序列固定 seed（如 42）保证 S-15 可复现；AI 中盘局面集（双方各 ≥20 子）预生成 ≥20 局存于测试数据目录。
- 环境限制与假设：CI 无 TTY 时系统用例经 pty 包装执行（见 §8 TP-Q1）；性能用例结果受硬件影响，按 NFR-01 基线声明记录、低于基线不判 FAIL；rich 渲染断言用字符/正则而非精确 ANSI 序列，避免终端差异导致的 flaky。

## 5. 自动化方案（如适用）
- 自动化范围：单元 + 集成 + 系统 + 性能全部自动化；仅"README 人工阅读性"（S-19 内容核对）为半自动（脚本检查关键章节存在 + 人工抽查）。
- 工具选型（有据）：pytest（方案选型一致，Python 测试事实标准）；子进程驱动用 subprocess + pty 模块（标准库，无需 pexpect 额外依赖；若输入时序控制不足再评估 pexpect）；性能采样用 pytest-benchmark 或自写采样脚本（取 P95）；Docker 冒烟脚本 docker run python:3.10-slim。
- 执行方式：`pytest tests/`（单元+集成，每个提交后跑）；`pytest tests/system -m system`（系统层，M3 后跑，需 pty）；`pytest tests/perf -m perf`（性能层，参考硬件上跑，结果写入测试报告）；`scripts/docker_smoke.sh`（M4 验收，一键冒烟）；触发时机：开发 T2~T7 每任务完成后跑对应子集，评审前跑全量。
