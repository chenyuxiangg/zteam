# 测试方案：gomoku（r1）

## 0. 元信息
- 需求：gomoku/gomoku｜依据方案：workspace/gomoku/plans/gomoku-r1.md｜轮次：r1（requeue 后首轮）
- 测试要点一句话：以方案接口为挂载点，对 FR-01~12/NFR-01~07 全覆盖——重点验证 AI 三档棋力可测底线（封堵 10 连测）、禁手判定（含跳形红线用例）、胜负判定与终端体验（渲染/输入/退出恢复）。

## 1. 测试目标与范围
- 目标：
  - 验证方案 §4 全部接口（Board 系列 / ai.choose_move / ui 系列 / CLI 参数）行为与需求验收标准一致；
  - 验证 FR-06 棋力底线可复现（中/强档封堵冲四/活三 10 连测、弱档合法不送死、强档有进攻）；
  - 验证 FR-07 禁手判定与方案 §5.2 对照表一致（含 `_X_XX_`/`_XX_X_` 跳形缺口外侧红线用例、成五优先）；
  - 验证 FR-09 胜负判定无漏判/误判（含边界/角部/满盘平局）；
  - 验证终端体验（FR-03/04/08/10/11）与性能指标（NFR-01/02）、健壮性（NFR-04）、安全（NFR-06）可测可验。
- 范围内（MECE）：
  - 单元层：board.py（落子/胜负/禁手/满盘/坐标解析）、ai.py（三档难度/封堵/禁手规避/时限）；
  - 集成层：main.py 回合循环（人类↔AI 切换、终局分支、重开）、CLI 参数装配；
  - 系统层：真实终端渲染、坐标输入、Ctrl+C/退出命令恢复、README 干净环境跑通；
  - 非功能：性能（AI 落子/刷新/启动耗时）、兼容（Python 版本/终端尺寸/无彩色/SSH）、健壮性（100 次随机输入）、安全（输入校验无越界、不联网不写系统目录）。
- 范围外（MECE，明确不测及理由）：
  - 不测联机/双人同屏/GUI/Web（需求明确不做，方案 §1 范围外）；
  - 不测 19×19 棋盘（方案明确不提供，Q3 排除）；
  - 不测悔棋/对局历史/胜负统计（方案按 Q6/Q7/Q8 建议默认不做）；
  - 不测威胁空间搜索/MCTS 竞赛级棋力（方案选型明确放弃，AI 定位娱乐级偏强 H5）；
  - 不写完整测试代码（本方案交付用例设计，代码由 test-developer 实现——角色边界）；
  - 不做性能基准的跨硬件对比（NFR-01 以参考硬件基线为界，低于基线环境仅记录实测值不判 FAIL）。

## 2. 测试策略（分层）
- 测试层级：
  - 单元测试（主）：tests/test_board.py、tests/test_ai.py（pytest）——覆盖胜负判定 4 方向/边界、禁手 3 类+对照表、坐标解析、AI 封堵/禁手规避/耗时断言。目标是逻辑内核 100% 关键路径覆盖，纯逻辑模块（board 零依赖、ai 仅依赖 board）无 I/O，最适合自动化；
  - 集成测试（中）：回合循环与 CLI 装配——用 monkeypatch 模拟 `ui.get_move` 输入序列驱动主循环（人类执黑时喂坐标、AI 执黑时允许自动），断言回合切换/终局横幅/重开路径；CLI 参数（size/difficulty/forbidden/human）装配正确性用 `python -m gomoku --help` 与非法参数用例验证；
  - 系统/验收测试（人工+脚本混合）：真实终端渲染、坐标输入体验、Ctrl+C 终端恢复、README 整局跑通——脚本可自动化的部分（渲染输出快照、stty 状态、退出码）自动化，体验类（视觉区分、提示清晰）走人工检查清单；
  - 回归测试：每轮修改后全量执行（pytest 全绿 + 人工清单复检），重点防禁手/胜负判定回归（红线用例固化）。
- 测试类型：
  - 功能：FR-01~FR-12 全量；
  - 边界：棋盘边线/角部五连、坐标 1/15 边界、13×13 坐标上限（M/13）、禁手形态边界（跳形缺口、同方向去重、单活四合法、单眠三合法）、满盘平局、AI 候选耗尽；
  - 异常：非法输入（乱码/越界/已占用/空串/超长）、Ctrl+C 各时刻中断、AI 超时降级链、终端过小；
  - 性能：NFR-01（AI 落子 P95 ≤2s）、NFR-02（刷新 ≤200ms、启动 ≤2s）；
  - 兼容性：Python 3.10/3.11/3.12、≥24×60 终端、无彩色降级（NO_COLOR/TERM=dumb 模拟）、SSH 会话（如环境可建）；
  - 安全：坐标输入 fuzz（随机乱码/超长/负号/Unicode）断言无越界访问、strace 级验证不联网不写系统目录（如工具可用，否则代码审查代替）。
- 通过标准：
  - 单元/集成层：pytest 全绿（断言精确到返回值/异常类型/提示文案），禁手对照表 ≥15 例逐例与判定结果一致；
  - 系统层：人工清单逐项打勾（渲染/输入/退出/重开），脚本检查项（退出码 0、stty 恢复、无残留输出）全过；
  - 性能层：NFR-01 采样 ≥20 次 P95 ≤2s（CI 环境宽限 0.5s，方案 §5.4）；NFR-02 刷新/启动各 ≥10 次均值达标；
  - 验收层：FR 验收标准逐条对应用例 PASS；任一 P0 用例 FAIL = 本阶段评审 FAIL。

## 4. 测试环境与数据
- 环境：
  - 主环境：Linux（本机，Ubuntu 内核 5.15+），Python 3.10+（以 3.10 为下限基准，另备 3.11/3.12 用于 C-E01）；
  - 依赖：rich（运行时）、pytest（测试）、coverage（覆盖率，可选）；`pip install -e .` 安装；
  - 终端：≥24×60 彩色终端（默认）、`TERM=dumb`/`NO_COLOR=1`（无彩色模拟）、<24×60（尺寸降级模拟）；
  - Docker（如可用）：python:3.10-slim 干净环境整局冒烟（与方案 §7 T7/M4 一致，对应 NFR-03 基线）；
  - 性能基线硬件：参考 README 声明的基线（x86-64 四核+/≥8GB RAM）；低于基线环境实测值仅记录不判 FAIL。
- 数据准备：
  - 禁手对照表：由开发侧交付（方案 §7 T3 承诺 ≥15 例，含 `_X_XX_`/`_XX_X_` 红线形态），测试侧逐例核对并转成 pytest 参数化用例（U-B12）；
  - AI 封堵棋局集：按 U-A02/U-A03 形态说明构造 ≥10 个不同棋局（方向/位置/形态各异），固化为 fixtures（棋盘快照 + 预期封堵点）；构造时用脚本生成辅助（摆子函数），人工复核每局确为"下一步成冲四/已有活三"形态（避免构造失真导致用例无效）；
  - 中盘性能局面：脚本随机对弈生成或手工摆出双方各 ≥20 子非终局局面 ≥3 个，落盘为 fixtures；
  - 满盘平局局面：固定 pattern 生成器构造，人工核对无五连；
  - 随机输入流：伪随机种子固定（如 seed=20260810）生成 100 次混合输入，保证可复现（R-R01）。

  - SSH 会话（C-E03）若本机无法建立 localhost SSH 则降级为 `TERM=dumb` 模拟 + 记录未测；
  - strace（R-S02）若无权限/未安装，以代码审查（grep 网络/写系统目录调用）替代并注明；
  - AI 耗时断言（U-A07）在 CI 慢环境宽限 0.5s（方案 §5.4 约定），本机参考基线环境按 2s 严格断言；
  - 渲染类断言以"输出快照 + 人工目视清单"结合（rich 输出含 ANSI，逐字符断言脆弱，快照留档 + 关键字符（●/○/坐标字母）断言）。

## 5. 自动化方案（如适用）
- 自动化范围与工具选型（有据）：
  - 单元/集成/性能核心：pytest（方案选型表已定，Python 测试事实标准）——纯逻辑模块（board/ai）全自动，无终端依赖，CI 可跑；
  - 渲染/输入/退出：混合策略——可脚本化部分（渲染输出快照断言、退出码、stty 状态、`TERM=dumb` 降级、非法输入重输循环）用 pytest + subprocess/pexpect 驱动真实进程自动化；纯体验部分（视觉区分、提示友好度）走人工检查清单（S-U02/S-U05/S-I01 的目视项）；
  - 随机健壮性（R-R01/R-S01）：pytest 参数化 + 固定种子，全自动；
  - 终端交互自动化工具：优先 pexpect（pty 模拟真实终端交互，覆盖输入循环/Ctrl+C 模拟）；不可用则 subprocess + 管道输入降级；
  - Docker 冒烟（S-D01 补充）：`docker run python:3.10-slim` 内 `pip install .` + 预置输入跑完一整局，断言退出码与输出关键标记。
- 执行方式（命令/触发时机）：
  - 单元+集成：`python -m pytest tests/ -x -q`（每轮修改后全量回归）；
  - 系统脚本化：`python -m pytest tests/ -m system`（标记 system 的进程级用例，含 pexpect 用例）；
  - 性能：`python -m pytest tests/test_ai.py::test_medium_ai_latency -m perf --count 20`（pytest-repeat 或循环采样）；
  - 全量验收：`python -m pytest && 人工检查清单（S-U02/S-U05 等目视项）`，对应里程碑 M1~M4 各阶段执行（见 §7 任务拆解）；
  - 触发时机：开发每完成一个里程碑即跑对应测试集；testplan 评审通过后 test-developer 按本方案实现用例，code 阶段结束后执行全量。
