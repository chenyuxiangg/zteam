# 测试方案：snake-linux（r1）

## 0. 元信息
- 需求：snake-linux/snake-linux｜依据方案：plans/snake-linux/snake-linux-r1.md｜轮次：r1
- 测试要点一句话：单元+PTY 集成+真实终端三层，覆盖玩法闭环、边界异常与终端卫生。

## 1. 测试目标与范围
- 目标：验证开发方案（curses 单文件、40×20 固定画布、模型/渲染/输入分层）实现的贪吃蛇满足需求分解文档全部验收标准——FR-01~FR-17（除已移出 FR 表的暂停功能）与 NFR-01~NFR-06；重点验证三条主线：
  1. **玩法闭环**：启动 → 移动/转向 → 吃食增长得分 → 撞墙/撞自身结束 → 结束画面（FR-05~FR-11、FR-16/17）；
  2. **配置与边界**：tick 50–1000ms 生效、非法参数报错、非 TTY/终端过小友好报错（FR-02/03/04）；
  3. **终端卫生**：q/Ctrl+C/SIGTERM 全部退出路径恢复终端原始状态、无残留（FR-13/14、NFR-03/04）。
- 范围内（做什么测试）：
  - 单元级：GameState 纯逻辑（移动/转向/反向禁止/吃食/碰撞/胜利/食物生成）、parse_args 参数校验、InputHandler 键位映射——模型层不依赖 curses，可脱离终端全量自动化；
  - 集成级：PTY 中驱动完整 `snake.py`，模拟真实按键序列验证端到端流程与退出卫生；
  - 系统级：真实终端（GNOME Terminal/Konsole/xterm/SSH）人工清单验收、README 走查、代码职责走查；
  - 性能级：输入延迟、CPU/内存占用、渲染流畅度。
- 范围外（不做什么测试）：
  - 不测暂停/继续（Q-04 默认不纳入，未实现）；
  - 不测分数持久化、速度随长度加快、多食物/道具、穿墙/环绕（Q-01/02/03、A-04 明确不做）；
  - 不测图形界面/联网/音效（需求范围外）；
  - 不测 Windows/macOS 平台（Q1 明确 Linux）；
  - 不写完整测试代码（本方案提供用例步骤与预期，测试代码由 test-developer 落地）。

## 2. 测试策略（分层）
- 测试层级：
  - **单元层（自动化，pytest）**：GameState/parse_args/InputHandler 三个纯逻辑模块。依据：开发方案 §2/§3.2 明确「游戏逻辑层刻意不依赖 curses」，这是脱离终端做确定性验证的天然挂载点。覆盖 FR-03/05/06/07/08/09/10/16 的逻辑面与全部边界分支（含尾部让行、pending 单槽连按）。
  - **集成层（自动化，pexpect 驱动 PTY）**：真实 TTY 下执行 `python3 snake.py`，注入按键序列、非 TTY 重定向、SIGINT/SIGTERM 信号，断言屏幕输出、退出码与终端状态。覆盖 FR-01/02/03/04/11/13/14/16/17。
  - **系统/验收层（半自动：脚本 + 人工清单）**：干净环境按 README 跑通、四种终端实测、README 四节齐全、代码职责分离走查、Python 多版本冒烟。覆盖 FR-01/15、NFR-04/05/06。
  - **回归层**：核心玩法冒烟集（8 个 P0 用例）在每次改动后执行，防止模型逻辑回归。
- 测试类型：
  - 功能：FR-05~FR-11 全流程；边界：FR-03/04 tick 与尺寸边界、FR-07 反向禁止、尾部让行；异常：FR-02 非 TTY、FR-13 信号退出、参数非法；性能：NFR-01/02；兼容性：NFR-06。
- 通过标准：
  - 单元层：pytest 全绿，无跳过；
  - 集成层：PTY 脚本全部断言通过，`termios.tcgetattr` 退出前后一致；
  - 系统层：人工清单逐项打勾，无「未验证」项遗留；
  - 回归层：P0 用例冒烟 100% 通过；
  - 任一 P0 用例失败 = 发布阻塞；P2 失败不阻塞（记录缺陷单）。

### 3.3 边界与异常用例汇总（已含于上表，此处归纳）
- 非法输入：tick 越界（49/1001/非数字/负数，TC-U-11）、尺寸非法（0/负数/过小 9×9，TC-U-12）→ 可读报错 + 非零退出码，无 traceback；
- 环境异常：非 TTY 管道/重定向（TC-I-02）、终端过小（TC-I-03）、运行中 resize（TC-I-11）；
- 信号与中断：Ctrl+C 三时机（TC-I-07）、SIGTERM（TC-I-08）；
- 逻辑边界：反向禁止直接/连按（TC-U-03/04）、尾部让行（TC-U-05）、撞墙贴边（TC-U-06）、撞自身（TC-U-07）、蛇占满判胜（TC-U-09/10）；
- 超时/重试/并发：不适用——本地单进程无网络 I/O（开发方案 §5.2 已声明），输入超时由 tick 机制覆盖，单线程无并发面；此判定写入测试记录备查。

## 4. 测试环境与数据
- 环境：
  - 主环境：Ubuntu 22.04/24.04（或 Debian 12）干净容器/虚拟机，仅预装系统 Python 3.x + 标准库（对齐 FR-01「干净 Linux 环境」定义，无第三方包、无游戏相关别名/环境变量）；
  - Python 版本矩阵：3.6 / 3.8 / 3.11 / 3.12（对齐 Q-05，3.6 为最低兼容验证）；
  - 终端矩阵：GNOME Terminal、Konsole、xterm、SSH 会话（对齐 Q-07 默认）；
  - 自动化依赖：pytest（单元）、pexpect（PTY 集成）——**仅测试侧依赖**，安装于测试环境，不影响交付物「运行时零第三方依赖」；
  - 性能测试固定机：单一终端、无负载波动，记录基线后测试。
- 数据准备：
  - 无外部测试数据；单元用例直接构造 GameState 并注入坐标/方向/食物（如蛇身 [(0,0),(1,0),(2,0)] 等）；
  - 集成用例由 pexpect 脚本发送按键序列（`w`/`a`/`s`/`d`、方向键转义序列、`q`）并以屏幕内容断言；
  - termios 校验用 `termios.tcgetattr` 前后对比脚本。
- 环境限制与假设：
  - 集成/系统用例必须在真实 TTY 或 PTY 中运行，无 TTY 的 CI 环境仅能跑单元层——假设测试执行机具备 PTY 能力；
  - 终端矩阵实机需 4 种终端可用，若环境受限则按 GNOME Terminal ≥ xterm ≥ SSH ≥ Konsole 的优先级缩减并在记录中标注；
  - 性能指标受终端渲染影响，P0 判定以功能用例为准，P1 性能用例在固定机复测。

## 5. 自动化方案（如适用）
- 自动化范围与工具选型（有据）：
  - **单元层 pytest**：GameState/parse_args/InputHandler 为纯逻辑模块（开发方案 §2 明确模型不依赖 curses），可全量确定性自动化，可在无 TTY CI 运行；
  - **集成层 pexpect**：真实分配 PTY 驱动 `snake.py`，比 mock curses 更接近真实终端行为，覆盖按键注入、SIGINT/SIGTERM、stty/termios 校验、屏幕断言；
  - **系统层**：验收走查脚本（bash）收集退出码/stderr/termios 快照 + 人工清单（终端矩阵、README、代码走查）；
  - 不选 pytest-cov 覆盖率门槛（第一版以需求覆盖为准），不引入 mock 框架（逻辑层无外部依赖可 mock）。
- 执行方式：
  - 单元：`pytest tests/ -v`（建议测试文件 tests/test_game_state.py、tests/test_config.py、tests/test_input.py）；
  - 集成：`bash tests/e2e_snake.sh`（内含 PTY 尺寸控制、按键注入、termios 对比、退出码断言）；
  - 性能：`bash tests/perf_snake.sh`（pidstat 采样 + 延迟计时）；
  - 触发时机：每次代码改动后跑单元 + 集成回归；发布前跑全量（含系统层人工清单）。

## 6. 风险与对策
| 风险 | 影响 | 对策 |
|------|------|------|
| curses 在无 TTY 环境不可用，CI 跑不了集成层 | 集成用例空转 | 单元层与集成层分离：单元层无 TTY 依赖；集成层显式标注 requires-tty，在执行机分配 PTY 运行 |
| pexpect 时序脆弱（固定 sleep 导致偶发失败） | 假失败/漏检 | 全部用 expect 屏幕内容轮询 + 超时重试，禁止固定 sleep 断言；每用例带 3 次重跑容错 |
| 性能指标受终端/负载波动 | P1 误判 | 固定测试机 + 记录基线；P0 判定不依赖性能用例 |
| 人工验收（终端矩阵/README/代码走查）漏项 | NFR-05/06 未验证 | 提供逐项清单文件（checklist），验收人逐项打勾留痕 |
| Python 3.6 语法兼容在单一环境测不出来 | Q-05 回归 | TC-S-06 覆盖 3.6/3.8/3.11/3.12 四版本冒烟 + py_compile |
| 需求方待确认项（Q-04 暂停/Q-06 多文件/Q-10 尺寸）拍板变更 | 用例返工 | 用例按方案默认值落地；暂停/多文件变更时仅新增对应用例，存量用例结构不受影响 |
