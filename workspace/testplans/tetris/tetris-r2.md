# 测试方案：tetris（r2）

## 0. 元信息
- 需求：tetris/tetris｜依据方案：plans/tetris/tetris-r2.md（终版）｜轮次：r2（修改轮，requeue 重跑）
- 测试要点一句话：单元（模型层纯逻辑）+PTY 集成+真实终端三层，覆盖 7 方块/消行计分/等级速度/旋转边界与终端卫生，验收口径随分析 r2 绝对值化（毫秒/P95）。

## 1. 测试目标与范围
- 目标：验证开发方案（curses 单文件 tetris.py、10×20 固定场地、模型/渲染/输入分层、简化旋转、纯随机、Guideline 计分 100/300/500/800、等级曲线每 10 行 1 级 tick×0.9 下限 100ms）实现的俄罗斯方块满足需求分解文档（analysis r2，approved 终版）全部验收标准——FR-01~FR-16、FR-18~FR-26 与 NFR-01~NFR-06（FR-17 按 Q-01 默认作废，不验收）；重点验证四条主线：
  1. **玩法闭环**：7 方块生成/下落/左右移/旋转/软硬降/锁定堆叠 → 整行消除与多行同消 → 计分 100/300/500/800 → 等级与速度联动 → 撞顶结束（FR-05~FR-16、FR-18）；
  2. **配置与边界**：--tick 50–2000ms 生效与越界报错、非 TTY/终端过小/运行中 resize 友好处理（FR-02/03/04）；
  3. **界面与交互**：next 预告准确、HUD 得分/等级/消行刷新、暂停相位补偿、结束画面（FR-19/21/22/24）；
  4. **终端卫生**：q/Ctrl+C/SIGTERM 全部退出路径恢复终端原始状态、无残留（FR-20/23、NFR-03/04）。
- 范围内（做什么测试）：
  - 单元级：模型层纯逻辑（方案 §2/§3.2 明确「游戏逻辑层刻意不依赖 curses」）——TETROMINOES 形状与 rotate_cw、collides/clear_lines、GameState 的 spawn/step/move/rotate/soft_drop/hard_drop/lock/计分/等级/撞顶/暂停状态机、parse_args（--tick/--no-color）——可脱离终端全量确定性自动化；
  - 集成级：pexpect 驱动真实 PTY 运行完整 `tetris.py`，注入按键序列（WASD/方向键/空格/P/q）、非 TTY 重定向、SIGINT/SIGTERM，断言屏幕内容、退出码与 termios 状态；
  - 系统级：干净环境按 README 跑通、四种终端实测（GNOME Terminal/Konsole/xterm/SSH）、README 五节走查、代码职责分离走查、Python 版本矩阵冒烟；
  - 性能级：输入延迟 ≤ 50ms P95（NFR-01，建议项）、CPU/内存占用（NFR-02，建议项）、渲染流畅度。
- 范围外（不做什么测试）：
  - 不测软降/硬降加分（FR-17，Q-01 默认「不加分」→ 作废，不验收）；
  - 不测 SRS 旋转系统/wall kick（Q-02 默认简化旋转：碰撞即拒绝、无踢墙，与分析 r2 FR-09 前置基线一致）；不测 7-bag 随机与 lock delay（Q-03 默认纯随机、无锁定延迟）；
  - 不测分数持久化/最高分、键位自定义、「再来一局」自动重开（Q-08/12/13 明确不做）；
  - 不测图形界面/联网/多人/音效（需求范围外）；不测 Windows/macOS（需求限定 Linux 终端）；
  - 不写完整测试代码（本方案提供用例步骤与预期，测试代码由 test-developer 落地）。

## 2. 测试策略（分层）
- 测试层级：
  - **单元层（自动化，pytest）**：TETROMINOES/rotate_cw/collides/clear_lines/GameState/parse_args 纯逻辑模块。依据：开发方案 §2 明确「模型层刻意不依赖 curses，保证 FR-05~FR-16 可脱离终端独立验证」——天然确定性挂载点。覆盖 FR-03/05~16/19/21/26 的逻辑面与全部边界分支（旋转碰撞拒绝、贴壁移动拒绝、多行同消、差一格不满、撞顶、负 y 坐标、O 方块旋转不变、纯随机 spawn 合法性）。方块形状断言基准采用方案 §4.2 占格坐标表（与 Tetris Wiki SRS spawn orientation 一致，r2 落定）。
  - **集成层（自动化，pexpect 驱动 PTY）**：真实 TTY 下执行 `python3 tetris.py`，注入按键序列、非 TTY 重定向、SIGINT/SIGTERM，断言屏幕输出、退出码与 termios 状态。覆盖 FR-01/02/03/04/05~24 的端到端面。
  - **系统/验收层（半自动：脚本 + 人工清单）**：干净环境按 README 跑通、四种终端实测、README 五节齐全、代码职责分离走查、Python 多版本冒烟。覆盖 FR-01/25、NFR-04/05/06。
  - **回归层**：核心玩法冒烟集（10 个 P0 用例）在每次代码改动后执行，防止模型逻辑回归（旋转/消行/计分为回归高发区）。
- 测试类型：
  - 功能：FR-05~FR-16 全流程（方块生命周期/消除计分/等级速度）、FR-18~FR-24 交互界面；边界：tick 与终端尺寸边界（FR-03/04）、旋转/移动碰撞拒绝（FR-08/09）、多行同消与差一格不满（FR-14）、撞顶（FR-13）；异常：非 TTY（FR-02）、信号退出（FR-20）、参数非法（FR-03）；性能：NFR-01/02（建议项，参考指标）；兼容性：NFR-06。
- 通过标准：
  - 单元层：pytest 全绿，无跳过；
  - 集成层：PTY 脚本全部断言通过，`termios.tcgetattr` 退出前后一致；
  - 系统层：人工清单逐项打勾，无「未验证」项遗留；
  - 回归层：P0 用例冒烟 100% 通过；
  - 性能层（建议项，非发布阻塞）：输入延迟与资源占用按绝对值口径记录（测量方法见 §4/§5，r1 实测已留痕）；
  - 任一 P0 用例失败 = 发布阻塞；P2 失败不阻塞（记录缺陷单）。

### 3.3 边界与异常用例汇总（已含于上表，此处归纳）
- 非法输入：tick 越界（49/2001/非数字/负数，TC-U-16）→ 可读报错 + 非零退出码，无 traceback；
- 环境异常：非 TTY 管道/重定向（TC-I-02）、终端过小（TC-I-03）、运行中 resize（TC-I-13）；
- 信号与中断：Ctrl+C 三时机（TC-I-08）、SIGTERM（TC-I-09）、q 键（TC-I-07）；
- 逻辑边界：旋转碰撞拒绝/贴壁拒绝（TC-U-06）、移动贴壁/贴堆叠拒绝（TC-U-05）、多行同消 1/2/4（TC-U-09）、差一格不满不消（TC-U-18）、撞顶判定（TC-U-12）、负 y/出界坐标不越界访问（TC-U-19）、O 方块旋转不变（TC-U-02）、计分多轮累计（TC-U-20）；
- 时间类边界（r2 绝对值化增量）：tick 偏差 ≤ max(50ms, tick×5%)（TC-I-04）、锁定→新方块 ≤100ms（TC-U-08）、HUD 刷新 ≤100ms（TC-I-10）、按键响应 ≤50ms P95（TC-I-06/TC-P-01）、硬降 <100ms（TC-U-07）、暂停不吞时间（TC-I-12）；
- 超时/重试/并发/资源耗尽：**不适用**——本地单进程、无网络 I/O、单线程无并发面、无外部资源可耗尽；输入超时由 curses timeout(25) 轮询机制天然覆盖（方案 §5.2 已声明）；此判定写入测试记录备查；
- FR-17（软硬降加分）作废理由：Q-01 默认「不加分」→ 需求分解文档明确「该 FR 作废（不验收）」，开发方案 §1 同样声明不实现，故映射用例数为 0，不测试。

## 4. 测试环境与数据
- 环境：
  - 主环境：Ubuntu 22.04/24.04（或 Debian 12）干净容器/虚拟机，仅预装系统 Python 3.x + 标准库（对齐 FR-01「干净 Linux 环境」定义，无第三方包、无游戏相关别名/环境变量）；
  - Python 版本矩阵：3.6 / 3.8 / 3.11 / 3.12（对齐 Q-05，3.6 为最低兼容验证）；
  - 终端矩阵：GNOME Terminal、Konsole、xterm、SSH 会话（对齐 Q-07 默认）；
  - 自动化依赖：pytest（单元）、pexpect + pyte（PTY 集成/性能）——**仅测试侧依赖**，安装于测试环境，不影响交付物「运行时零第三方依赖」；
  - 性能测试固定机：单一终端、无负载波动，记录基线后测试（r1 已留痕：avg_cpu=1.81%、peak_rss=17.7MB、输入延迟含轮询开销数据）。
- 数据准备：
  - 无外部测试数据；单元用例直接构造 GameState 并注入 board/piece_type/rotation/pos/next_type 等字段构造场景（如消行场景手工填满指定行、撞顶场景填满顶部、旋转阻挡场景在目标位置预置锁定格），**不依赖随机序列**，全部确定性可复现；
  - 集成用例由 pexpect 脚本发送按键序列（W/A/S/D、方向键转义序列、空格、P、q）并以屏幕内容断言；
  - termios 校验用 `termios.tcgetattr` 前后对比脚本；
  - 软降速度对比：集成层用 pexpect 快速连续发送 S/↓ 模拟「按住」（OS 键盘重复率不可控，以连发事件近似），与自动下落速度对比（FR-10 口径「明显快于自动下落」粗粒度检查，精确逐格行为由单元层 TC-U-13 覆盖——r2 明确此分工，见 §9 遗留 2）；
  - 输入延迟测量（TC-P-01，r2 明确口径）：`time.monotonic()` 在 send 前后计时 + pyte 屏幕轮询（**r2 起细粒度 ≤10ms**，r1 为 50ms 粒度）确认画面生效后取差值；开销（轮询粒度 + pexpect 调度）记录于测试结果，与真实延迟分离表述。
- 环境限制与假设：
  - 集成/系统用例必须在真实 TTY 或 PTY 中运行，无 TTY 的 CI 环境仅能跑单元层——假设测试执行机具备 PTY 能力；

## 5. 自动化方案（如适用）
- 自动化范围与工具选型（有据）：
  - **单元层 pytest**：TETROMINOES/rotate_cw/collides/clear_lines/GameState/parse_args 为纯逻辑模块（开发方案 §2 明确模型不依赖 curses），可全量确定性自动化，可在无 TTY CI 运行；
  - **集成层 pexpect + pyte**：真实分配 PTY 驱动 `tetris.py`，比 mock curses 更接近真实终端行为，覆盖按键注入、SIGINT/SIGTERM、termios 校验、屏幕断言；pyte 屏幕仿真同时用于 TC-P-01 输入延迟的「动作生效确认」（对齐 snake-linux 已验证模式，test r1 已落地）；
  - **系统层**：验收走查脚本（bash）收集退出码/stderr/termios 快照 + 人工清单（终端矩阵、README、代码走查）；
  - 不选 pytest-cov 覆盖率门槛（第一版以需求覆盖为准），不引入 mock 框架（逻辑层无外部依赖可 mock）。
- 执行方式：
  - 单元：`pytest tests/ -v`（建议测试文件 tests/test_tetrominoes.py、tests/test_game_state.py、tests/test_config.py、tests/test_input.py）；
  - 集成：`bash tests/e2e_tetris.sh`（内含 PTY 尺寸控制、按键注入、termios 对比、退出码断言）；
  - 性能：`bash tests/perf_tetris.sh`（pidstat 采样 + `time.monotonic()` 延迟计时 + pyte 细粒度轮询）；
  - 触发时机：每次代码改动后跑单元 + 集成回归；发布前跑全量（含系统层人工清单）。
