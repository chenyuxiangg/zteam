## 1. 方案概述
- 目标（可验证，对齐 FR/NFR 验收口径）：
  - 启动命令后 ≤3s 出现完整渲染画面，六类元素（墙/通道/豆/能量豆/玩家/幽灵）均可辨识（FR-01/FR-14）；
  - 完整对局闭环：吃豆得分、能量豆限时反击（连吃递增 200/400/800/1600）、清豆过关、撞幽灵扣命、命尽结算（FR-06~FR-09/FR-17）；
  - 地图可配置且合法性可离线判定（FR-03 验收三项）：① 全部豆子格可从玩家出生点沿合法通道到达（迷宫连通性检查，BFS）；② 幽灵出生区有 ≥1 条通道通往迷宫主体（不堵死）；③ 不同规格地图（内置 22×19 与任意 `--map` 自定义地图）下上述判定均成立，对局逻辑（寻路可达、豆子可吃完）可正常运转——由 map.py `validate_map()` 在加载期统一执行，违规报错退出，不进入游戏；
  - 4 只幽灵差异化 AI：Blinky 直线追击（含 Elroy 残豆加速）、Pinky 前方 4 格预判、Inky 向量翻倍协同、Clyde 距离感知（<8 格撤退）——目标格计算规则互不相同，**主验收标准为客观可验证**：target_cell 为纯函数、按幽灵类型分派，单元测试断言同一局面四者目标格互异（规则实现不同/目标不同均可验证），并支持 `--log-ai` 输出每 tick 目标格行为日志佐证；"对局中可观察区分"为辅助验收（FR-10，r2 口径）；
  - 幽灵三态（追逐/散开/脆弱）交替与可见信号（模式切换强制掉头、脆弱变蓝闪白）（FR-11/FR-07）；
  - 方向键/WASD 控制、输入缓冲（≤100ms 转向）、P 暂停、q/Ctrl+C 干净退出（终端状态完全恢复，10 次连测干净）（FR-04/FR-16）；
  - HUD 实时显示分数/命数/关卡/能量倒计时（FR-15）；
  - 交付 README（运行/依赖/键位/AI 策略/配置）与 requirements.txt（FR-18/FR-19），干净 Linux 环境按 README 可跑通（NFR-03/NFR-05）；
  - 渲染 ≥10 FPS、按键响应 ≤100ms（NFR-01）；终端 <80×24 明确提示不崩溃（NFR-04）；运行期零网络行为（NFR-06）。

## 2. 技术选型
| 技术栈/框架/中间件 | 用途 | 选择理由 | 替代方案对比 | 来源 |
|------|------|----------|--------------|------|
| Python 标准库 curses | 终端渲染 + 输入 + 终端状态管理 | ① 标准库内置模块，Linux（Ubuntu/Debian）CPython ≥3.8 预装，满足 NFR-05 依赖最少化（pip 依赖 0 条）；② `wrapper()` 自动保存/恢复终端原始状态（noecho/cbreak/光标/颜色），是 FR-16 干净退出（10 次连测干净）的现成保障；③ `keypad(True)` + `getch()` 直接返回 KEY_UP/DOWN/LEFT/RIGHT，免手工解析方向键多字节转义序列（FR-04）；④ `has_colors/init_pair` 支撑 6 类元素 4 幽灵分色（FR-14）与脆弱态蓝/闪白（FR-07/FR-11）；⑤ `timeout(n)` 非阻塞轮询输入，支撑主循环 10FPS（NFR-01）；⑥ terminfo 抽象终端差异，利于 NFR-03 兼容性；⑦ 本机实测 `import curses` 可用（CPython 3.11） | 裸 ANSI 转义序列：字节级可控但需自研 termios 原始模式、终端状态保存/恢复（信号安全）、ESC[ 方向键解析（含 ESC 键时序歧义）、SIGWINCH 处理——终端卫生全部自研，风险集中在 FR-16 雷区，无收益；**rich**（第三方）：Live 渲染 API 优雅，但引入 pip 依赖、输入需自行起线程处理非阻塞 stdin、整屏 diff 渲染性能开销；**prompt_toolkit**：输入能力强但对全屏游戏渲染（每帧 200+ 字符重绘）非其设计场景，依赖重。**与组内 snake-linux/tetris 已通过评审的方案一致**（curses + 纯逻辑层分离），pacman 按 AI/多实体特性补充论证 | Python 官方 curses HOWTO（wrapper/cbreak/noecho/keypad/timeout 语义）https://docs.python.org/3/howto/curses.html ；标准库参考 https://docs.python.org/3/library/curses.html |
| 纯 Python 逻辑层（无第三方） | 地图/AI/对局状态 | 地图 22×19 网格、AI 目标计算与路口决策均为轻量纯函数，Python 原生 list/tuple/enum 足够，无需 numpy 向量化（NFR-01 帧率瓶颈在渲染不在逻辑）；逻辑层不依赖 curses 可脱离终端单测（对齐 NFR-02 职责分离 + FR-10「单测验证目标规则不同」主验收口径） | numpy：对 418 格地图无性能收益，引入编译依赖，破坏 NFR-05 依赖最少化；自研 C 扩展/多线程：过度设计 | Python 标准库文档（enum/collections.deque/time.monotonic/random） |
| argparse（标准库） | `--map/--ghosts/--lives/--no-color/--speed/--level/--log-ai` 参数解析 | 标准库自带；类型校验内建；满足 FR-03「配置/命令行参数」与 FR-12 数量配置 | 手写 sys.argv：易错；配置文件（JSON/INI）：本需求 6 个标量参数，CLI 足够（FR-03 验收「修改配置后重启生效」由 `--map` 换文件满足）；若后续参数膨胀再叠加配置文件 | Python 标准库文档（argparse） |
| time.monotonic（标准库） | 主循环 tick 计时、暂停相位补偿、能量豆倒计时 | 单调时钟不受系统时间跳变影响，保证 NFR-01 帧率与 FR-15 倒计时精度 | time.time()：受系统时钟调整影响，倒计时可能跳变 | Python 标准库文档（time.monotonic） |
| random（标准库） | 脆弱态幽灵随机游走、出生方向 | 标准库自带；FR-11 脆弱态「随机游走」语义直接对应 | 确定性伪随机序列（seeded）：可复现但降低脆弱态「不可预测」体验；本方案默认随机，测试时可注入 seed | Python 标准库文档（random） |

- 选型结论：**渲染/输入/终端管理采用 curses（标准库），逻辑层（地图/AI/对局）用纯 Python 数据结构，不引入任何第三方 pip 依赖**。理由：需求「允许使用第三方库」是授权而非强制；curses 内置能力（终端卫生/方向键/颜色/非阻塞输入）与本需求每项硬性验收（FR-04/FR-14/FR-16/NFR-01/NFR-04）一一对应，且与组内 snake-linux/tetris 已验证的选型结论一致（复用组内惯例，评审风险低）；rich/prompt_toolkit 的额外能力（渐变/复杂输入）在本需求无验收对应项，却引入依赖与输入线程复杂度。放弃裸 ANSI：终端状态恢复/方向键解析/resize 全部自研，是 FR-16「干净退出」的雷区。
  **依赖声明（吸收旧评审建议 2，NFR-03/NFR-05 落实）**：依赖面 = 0 个 pip 包，requirements.txt 声明空列表；但 README「依赖安装」节必须显式注明两条路径，避免「完全零依赖」错觉：(1) 标准 Python 环境 → 零 pip 命令直接运行；(2) 极精简发行版若报 `ModuleNotFoundError: _curses` → Debian/Ubuntu 系执行 `apt install python3-curses`（系统包，非 pip）。两条路径均 ≤1 条命令，满足 NFR-05。

### 3.3 关键流程时序（主循环，tick = 100ms）
```
每 tick（time.monotonic 校准，暂停时相位补偿）:
  1. input.poll() → 玩家转向指令入缓冲队列（容量 1，新指令覆盖旧指令）
  2. player 移动：优先执行缓冲指令（目标方向合法则转向），随后沿当前方向走 1 格
  3. 幽灵决策（每只，非 FRIGHTENED 随机游走/EYES 直返鬼屋）：
     到路口（合法候选 ≥2 且含非反向）→ choose_dir() 更新方向 → 沿方向走 1 格（速度累积器）
     若 --log-ai：记录 幽灵名/模式/目标格/选择方向 → 行为日志（FR-10 客观验证）
  4. 碰撞判定（玩家格 vs 各幽灵格）：
     幽灵 FRIGHTENED → 吃幽灵（→EYES，得分 200/400/800/1600 序列）
     幽灵 CHASE/SCATTER → 扣命流程（命-1 → 全实体重置 → SCATTER 保护期）
  5. 吃豆判定：玩家所在格为 . / o → 得分；o 触发全部幽灵 → FRIGHTENED（重置计时）
  6. dots_left == 0 → 过关流程（level+1 → 地图重置/豆恢复/实体回位 → 难度参数更新）
  7. renderer.draw(game)（HUD + 地图 + 能量倒计时/脆弱闪烁）
```
扣命流程：命 > 0 → 玩家回 P、幽灵回鬼屋并按出场规则重置、模式计时器重置（首段 SCATTER）、2s 保护期（玩家闪烁，幽灵可穿过不判定）；命 == 0 → 结算画面（最终得分/到达关卡/吃幽灵数），按任意键或 q 退出。

### 4.2 数据结构/数据模型
```python
# map.py —— Tile 枚举（字符 → 语义）
Tile = Enum('Tile', 'WALL EMPTY DOT POWER DOOR HOUSE')   # 映射: # . o - H
# 出生点特殊格：P 玩家出生区（渲染为通道），B/PK/I/C 幽灵出生格（可选标记，默认在 HOUSE 内）
# 墙/门判定：WALL 不可通行（所有实体）；DOOR 仅幽灵可通行（玩家视为墙）；HOUSE 仅幽灵可通行

# entities.py
@dataclass
class Pos: row: int; col: int

class Mover:                 # 速度累积器（格/tick 支持浮点）
    pos: Pos; dir: Dir; speed: float; acc: float = 0.0
    def tick_move(self): self.acc += self.speed
                       if self.acc >= 1.0: self.acc -= 1.0; self.step()

class Ghost(Mover):
    kind: Kind            # BLINKY/PINKY/INKY/CLYDE
    mode: Mode            # CHASE/SCATTER/FRIGHTENED/EYES
    home_corner: Pos      # 散开目标角（Dossier: 各角落）
    dot_counter: int      # 鬼屋出场计数（Inky 30/Clyde 60，第 1 关）

# game.py
@dataclass
class GameState:

    dots_left: int; power_timer: float      # 能量豆剩余秒数
    mode_timer: float; mode_phase: int      # SCATTER/CHASE 交替进度
    eaten_chain: int                        # 本次能量豆连吃计数（重置 200/400/800/1600）
    player: Player; ghosts: list[Ghost]
    status: PLAYING | PAUSED | LEVEL_CLEAR | GAME_OVER
```

### 4.4 状态机
**幽灵模式状态机**（每只幽灵独立，mode_timer 驱动）：
```
SCATTER ──计时到──▶ CHASE ──计时到──▶ SCATTER ...（交替表见 §5.4）
   ▲                    │
   │  吃能量豆(全体)      │ 吃能量豆(全体)
   │                    ▼
   └──计时结束── FRIGHTENED(脆弱, 随机游走, 变蓝→闪白)
                    │ 被玩家撞到
                    ▼
                   EYES(眼睛, 2 倍速返鬼屋门 → 进门重生为 CHASE/SCATTER)
```
切换掉头规则（Dossier 实测）：chase→scatter / chase→frightened / scatter→chase / scatter→frightened 强制 180° 掉头（可见信号，FR-11）；frightened→chase/scatter、eyes 相关切换不掉头。
**对局状态机**：
```
PLAYING ──最后一颗豆──▶ LEVEL_CLEAR ──▶ PLAYING(level+1, 全重置)
   │撞可伤害幽灵(命>0)──▶ PLAYING(命-1, 全重置, 2s 保护)
   │撞可伤害幽灵(命=0)──▶ GAME_OVER(结算画面) ──任意键/q──▶ 退出
   │P ──▶ PAUSED ◀── P
```

## 5. 关键实现要点
### 5.1 核心算法：四幽灵目标计算（差异化核心，FR-10）
规则来源：Pac-Man Dossier（https://pacman.holenet.info/ 第四章，已抓取原文核对；分析文档 A4 同源）。
> **规格说明（吸收旧评审建议 1）**：以下为算法规格（What），非生产实现。code-developer 须按 TDD 先写单元测试再实现；测试用例必须覆盖 target_cell 与 choose_dir 的边界条件——四幽灵同一局面 target 互异断言（FR-10 主验收）、出界 clamp、曼哈顿平局优先级、无候选时掉头。target_cell 保持纯函数签名（入参 Ghost + game 状态，无副作用），保证可脱离终端单测。
```python
# ghost_ai.py —— 每 tick 各幽灵计算目标格（纯函数，可单测；FR-10 主验收点）
def target_cell(g: Ghost, game) -> Pos:
    pr, pc = game.player.pos; d = game.player.dir
    if g.kind == BLINKY:  return (pr, pc)                    # 直接追击
    if g.kind == PINKY:                                      # 前方 4 格（含原版向上 bug）
        off = offset4(pr, pc, d)                             # up 时额外左偏 4（Dossier 记载的原版溢出 bug，忠实复刻）
        return clamp(off)
    if g.kind == INKY:                                       # 向量翻倍协同（依赖 Blinky 位置）
        off = offset2(pr, pc, d)                             # 玩家前方 2 格（up 时同 bug 左偏 2）
        vec = (2 * off.r - blinky.pos.r, 2 * off.c - blinky.pos.c)
        return clamp(vec)                                    # 出界 clamp 到地图边界
    if g.kind == CLYDE:                                      # 距离感知
        if euclid(g.pos, player.pos) >= 8: return player.pos # ≥8 格追击
        return g.home_corner                                 # <8 格回角落撤退
```
路口决策（原版规则：候选 = 合法方向排除反向；选使到目标格**曼哈顿距离最小**的方向；平局按 UP>LEFT>DOWN>RIGHT 优先级；无候选时允许掉头）：
```python
def choose_dir(g, game) -> Dir:
    cands = [d for d in DIRS
             if passable(next_pos(g.pos, d))
             and d != REVERSE[g.dir]]
    if not cands: cands = [REVERSE[g.dir]]
    return min(cands, key=lambda d: (manhattan(next_pos(g.pos, d), g.target),
                                     -PRIORITY[d]))          # PRIORITY: UP>LEFT>DOWN>RIGHT
```
- **FR-10 验收映射**：主验收（客观）——四幽灵 target_cell 规则实现互不相同（按 kind 分派 4 个分支），单元测试断言同一局面（固定玩家位置/方向/Blinky 位置）下四者目标格互异；`--log-ai` 行为日志可复现同一局面输出差异（行为日志或单元测试任一满足即达主验收）。辅助验收——对局中四幽灵移动模式可观察区分（速度/目标/撤退行为不同），README AI 节说明各策略。
- Blinky Elroy（Dossier）：残豆 ≤ 阈值（第 1 关 20 颗，公式见 §5.4）→ 速度升至与玩家持平（1.0），且散开期也追玩家。
- 鬼屋出场（Dossier）：Pinky 立即出；Inky 吃 30 豆出、Clyde 吃 60 豆出（第 1 关；每关递减见 §5.4 公式）；Blinky 同屋出生（简化：不严格复刻 Blinky 屋外出生，见 §8 说明）。扣命/过关后重置出场计数。
### 5.2 核心算法：移动与速度模型（FR-04/FR-05，NFR-01）
- 逐格移动 + 速度累积器（§4.2 Mover）：speed 单位「格/tick」，浮点累积，tick=100ms 即 10 FPS 基准（NFR-01 下限恰为 10 FPS，tick 上限 100ms 达标；`--speed` 仅整体缩放）；
- 默认速度：玩家 1.0；幽灵 0.9（基础）；Elroy 1.0；FRIGHTENED 0.75；EYES 1.5；
- 玩家输入缓冲：deque 容量 1——`keydown` 时若目标方向合法立即转向，否则入队；每 tick 开始时若缓冲方向合法则执行（转向 ≤1 tick = ≤100ms，FR-04 验收达标）；连续快速输入新指令覆盖旧指令，不粘滞（FR-04）；
- 玩家被撞判定：幽灵进入玩家格时按幽灵模式判定（§3.3 第 4 步）；保护期（扣命后 2s）内玩家闪烁且不判定。
### 5.3 边界与异常处理
| 场景 | 处理 |
|------|------|
| 终端尺寸 <80×24（FR-14/NFR-04 验收口径） | 启动时 `curses.LINES/COLS` 检查，不足则居中显示「需要 ≥80×24 终端，当前 WxH」，等待按键后退出 exit 1（不崩溃不乱码） |
| 非 TTY 运行 | `sys.stdin.isatty()` 检查，报错退出 |
| Ctrl+C / q（FR-16） | `wrapper()` 统一恢复终端（endwin/光标/回显/颜色）；KeyboardInterrupt 在 wrapper 内捕获→显示「已退出」→正常返回；验收：连续 10 次退出干净 |
| 非法按键（NFR-04） | 忽略或提示（映射表外按键不产生动作，不中断） |
| 暂停相位（Q11） | `time.monotonic` 记录暂停起止，恢复时把暂停时长从计时器扣除（能量倒计时/模式计时不漂移） |
| 模式计时与扣命重置 | 扣命/过关后 mode_phase 归零（回到首段 SCATTER，Dossier：重置后从散开开始），保护玩家 |
| Pinky/Inky 目标出界（向上 bug 向量越界） | `clamp` 到地图边界内（§5.1），保证 target 永远合法 |
| EYES 寻路 | 复用 choose_dir，目标固定为鬼屋门（row10 col8~13 中点），速度 1.5；到门后进入鬼屋重生 |
| 连吃封顶 | eaten_chain ≥4 时固定 1600（不越界） |
| 地图文件非法/判定失败（FR-03） | validate_map() 三项离线判定 + 加载期校验统一报错（行列/原因定位），exit 1，不进入游戏 |
| `--log-ai` 输出失败（stderr 不可写等） | 降级静默（不影响对局），启动时提示一次 |
