## 1. 需求理解（SCQA）

### 1.1 情境（Situation）
用户已在终端游戏方向连续交付过多个项目（snake-linux、tetris、gomoku），偏好"可运行成品 + 完整文档"的交付标准（组内既有惯例）。经典街机吃豆人（Pac-Man，Namco 1980）是游戏史最具代表性的迷宫追逐游戏之一，其四幽灵差异化 AI 行为有完整公开资料（Pac-Man Dossier）可参照。用户在 Linux 终端环境下希望获得同类的、可本地运行的单机游戏体验。

### 1.2 冲突（Complication）
终端环境的表达力有限（无音效、无动画、字符渲染），市面终端版吃豆人多为低完成度项目（GitHub 检索可见同类项目 star 数普遍 ≤5，AI 多未做差异化）；而经典吃豆人的核心乐趣恰恰在于"四只幽灵性格不同"的追逐博弈。若只是"能跑起来的吃豆人"，体验与竞品无差异；要做"可玩性达标"的终端版，需要把差异化 AI、完整对局闭环、干净 UX 同时落地。

### 1.3 问题（Question）
如何交付一款 Linux 终端可玩、四幽灵差异化 AI、对局规则完整、且用户能按 README 一键跑通的吃豆人人机对战游戏？

### 1.4 结论（Answer）
本需求的核心价值：在终端环境下还原经典吃豆人的完整对局体验（吃豆得分、能量豆反击、四幽灵差异化 AI、过关扣命），并以"成品可玩 + 文档齐备"的标准交付，弥补终端吃豆人生态中"高品质差异化 AI 实现"的空白。

## 2. 需求范围（MECE 边界）

### 2.1 做什么
- 单人对战 AI 幽灵的终端吃豆人游戏（人机对战，非联机）
- 完整核心玩法：吃豆得分、能量豆限时反击、清豆过关、撞幽灵扣命/结束
- 4 只（或可配数量）差异化 AI 幽灵
- 终端实时渲染 + HUD（分数/命数/状态）+ 方向键/WASD 控制
- 干净退出（Ctrl+C 安全中断、恢复终端状态）
- README 交付（运行方式、依赖安装、键位、AI 策略、配置选项）
- 允许使用第三方库

### 2.2 不做什么
- 不做联机/双人对战（需求原文明确"不要求"）
- 不做图形界面（GUI）/浏览器版本（限定 Linux 终端）
- 不做移动端/跨平台适配（限定 Linux）
- 不做商业发布、美术素材、音效制作（终端字符渲染范畴；音效可行性与否见待确认 Q9）
- 不做在线排行榜/云存储（单机游戏，本地持久化与否见待确认 Q7）
- 不做 256 关级无限关卡设计（原版存在整数溢出 kill screen，属街机遗留缺陷，非本需求目标——难度递增见待确认 Q6）

### 组 B：玩家控制与核心玩法
| 编号 | 功能点 | 描述 | 优先级 | 验收标准 |
|------|--------|------|--------|----------|
| FR-04 | 方向控制 | 支持方向键或 WASD 控制玩家移动；支持输入排队（转向指令提前缓冲，到路口自动执行） | 高 | 按下方向键后玩家在 ≤100ms 内完成转向；连续快速输入不丢失、不粘滞 |
| FR-05 | 移动与碰撞边界 | 玩家仅沿通道移动，撞墙不穿墙；与"可伤害状态"的幽灵同格触发扣命 | 高 | 玩家无法进入墙格；与幽灵同格时按当前幽灵状态正确触发扣命或吃幽灵 |
| FR-06 | 吃豆得分 | 玩家经过豆子格自动吃豆，豆子从地图消失并加分（分值规则见假设 A2 / 待确认 Q4） | 高 | 吃豆后该格豆子消失、分数即时增加且 HUD 同步刷新 |
| FR-07 | 能量豆与反击 | 吃能量豆后幽灵进入限时脆弱状态（视觉可区分），此间撞到幽灵可将其吃掉（眼睛返回鬼屋重生）；限时结束恢复；连续吃多只幽灵得分递增 | 高 | 吃能量豆后幽灵状态/颜色变化可见；脆弱期内撞幽灵→幽灵被吃且回鬼屋重生；限时结束后幽灵恢复可伤害；连续吃第 2 只起得分高于第 1 只（如 200/400/800/1600，来源见 A2） |
| FR-08 | 过关判定 | 地图全部豆子（含能量豆）吃完即过关，进入下一关（地图重置，难度递增与否见待确认 Q6） | 高 | 最后一颗豆被吃后触发过关流程；新一关地图完整重置、豆子恢复、玩家与幽灵回到出生点 |
| FR-09 | 扣命与游戏结束 | 撞到可伤害状态的幽灵扣 1 条命；命数归零时游戏结束，显示结算（得分/到达关卡），随后可干净退出 | 高 | 扣命后玩家与幽灵重置至出生点、命数 -1 且 HUD 刷新；命数 0 时出现结算画面，退出后终端状态完好 |

### 组 C：幽灵 AI（本需求差异化核心）
| 编号 | 功能点 | 描述 | 优先级 | 验收标准 |
|------|--------|------|--------|----------|
| FR-10 | 四幽灵差异化 AI | 默认 4 只幽灵，行为特征各不相同，禁止 4 只同质：① 红色（Blinky 型）直线追击玩家且追击性强；② 粉色（Pinky 型）倾向预判玩家行进方向、绕前拦截；③ 青色（Inky 型）协同围堵——目标位置受红色幽灵与玩家相对位置共同影响，行为最难预测；④ 橙色（Clyde 型）距离感知——离玩家近时撤退/游走、远时追击（行为规格依据 Pac-Man Dossier，见 5.1 来源） | 高 | **主验收标准（客观可验证）**：四只幽灵的目标格（target tile）选择规则互不相同——可通过行为日志或单元测试验证各幽灵的目标计算逻辑存在可复现差异（如同一局面下四者计算出的目标格不同，或目标计算函数/规则实现彼此不同）；**辅助验收标准（主观观察）**：对局中 4 只幽灵的移动模式可被观察区分 |
| FR-11 | 幽灵模式切换 | 幽灵具备 追逐/散开/脆弱 三种状态：散开态（定时返回各自角落区域）与追逐态交替；吃能量豆进入脆弱态；模式切换伴随可见信号（原版为强制掉头，来源见 5.1） | 高 | 对局中可观察到散开/追逐交替（幽灵方向整体反转的可见信号）；脆弱态有独立视觉（颜色变化）；三种状态切换逻辑不冲突 |
| FR-12 | 幽灵数量可配置 | 支持配置幽灵数量（默认 4，允许减少） | 中 | 配置为 2/3/4 时游戏均可正常启动与对局，无报错、无死局 |
| FR-13 | 幽灵重置 | 过关或扣命后，所有幽灵回到出生位置（鬼屋及其周边） | 高 | 重置后 4 只幽灵均回到出生点附近；重置瞬间不与玩家重叠造成误判 |

### 5.3 差异化机会（结论先行）
1. **AI 差异化是本需求最核心的差异化机会**：GitHub 终端吃豆人生态检索显示同类项目 star 普遍 ≤5、多未实现差异化幽灵 AI；对齐原版四幽灵人格（追击/预判/协同/撤退）即可显著拉开与现有终端克隆的差距。
2. **"成品级交付标准"是第二机会点**：README 完整（安装/键位/AI/配置）、干净退出、健壮性处理（小终端提示等）——终端开源项目普遍缺失，而这是用户一贯的交付标准（组内惯例）。
3. **组内协同价值**：与 snake-linux/tetris/gomoku 构成终端游戏合集，渲染/输入/配置基建可复用（内部效率，非外部竞争）。
4. **风险点**：终端表达力天花板（无音效/动画/色彩深度）无法与网页/街机版比体验，受众限于终端用户；且"终端吃豆人"本身生态冷清，说明需求小众——本需求定位为自用/学习/作品集向，而非面向大众的商业产品。

## 6. 依赖与假设

**外部依赖**：
- 运行环境：Linux 终端（需支持 ANSI 颜色与 Unicode 字符显示，现代主流终端均满足）
- 运行时：Python（版本要求见待确认 Q8）
- 第三方库：允许使用（numpy / curses / prompt_toolkit / rich 等为需求原文列举方向，**具体选型属实现方案（How），交由下游方案设计阶段决定**）；无外部网络服务、无数据接口依赖

**假设**（原文未明确、按公开资料/常理假定，均注明来源；与原文冲突处已进待确认）：
