# 测试方案：pacman（r1）

## 0. 元信息
- 需求：pacman/pacman｜依据方案：workspace/pacman/plans/pacman-r1.md（plan 阶段终版）｜轮次：r1
- 测试要点一句话：以四幽灵差异化 AI（target_cell 客观验证）与对局闭环（吃豆/反击/过关/扣命）为 P0 主线，叠加终端卫生（干净退出/小终端）与安全（零网络）验证，全部 FR/NFR 可追溯。

## 1. 测试目标与范围
- 目标：验证开发方案（plans/pacman-r1.md）实现的游戏满足需求分解文档（analysis/pacman-r2.md）全部 FR-01~FR-19 与 NFR-01~NFR-07 的验收标准，其中 FR-10 以客观手段（target 规则互异单测 + --log-ai 行为日志）为主验收，FR-03 以三项离线判定为验收；为 test-developer 编写测试代码与 test-reviewer 评审提供可直接照做的用例清单。
- 范围内（MECE）：
  - 单元测试：map.py 校验与查询、ghost_ai.py 目标计算/路口决策/模式状态机、entities.py 速度累积器、game.py 对局状态机与计分、input.py 键位缓冲（逻辑层不依赖 curses，可脱离终端执行）；
  - 集成测试：逻辑层组合（Game + 多幽灵 + 地图）全对局推演——吃豆、能量豆反击链、过关、扣命、保护期、连吃封顶；
  - 系统/验收测试：终端内实际游玩——渲染可辨识、HUD 刷新、方向控制、暂停、退出干净（10 次连测）、结算画面、<80×24 提示；
  - 性能测试：帧率 ≥10 FPS、按键响应 ≤100ms、5 分钟连续对局无卡顿；
  - 兼容性测试：Ubuntu/Debian 干净环境按 README 跑通；无 256 色终端降级；
  - 安全测试：运行期零网络连接（strace/防火墙验证）、无用户数据读写、终端状态恢复；
  - 文档一致性：README 五节与实现行为一致（FR-18/NFR-07）。
- 范围外（明确不测）：
  - 不测 GUI/浏览器/移动端（需求明确限定 Linux 终端）；
  - 不测联机/双人对战（需求明确不要求）；
  - 不测 28×31 原版比例内置地图（方案 Q1 处置默认 22×19）；但 `--map` 加载 28×31 自定义文件的判定流程在 T-MAP-05 覆盖；
  - 不测原版街机 256 关 kill screen 与 Elroy 全表数值（方案 §8 N2 简化公式已声明，按方案口径验证公式实现正确即可）；
  - 不做最高分持久化测试（方案 Q7 默认不做）；
  - 不测音效（方案 Q9 默认不做）；
  - 不写完整测试代码（仅用例步骤/伪代码，属 test-developer 职责）；
  - 不改开发方案、不评审（越界行为，禁止）。

## 2. 测试策略（分层）
- 测试层级：
  - 单元（逻辑层，脱离终端）：map/ghost_ai/entities/game/input 各模块纯函数与状态机。重点：validate_map() 三项离线判定、target_cell() 四分支、choose_dir() 决策、Mover 速度累积、Game 状态迁移、计分序列。PASS 定义：全部断言通过，覆盖 FR-10 主验收（同一局面四幽灵 target 互异）、FR-03 三项判定、计分/碰撞/过关/扣命规则；
  - 集成（逻辑层组合）：真实 Game 实例 + 4 幽灵 + 内置地图跑完整对局场景（吃能量豆→连吃 4 幽灵→清豆过关→扣命→命尽结算），验证模块间协作与状态一致性。PASS 定义：推演结果与规则表逐项一致（计分 200/400/800/1600、命-1、level+1、dot 清零触发）；
  - 系统（终端真实游玩，手动 + pexpect 脚本驱动）：渲染/HUD/控制/暂停/退出/结算。PASS 定义：六类元素可辨识、4 幽灵分色、HUD 实时刷新（≤1s）、Ctrl+C/q 退出后终端状态完好（连续 10 次）、<80×24 提示友好；
  - 回归：修改轮（r2+）重跑全量单元/集成 + 关键系统用例（T-EXIT-01/T-RENDER-01/T-GAME-08 等），验证评审意见修复未引入新缺陷；
  - 验收：按 §3 需求映射表逐条执行 FR/NFR 验收标准，全部 P0 通过、P1 无未决阻塞项方可达标。
- 测试类型：功能（对局闭环）、边界（非法地图/非法参数/终端过小/连吃封顶/能量时长下限）、异常（非 TTY、Ctrl+C 中途、stderr 不可写）、性能（帧率/响应/长跑）、兼容（终端类型/无 256 色）、安全（零网络/无数据读写）。
- 通过标准：
  - 单元/集成：用例全部 PASS，P0 缺陷数为 0；
  - 系统/验收：P0 全部通过且无复现；P1 缺陷须有明确修复计划（不阻塞发布需评审确认）；P2 不阻塞发布；
  - 终端卫生：T-EXIT-01 连续 10 次 Ctrl+C/q 退出后 stty 状态/光标/颜色均恢复，0 残留；
  - 安全：运行期 socket 系统调用计数 = 0（NFR-06）。

## 4. 测试环境与数据
- 环境：
  - OS：Ubuntu/Debian 系（主测 Ubuntu 22.04/24.04 或等位容器；NFR-03 需干净容器/VM 验证 README 从零跑通）；
  - 运行时：Python ≥3.8（本机 CPython 3.11 实测 import curses 可用）；终端 ≥80×24，TERM 支持 ANSI 颜色（xterm-256color 主测 + linux 降级测）；
  - 依赖：零第三方 pip 包；极简发行版路径需 `apt install python3-curses`（README 两路径验证）；
  - 工具：strace（网络行为）、script/tmux（TTY 会话）、pexpect（自动化终端交互）、pytest/unittest（单元/集成）。
- 数据准备：
  - 内置地图 data/map_classic.txt（22×19，216 豆）为默认被测对象；
  - 构造测试用地图：合规格 28×31 文件（T-MAP-05）、6 种非法地图（T-MAP-04：行宽不一致/非法字符/豆不足/无 P/鬼屋无门/孤立豆）、不存在路径文件（T-MAP-06）——由测试脚本按 map.py 文档化格式生成；
  - 固定局面注入：target_cell/choose_dir 单测直接以构造的 GameState 调用纯函数（无需终端）；对局推演用注入计时器（monotonic 可注入假时钟）控制能量豆倒计时/模式切换/保护期，实现 T-GAME-05/13、T-GAME-17、T-GAME-18 等计时类用例。
- 环境限制与假设：
  - 帧率/响应测量依赖宿主性能，PASS 口径为方案目标值（10FPS/100ms），采样取多次均值；
  - 零网络验证以 strace 系统调用计数为准（防火墙日志为辅助证据），需 root 或 ptrace 权限；无权限时降级为代码审查（import 清单无 socket/urllib/requests）+ ss 观察；
  - 终端视觉类用例（T-RENDER-01/T-FR11-02）依赖人工目视或截图比对，由 test-developer 提供截图留证；
  - 假设方案 §5.4 难度公式与 §5.2 速度常量按表实现（实现偏差属缺陷，由用例暴露）。

## 5. 自动化方案（如适用）
- 自动化范围与工具选型（有据）：
  - 单元/集成（逻辑层，可全自动）：pytest 或 unittest——方案 §3.1 依赖方向保证 game/map/entities/ghost_ai 不 import curses，纯逻辑层可在无终端 CI 环境执行（FR-10 主验收 T-AI-01、FR-03 T-MAP-01~04 均在此层，自动化必要性最高）；
  - 系统/终端交互（半自动）：pexpect 驱动 TTY 会话模拟按键（方向键/P/q/Ctrl+C），覆盖 T-CTRL-02、T-EXIT-01/02/06、T-UI-01 的脚本化部分；终端恢复验证用退出前后 `stty -a` 快照 diff + 光标位置检查脚本化断言；
  - 性能：主循环 tick 间隔采样脚本（monotonic 打点）自动化统计帧率（T-NFR-01-01）；按键响应用 pexpect send 与画面变化时间戳差（T-NFR-01-02）；
  - 安全：strace -e trace=network 包装启动命令，解析系统调用计数（T-NFR-06-01）脚本化；
  - 视觉类（T-RENDER-01/T-FR11-01/02）：tmux + 终端截图 + 人工/图像比对，半自动留证。
- 执行方式与触发时机：
  - 单元/集成：code 阶段每次提交后由 test-developer 本地执行（TDD 伴随，方案 §5.1 规格说明要求 code-developer 先写测试再实现）；回归轮（testplan r2+）全量重跑；
  - 系统/性能/安全：集成完成后、release 前回归跑一轮；
  - 验收：release 门禁前按 §3.1 映射表逐条执行，输出 PASS/FAIL 清单留档。
