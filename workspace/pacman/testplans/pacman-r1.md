## 1. 测试目标与范围
- 目标：验证开发方案（plans/pacman-r1.md）实现的游戏满足需求分解文档（analysis/pacman-r4.md）全部 FR-01~FR-19 与 NFR-01~NFR-07 的验收标准，其中 FR-10 以客观手段（target 规则互异单测 + --log-ai 行为日志）为主验收，FR-03 以三项离线判定为验收；为 test-developer 编写测试代码与 test-reviewer 评审提供可直接照做的用例清单。
- 范围内（MECE）：
  - 单元测试：map.py 校验与查询、ghost_ai.py 目标计算/路口决策/模式状态机、entities.py 速度累积器、game.py 对局状态机与计分、input.py 键位缓冲（逻辑层不依赖 curses，可脱离终端执行）；
  - 集成测试：逻辑层组合（Game + 多幽灵 + 地图）全对局推演——吃豆、能量豆反击链、过关、扣命、保护期、连吃封顶；
  - 系统/验收测试：终端内实际游玩——渲染可辨识、HUD 刷新、方向控制、暂停、退出干净（10 次连测）、结算画面、<80×24 提示；
  - 性能测试：帧率 ≥10 FPS、按键响应 ≤100ms、5 分钟连续对局无卡顿；
  - 兼容性测试：Ubuntu/Debian 干净环境按 README 跑通；无 256 色终端降级；
  - 安全测试：运行期零网络连接（strace/防火墙验证）、无用户数据读写、终端状态恢复；
  - 文档一致性：README 五节与实现行为一致（FR-18/NFR-07）。
- 范围外（明确不测）：
  - 不测 GUI/浏览器/移动端（需求明确限定 Linux 终端）；
  - 不测联机/双人对战（需求明确不要求）；
  - 不测 28×31 原版比例内置地图（方案 Q1 处置默认 22×19——28×31 高 31 行超出 FR-14「≥80×24 完整显示」口径，冲突处置见方案 §8）；但 `--map` 加载 28×31 自定义文件的判定流程在 U-04 覆盖；
  - 不测原版街机 256 关 kill screen 与 Elroy 全表数值（方案 §8 N2 简化公式已声明，按方案口径验证公式实现正确即可）；
  - 不做最高分持久化测试（方案 Q7 默认不做）；
  - 不测音效（方案 Q9 默认不做）；
  - 不写完整测试代码（仅用例步骤/伪代码，属 test-developer 职责）；
  - 不改开发方案、不评审（越界行为，禁止）。

## 2. 测试策略（分层）
- 测试层级：
  - 单元（逻辑层，脱离终端）：map/ghost_ai/entities/game/input 各模块纯函数与状态机。重点：validate_map() 三项离线判定、target_cell() 四分支、choose_dir() 决策、Mover 速度累积、Game 状态迁移、计分序列。PASS 定义：全部断言通过，覆盖 FR-10 主验收（同一局面四幽灵 target 互异）、FR-03 三项判定、计分/碰撞/过关/扣命规则；
  - 集成（逻辑层组合）：真实 Game 实例 + 4 幽灵 + 内置地图跑完整对局场景（吃能量豆→连吃 4 幽灵→清豆过关→扣命→命尽结算），验证模块间协作与状态一致性。PASS 定义：推演结果与规则表逐项一致（计分 200/400/800/1600、命-1、level+1、dot 清零触发）；
  - 系统/验收（PTY 终端）：真实终端内启动/渲染/控制/暂停/退出/结算/小终端提示。PASS 定义：E2E 驱动脚本断言全绿 + 手动观察项清单逐项复核；
  - 回归/验收：每轮 code 阶段交付后全量回归（单测 + E2E + 勾稽报告），门禁 P0 用例任一 FAIL 即整轮 FAIL。
- 测试类型：
  - 功能：全部 FR 逐条（映射表 §3.1）；
  - 边界：非法 CLI 参数、非法地图 5 类、小终端/非 TTY、目标出界 clamp、计时下限、连吃封顶、暂停相位补偿（§3.3）；
  - 异常：Ctrl+C/q 10 次连测、非法按键、--map 缺失、--log-ai stderr 不可写降级；
  - 性能：帧率 ≥10 FPS、按键响应 ≤100ms、5 分钟无卡顿（N-01/N-02）；
  - 兼容性：Ubuntu/Debian 干净环境、无 256 色终端降级、TERM 矩阵（N-03）；
  - 安全：零网络（N-04）。
- 通过标准：
  - 单元/集成：`python3 -m unittest discover -s tests` 全绿，P0 用例为门禁（任一 FAIL 即整轮 FAIL）；
  - 系统：E2E 驱动脚本断言全绿 + 手动观察项清单逐项复核；
  - 性能：帧率均值 ≥10 FPS（60s 采样）、按键响应 ≤100ms、5 分钟对局无卡顿（NFR-01 下限口径）；
  - 安全：strace 60s 运行期零 socket 系统调用（NFR-06）；
  - 验收：需求映射表全项勾稽完成，无"未覆盖且无理由"项。

### 3.3 边界与异常用例汇总（含并发/资源耗尽语义）
- 非法输入：非法 CLI 参数（U-50 exit 2）、非法按键（E-03）、非法地图五类（E-05/U-04）、非 TTY（E-02）；
- 超时/时限：启动 ≤3s（S-01）、能量豆时长下限 1.0s（E-08）、SCATTER 下限 1s（E-08）、倒计时相位补偿（U-46/E-11）；
- 重试/连测：10 次 Ctrl+C（E-10）、10 次 q 退出（S-11）、暂停 10 次切换（E-11）；
- 并发/同 tick 多事件：碰撞判定先于吃豆判定（U-47）、连吃多幽灵链（E-07）、多幽灵同 tick 同格碰撞（U-47 扩展：按幽灵列表顺序判定）；
- 资源耗尽/越界：连吃封顶 1600（E-07）、目标出界 clamp（U-12/E-06）、速度上限 0.98 与阈值下限（E-09）、level 极大公式不越界（U-44）；
- 环境异常：终端 <80×24（E-01）、非 TTY（E-02）、--map 文件缺失（E-04）、stderr 不可写时 --log-ai 降级静默（U-15 扩展：关闭 stderr 断言不中断对局）。

- 环境限制与假设：curses 全屏程序自动化断言以字符形状 + 状态日志为主，颜色/闪烁以人工观察清单兜底；性能测试受终端与负载影响，阈值取 NFR 下限（10 FPS/100ms）；随机性通过 seed 注入消除不确定性。

## 5. 自动化方案（如适用）
- 自动化范围与工具选型（有据）：
  - 逻辑层单测：**unittest（标准库，零第三方依赖）**——与 plan §2 选型结论一致（生产零 pip 依赖），避免测试引入 pytest 污染依赖面；P0/P1 用例全自动化（U 系列 22 条 + E 系列逻辑类）；
  - 系统 E2E：**标准库 pty + subprocess 驱动**（tests/e2e_driver.py）——curses 必须运行于真实终端，pty.fork 模拟 PTY 注入按键/采集输出；断言基于字符 dump + --log-ai 日志 + stty 状态；
  - 性能/安全：主循环 monotonic 打点（测试钩子或 --log-ai 时间戳）；strace 抓网络系统调用（N-04）；
  - 手动观察项（P2 视觉类）：S-02/S-06 颜色、S-09 掉头信号、S-13 辅助观察——沉淀为手动验收清单（tests/manual_checklist.md）。
- 执行方式（命令/触发时机，与 plan §7 里程碑对齐）：
  - M1 对齐（plan T1~T4 完成）：`python3 -m unittest discover -s tests -v` 全绿（U 系列 + validate_map 样本集）；
  - M2 对齐（plan T5~T7 完成）：`python3 tests/e2e_driver.py --smoke`（启动/控制/退出断言）；
  - M3 对齐（plan T8~T9 完成）：全量回归 `python3 -m unittest discover -s tests && python3 tests/e2e_driver.py --full` + 手动清单复核 + FR/NFR 勾稽报告（tests/report_template.md）；
  - 触发时机：本地每次阶段交付前必跑；CI 可接入（无依赖，任一 Ubuntu runner 直接可跑）。

## 6. 风险与对策
| 风险 | 影响 | 对策 |
|------|------|------|
| curses 颜色/闪烁断言脆弱（终端差异） | S-02/S-06 自动化不可靠 | 自动化只断言字符形状/状态日志；颜色走人工清单（§5）；--no-color 模式字符断言兜底 |
| 10 次干净退出连测耗时且易误判 | E-10/S-11 执行成本高 | 脚本循环 + 每次断言 stty 回显与进程退出码，异常才人工介入 |
| FR-10 辅助验收主观（"可观察区分"） | 评审争议 | 主验收以 U-10 互异断言为门禁（客观），--log-ai 日志为佐证（U-15），辅助观察仅 P2 |
| 性能测试受终端/负载波动 | N-01/N-02 假阳性/假阴性 | 阈值取 NFR 下限 + 60s 均值 + 连续卡顿帧单独断言；--speed 1.0 标准档位 |
| 随机游走不可复现 | U-15/S-13 难稳定 | random seed 注入（§4），--log-ai 记录每 tick 决策可回放 |
| E2E 驱动与游戏进程竞态（tick 100ms） | 按键注入错过窗口 | 按键注入与 tick 对齐（固定间隔 120ms）+ 断言轮询带超时（≤5s） |
| 逻辑层测试钩子缺失（纯函数签名若被破坏） | U 系列无法挂载 | 提前约定测试入口：target_cell/choose_dir/validate_map 为纯函数（方案 §5.1 规格说明已约定 TDD），test-developer 实现时保持签名 |
| 高关卡（--level 20）公式边界未被实现覆盖 | E-08/E-09 失败 | 属方案 §5.4 显式公式，U-44 单元层先验证，E-08/E-09 端到端复核 |
| 映射表计数与用例表漂移（评审建议 1/2 同类问题复发） | 可追溯性缺陷 | 本版已按"计数=全量关联、关键用例=主推"口径全表复核；TT5 勾稽报告按用例 ID 反查计数，test-developer 增删用例时必须同步映射表 |
