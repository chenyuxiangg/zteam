## 0. 元信息
- 需求：pacman/pacman｜依据方案：workspace/pacman/plans/pacman-r1.md（plan 终版）｜轮次：r1（2026-08-10 16:20 人工 requeue 重置 stages 后，testplan 阶段重新计数的第 1 轮）
- 测试要点一句话：逻辑层（地图/四幽灵 AI/对局状态机）纯单测 + 系统层伪终端全流程，逐条覆盖 19 FR + 7 NFR 验收口径。

## 1. 测试目标与范围
- 目标（与验收标准对应）：
  - 验证 19 项 FR 全部可测、可过：启动渲染（FR-01）、地图（FR-02/03）、控制与玩法闭环（FR-04~09）、四幽灵差异化 AI 主验收（FR-10，客观断言 target 互异）、模式切换（FR-11）、配置（FR-12/13）、渲染/HUD/退出/结算（FR-14~17）、交付物（FR-18/19）；
  - 验证 7 项 NFR：性能（NFR-01 帧率≥10FPS/响应≤100ms/5 分钟不卡顿）、模块分离（NFR-02）、干净环境可跑（NFR-03）、健壮性（NFR-04）、依赖清晰（NFR-05）、零网络（NFR-06）、文档一致（NFR-07）；
  - 为 test-developer 提供可直接照做的用例（前置/步骤/预期均已具体到命令与断言口径）。
- 范围内（MECE）：
  - 逻辑层单元测试：map.py（加载/校验/validate_map 三项离线判定/查询）、entities.py（速度累积器/玩家/幽灵）、ghost_ai.py（四幽灵 target_cell/choose_dir/模式状态机/出场规则）、game.py（计分/碰撞/过关/扣命/难度公式）、config.py（默认值/CLI 覆盖/非法值）；
  - 集成测试：对局闭环场景（吃豆/能量豆反击/过关/扣命/结束/EYES 重生/--log-ai 差异复现）；
  - 系统测试：真实终端启动渲染、HUD 刷新、方向控制、暂停、干净退出（10 连测）、结算、各 CLI 参数组合、--map 多规格与非法地图；
  - 边界与异常：<80×24、非 TTY、非法按键、地图非法/不连通/鬼屋堵死、暂停相位、保护期、连吃封顶、--log-ai 降级；
  - 性能/兼容/安全：FPS 采样、按键响应、5 分钟稳定性、干净环境跑通、模块分离核查、零网络验证、依赖声明核查。
- 范围外：
  - 不写测试代码（用例步骤/伪代码级，完整实现属 test-developer）；
  - 不改开发方案、不评审（方案已 PASS，发现缺陷写入 §8 待确认）；
  - 不做非需求项测试：联机/双人、GUI/浏览器版、音效、移动端、在线排行榜（需求明确不做，无测试价值）；
  - 不做最高分持久化测试（Q7 默认不做，方案 §8 明确 r1 范围收敛）；
  - 不做 28×31 原版比例内置地图测试（Q1 默认 22×19；28×31 仅作为 --map 自定义地图的"多规格判定③"验证样本之一，不要求内置）。

## 2. 测试策略（分层）
- 测试层级与侧重：
  | 层级 | 对象 | 侧重 | 执行方式 |
  |------|------|------|---------|
  | 单元 | map/entities/ghost_ai/game/config（纯逻辑，不依赖 curses） | 规则正确性：validate_map 三项判定、target_cell 四分支、choose_dir 决策、计分/状态机/公式 | 逻辑层可脱离终端直接运行（方案 NFR-02 依赖方向保证），unittest 全量 |
  | 集成 | Game 状态机 + 多模块协作 | 闭环场景：吃豆→能量豆→过关→扣命→结算；EYES 回屋重生；--log-ai 输出差异 | 直接构造 GameState 驱动若干 tick 断言终态；--log-ai 用固定局面注入 seed 复现 |
  | 系统 | 完整程序（curses 渲染 + 输入 + 主循环） | 验收口径：≤3s 渲染、六元素可辨识、HUD ≤1s 刷新、转向 ≤100ms、10 连测干净退出、各 CLI 参数 | 伪终端（util-linux script 或 pexpect）驱动真实进程，截图/文本断言 |
  | 验收 | 全链路 | FR/NFR 逐条映射核对（§3 需求映射表），P0 全绿 + P1 不阻塞 | 每阶段产物与 README 对照 + 手工走查清单 |
  | 回归 | 修改轮 | 方案变更后全量重跑 P0/P1，确保无回归 | test-developer 每次修改后执行 |
- 测试类型：功能（核心）、边界（非法输入/尺寸/资源）、异常（崩溃/降级路径）、性能（FPS/响应/长时）、兼容性（干净环境/极简发行版缺 _curses 路径）、安全（零网络行为）。
- 通过标准：
  - 单元层：P0/P1 用例 100% 通过，P2 不阻塞；
  - 集成层：闭环场景全通过（I-01~I-09 全绿）；
  - 系统层：P0 全过；P1 通过率 ≥95%（失败须有明确根因记录）；P2 允许挂起并登记；
  - 验收层：§3 需求映射表中每个 FR/NFR 至少 1 个用例通过（或明确"不可测/不测"及理由，本方案无此情况）；
  - 性能：FPS 采样最小 ≥10、响应 ≤100ms、5 分钟无持续下滑；安全：strace 网络调用为 0。

## 4. 测试环境与数据
- 环境：
  - OS：Ubuntu/Debian 系（开发机 + 干净验证容器各一）；Python ≥3.8（实测 3.11，含 curses 标准库）；
  - 终端：≥80×24 标准终端（GNOME Terminal/konsole/xterm 任选）；<80×24 用例用 `stty cols 60 rows 15` 或 tmux resize 构造；
  - 非 TTY 用例：`python3 -m pacman < /dev/null` 或 CI 无 PTY 上下文；
  - 网络观察：strace（`strace -e trace=network -f`）或 `ss -tnp`；运行期应零连接；
  - 自动化：Python unittest（标准库）+ 伪终端（util-linux `script` 命令提供 PTY；如需更强交互断言可加 pexpect——仅测试环境依赖，不进运行时 requirements.txt，见 §5）；
  - 干净环境验证：Docker 容器（ubuntu:latest + python3 最小安装）或全新用户目录。

  - 内置地图：data/map_classic.txt（22×19，216 豆）；

  - seed 注入：--log-ai 复现用例（I-08）要求 code-developer 支持测试 seed（方案 §2 random 条目"测试时可注入 seed"已约定）；
  - 一键验收脚本：`python3 tests/run_all.py` 汇总各层结果（可选，见 §5）。
- 环境限制与假设：
  - 终端渲染断言以"字符/颜色序列可观测"为准（伪终端文本捕获 + 人工走查清单兜底），不依赖截图 OCR；

  - 干净环境容器无 GUI，S 系列渲染用例在开发机真终端执行；容器只跑 C-01 启动冒烟。

## 5. 自动化方案（如适用）
- 自动化范围与工具选型（有据）：
  | 层 | 工具 | 理由 |
  |----|------|------|
  | 单元/集成 | Python unittest（标准库） | 逻辑层纯函数/状态机天然可单测；零额外依赖，与方案"0 pip 依赖"交付口径一致；TDD 要求（方案 §5.1）同源 |
  | 系统层 | util-linux `script` 伪终端 + 文本断言；交互断言不足时补 pexpect | script 命令系统自带零依赖；pexpect 仅测试环境安装（`pip install pexpect` 放 test-requirements.txt，不污染运行时 requirements.txt），用于按键注入/退出干净度自动化 |
  | 性能 | 内置计时脚本（time.monotonic 采样 tick 间隔） | 直接对接主循环，无侵入 |
  | 安全 | strace -e trace=network | 系统级网络行为观测，客观 |
  | 回归 | tests/run_all.py 汇总脚本 | 单命令全量回归（unittest discover + 系统用例脚本），供 test-developer 每次修改后执行 |
- 执行方式：
  - 逻辑层：`python3 -m unittest discover tests/unit -v`（U/I 系列）；
  - 系统层：`python3 tests/system/run_system.py`（script/pexpect 驱动，S/E/P 系列；需真终端）；
  - 全量回归：`python3 tests/run_all.py`；
  - 触发时机：test-developer 每轮实现后全量执行；修改轮对变更模块定向重跑 + 全量回归。
