# 需求：Linux 终端版吃豆人游戏（人机对战，Python，可使用第三方库）

**投放时间**：2026-08-09
**来源**：Telegram 用户直接投放

## 需求描述

开发一个运行于 **Linux 终端**的吃豆人（Pac-Man）游戏（人机对战），使用 Python 实现。**允许使用第三方库**（与 snake-linux/tetris "从零不依赖框架" 的约束不同；与 gomoku 允许第三方库的约束一致）。

## 期望要点（供分析师展开）

- **对弈模式**：单人对战 AI 控制的幽灵（人机对战），不要求联机双人对战
- **AI 能力**：4 只（或可配）幽灵，每只采用不同追逐/逃跑策略（如 Blinky 直线追击、Pinky 预判拦截、Inky 协同围堵、Clyde 随机/撤退）；具体算法由分析师细化建议（BFS/A*、状态机、行为切换）
- **地图/迷宫**：标准吃豆人迷宫（22×19 或类似规格，可缩放），由分析师给出建议（硬编码 / 从字符串加载 / 自动生成）
- **核心玩法**：玩家吃豆子得分、吃能量豆后幽灵可被反击（限时）、全部豆子吃完过关、撞到幽灵扣命/结束
- **可选第三方库方向**（供分析师参考，不强制）：`numpy`（地图高效表示）、`curses` 或 `prompt_toolkit`/`rich`（终端渲染）、AI 算法无标准库选型——分析师自由选择
- **UX**：终端渲染迷宫（区分墙/通道/豆子/能量豆/玩家/幽灵）+ 实时分数/剩余命/状态（普通/能量暴走）；玩家方向控制（方向键或 WASD）
- **退出干净**：恢复终端原始状态，Ctrl+C 安全中断
- **交付 README**：运行方式、依赖安装（pip）、键位说明、AI 策略说明、配置选项

## 验收标准（待评审确认）

- Linux 终端可玩，渲染清晰、方向控制流畅
- 4 只幽灵采用差异化 AI（不能 4 只全一样）
- 胜负/过关/吃能量豆反击判定正确
- 代码职责分离、README 可让用户在干净 Linux 环境跑通

## 1. 需求理解（SCQA）

### 1.1 情境（Situation）
用户已在终端游戏方向连续交付过多个项目（snake-linux、tetris、gomoku），偏好"可运行成品 + 完整文档"的交付标准（组内既有惯例）。经典街机吃豆人（Pac-Man，Namco 1980）是游戏史最具代表性的迷宫追逐游戏之一，其四幽灵差异化 AI 行为有完整公开资料（Pac-Man Dossier）可参照。用户在 Linux 终端环境下希望获得同类的、可本地运行的单机游戏体验。

### 1.2 冲突（Complication）
终端环境的表达力有限（无音效、无动画、字符渲染），市面终端版吃豆人多为低完成度项目（GitHub 检索可见同类项目 star 数普遍 ≤5，AI 多未做差异化）；而经典吃豆人的核心乐趣恰恰在于"四只幽灵性格不同"的追逐博弈。若只是"能跑起来的吃豆人"，体验与竞品无差异；要做"可玩性达标"的终端版，需要把差异化 AI、完整对局闭环、干净 UX 同时落地。

### 1.3 问题（Question）
如何交付一款 Linux 终端可玩、四幽灵差异化 AI、对局规则完整、且用户能按 README 一键跑通的吃豆人人机对战游戏？

### 1.4 结论（Answer）
本需求的核心价值：在终端环境下还原经典吃豆人的完整对局体验（吃豆得分、能量豆反击、四幽灵差异化 AI、过关扣命），并以"成品可玩 + 文档齐备"的标准交付，弥补终端吃豆人生态中"高品质差异化 AI 实现"的空白。

## 2. 需求范围（MECE 边界）

### 2.1 做什么
- 单人对战 AI 幽灵的终端吃豆人游戏（人机对战，非联机）
- 完整核心玩法：吃豆得分、能量豆限时反击、清豆过关、撞幽灵扣命/结束
- 4 只（或可配数量）差异化 AI 幽灵
- 终端实时渲染 + HUD（分数/命数/状态）+ 方向键/WASD 控制
- 干净退出（Ctrl+C 安全中断、恢复终端状态）
- README 交付（运行方式、依赖安装、键位、AI 策略、配置选项）
- 允许使用第三方库

### 2.2 不做什么
- 不做联机/双人对战（需求原文明确"不要求"）
- 不做图形界面（GUI）/浏览器版本（限定 Linux 终端）
- 不做移动端/跨平台适配（限定 Linux）
- 不做商业发布、美术素材、音效制作（终端字符渲染范畴；音效可行性与否见待确认 Q9）
- 不做在线排行榜/云存储（单机游戏，本地持久化与否见待确认 Q7）
- 不做 256 关级无限关卡设计（原版存在整数溢出 kill screen，属街机遗留缺陷，非本需求目标——难度递增见待确认 Q6）

### 5.3 差异化机会（结论先行）
1. **AI 差异化是本需求最核心的差异化机会**：GitHub 终端吃豆人生态检索显示同类项目 star 普遍 ≤5、多未实现差异化幽灵 AI；对齐原版四幽灵人格（追击/预判/协同/撤退）即可显著拉开与现有终端克隆的差距。
2. **"成品级交付标准"是第二机会点**：README 完整（安装/键位/AI/配置）、干净退出、健壮性处理（小终端提示等）——终端开源项目普遍缺失，而这是用户一贯的交付标准（组内惯例）。
3. **组内协同价值**：与 snake-linux/tetris/gomoku 构成终端游戏合集，渲染/输入/配置基建可复用（内部效率，非外部竞争）。
4. **风险点**：终端表达力天花板（无音效/动画/色彩深度）无法与网页/街机版比体验，受众限于终端用户；且"终端吃豆人"本身生态冷清，说明需求小众——本需求定位为自用/学习/作品集向，而非面向大众的商业产品。

## 1. 方案概述
- 目标（可验证，对齐 FR/NFR 验收口径）：
  - 启动命令后 ≤3s 出现完整渲染画面，六类元素（墙/通道/豆/能量豆/玩家/幽灵）均可辨识（FR-01/FR-14）；

  - 地图可配置且合法性可离线判定（FR-03 验收三项）：① 全部豆子格可从玩家出生点沿合法通道到达（迷宫连通性检查，BFS）；② 幽灵出生区有 ≥1 条通道通往迷宫主体（不堵死）；③ 不同规格地图（内置 22×19 与任意 `--map` 自定义地图）下上述判定均成立，对局逻辑（寻路可达、豆子可吃完）可正常运转——由 map.py `validate_map()` 在加载期统一执行，违规报错退出，不进入游戏；
  - 4 只幽灵差异化 AI：Blinky 直线追击（含 Elroy 残豆加速）、Pinky 前方 4 格预判、Inky 向量翻倍协同、Clyde 距离感知（<8 格撤退）——目标格计算规则互不相同，**主验收标准为客观可验证**：target_cell 为纯函数、按幽灵类型分派，单元测试断言同一局面四者目标格互异（规则实现不同/目标不同均可验证），并支持 `--log-ai` 输出每 tick 目标格行为日志佐证；"对局中可观察区分"为辅助验收（FR-10，r5 口径）；
  - 幽灵三态（追逐/散开/脆弱）交替与可见信号（模式切换强制掉头、脆弱变蓝闪白）（FR-11/FR-07）；
  - 方向键/WASD 控制、输入缓冲（≤100ms 转向）、P 暂停、q/Ctrl+C 干净退出（终端状态完全恢复，10 次连测干净）（FR-04/FR-16）；
  - HUD 实时显示分数/命数/关卡/能量倒计时（FR-15）；
  - 交付 README（运行/依赖/键位/AI 策略/配置）与 requirements.txt（FR-18/FR-19），干净 Linux 环境按 README 可跑通（NFR-03/NFR-05）；
  - 渲染 ≥10 FPS、按键响应 ≤100ms（NFR-01）；终端 <80×24 明确提示不崩溃（NFR-04）；运行期零网络行为（NFR-06）。

## 2. 技术选型
| 技术栈/框架/中间件 | 用途 | 选择理由 | 替代方案对比 | 来源 |
|------|------|----------|--------------|------|
| Python 标准库 curses | 终端渲染 + 输入 + 终端状态管理 | ① 标准库内置模块，Linux（Ubuntu/Debian）CPython ≥3.8 预装，满足 NFR-05 依赖最少化（pip 依赖 0 条）；② `wrapper()` 自动保存/恢复终端原始状态（noecho/cbreak/光标/颜色），是 FR-16 干净退出（10 次连测干净）的现成保障；③ `keypad(True)` + `getch()` 直接返回 KEY_UP/DOWN/LEFT/RIGHT，免手工解析方向键多字节转义序列（FR-04）；④ `has_colors/init_pair` 支撑 6 类元素 4 幽灵分色（FR-14）与脆弱态蓝/闪白（FR-07/FR-11）；⑤ `timeout(n)` 非阻塞轮询输入，支撑主循环 10FPS（NFR-01）；⑥ terminfo 抽象终端差异，利于 NFR-03 兼容性；⑦ 本机实测 `import curses` 可用（CPython 3.11） | 裸 ANSI 转义序列：字节级可控但需自研 termios 原始模式、终端状态保存/恢复（信号安全）、ESC[ 方向键解析（含 ESC 键时序歧义）、SIGWINCH 处理——终端卫生全部自研，风险集中在 FR-16 雷区，无收益；**rich**（第三方）：Live 渲染 API 优雅，但引入 pip 依赖、输入需自行起线程处理非阻塞 stdin、整屏 diff 渲染性能开销；**prompt_toolkit**：输入能力强但对全屏游戏渲染（每帧 200+ 字符重绘）非其设计场景，依赖重。**与组内 snake-linux/tetris 已通过评审的方案一致**（curses + 纯逻辑层分离），pacman 按 AI/多实体特性补充论证 | Python 官方 curses HOWTO（wrapper/cbreak/noecho/keypad/timeout 语义）https://docs.python.org/3/howto/curses.html ；标准库参考 https://docs.python.org/3/library/curses.html （本方案产出时点实测可达 HTTP 200） |
| 纯 Python 逻辑层（无第三方） | 地图/AI/对局状态 | 地图 22×19 网格、AI 目标计算与路口决策均为轻量纯函数，Python 原生 list/tuple/enum 足够，无需 numpy 向量化（NFR-01 帧率瓶颈在渲染不在逻辑）；逻辑层不依赖 curses 可脱离终端单测（对齐 NFR-02 职责分离 + FR-10「单测验证目标规则不同」主验收口径） | numpy：对 418 格地图无性能收益，引入编译依赖，破坏 NFR-05 依赖最少化；自研 C 扩展/多线程：过度设计 | Python 标准库文档（enum/collections.deque/time.monotonic/random） |
| argparse（标准库） | `--map/--ghosts/--lives/--no-color/--speed/--level/--log-ai` 参数解析 | 标准库自带；类型校验内建；满足 FR-03「配置/命令行参数」与 FR-12 数量配置 | 手写 sys.argv：易错；配置文件（JSON/INI）：本需求 6 个标量参数，CLI 足够（FR-03 验收「修改配置后重启生效」由 `--map` 换文件满足）；若后续参数膨胀再叠加配置文件 | Python 标准库文档（argparse） |
| time.monotonic（标准库） | 主循环 tick 计时、暂停相位补偿、能量豆倒计时 | 单调时钟不受系统时间跳变影响，保证 NFR-01 帧率与 FR-15 倒计时精度 | time.time()：受系统时钟调整影响，倒计时可能跳变 | Python 标准库文档（time.monotonic） |
| random（标准库） | 脆弱态幽灵随机游走、出生方向 | 标准库自带；FR-11 脆弱态「随机游走」语义直接对应 | 确定性伪随机序列（seeded）：可复现但降低脆弱态「不可预测」体验；本方案默认随机，测试时可注入 seed | Python 标准库文档（random） |

- 选型结论：**渲染/输入/终端管理采用 curses（标准库），逻辑层（地图/AI/对局）用纯 Python 数据结构，不引入任何第三方 pip 依赖**。理由：需求「允许使用第三方库」是授权而非强制；curses 内置能力（终端卫生/方向键/颜色/非阻塞输入）与本需求每项硬性验收（FR-04/FR-14/FR-16/NFR-01/NFR-04）一一对应，且与组内 snake-linux/tetris 已验证的选型结论一致（复用组内惯例，评审风险低）；rich/prompt_toolkit 的额外能力（渐变/复杂输入）在本需求无验收对应项，却引入依赖与输入线程复杂度。放弃裸 ANSI：终端状态恢复/方向键解析/resize 全部自研，是 FR-16「干净退出」的雷区。
  **依赖声明（吸收旧评审建议 2 延续，NFR-03/NFR-05 落实）**：依赖面 = 0 个 pip 包，requirements.txt 声明空列表；但 README「依赖安装」节必须显式注明两条路径，避免「完全零依赖」错觉：(1) 标准 Python 环境 → 零 pip 命令直接运行；(2) 极精简发行版若报 `ModuleNotFoundError: _curses` → Debian/Ubuntu 系执行 `apt install python3-curses`（系统包，非 pip）。两条路径均 ≤1 条命令，满足 NFR-05。

### 3.3 关键流程时序（主循环，tick = 100ms）
```
每 tick（time.monotonic 校准，暂停时相位补偿）:
  1. input.poll() → 玩家转向指令入缓冲队列（容量 1，新指令覆盖旧指令）
  2. player 移动：优先执行缓冲指令（目标方向合法则转向），随后沿当前方向走 1 格
  3. 幽灵决策（每只，非 FRIGHTENED 随机游走/EYES 直返鬼屋）:
     到路口（合法候选 ≥2 且含非反向）→ choose_dir() 更新方向 → 沿方向走 1 格（速度累积器）
     若 --log-ai：记录 幽灵名/模式/目标格/选择方向 → 行为日志（FR-10 客观验证）
  4. 碰撞判定（玩家格 vs 各幽灵格）:
     幽灵 FRIGHTENED → 吃幽灵（→EYES，得分 200/400/800/1600 序列）
     幽灵 CHASE/SCATTER → 扣命流程（命-1 → 全实体重置 → SCATTER 保护期）
  5. 吃豆判定：玩家所在格为 . / o → 得分；o 触发全部幽灵 → FRIGHTENED（重置计时）
  6. dots_left == 0 → 过关流程（level+1 → 地图重置/豆恢复/实体回位 → 难度参数更新）
  7. renderer.draw(game)（HUD + 地图 + 能量倒计时/脆弱闪烁）
```
扣命流程：命 > 0 → 玩家回 P、幽灵回鬼屋并按出场规则重置、模式计时器重置（首段 SCATTER）、2s 保护期（玩家闪烁，幽灵可穿过不判定）；命 == 0 → 结算画面（最终得分/到达关卡/吃幽灵数），按任意键或 q 退出。

### 4.2 数据结构/数据模型
```python
# map.py —— Tile 枚举（字符 → 语义）
Tile = Enum('Tile', 'WALL EMPTY DOT POWER DOOR HOUSE')   # 映射: # . o - H
# 出生点特殊格：P 玩家出生区（渲染为通道），B/PK/I/C 幽灵出生格（可选标记，默认在 HOUSE 内）
# 墙/门判定：WALL 不可通行（所有实体）；DOOR 仅幽灵可通行（玩家视为墙）；HOUSE 仅幽灵可通行

# entities.py
@dataclass
class Pos: row: int; col: int

class Mover:                 # 速度累积器（格/tick 支持浮点）
    pos: Pos; dir: Dir; speed: float; acc: float = 0.0
    def tick_move(self): self.acc += self.speed
                       if self.acc >= 1.0: self.acc -= 1.0; self.step()

class Ghost(Mover):
    kind: Kind            # BLINKY/PINKY/INKY/CLYDE
    mode: Mode            # CHASE/SCATTER/FRIGHTENED/EYES
    home_corner: Pos      # 散开目标角（Dossier: 各角落）
    dot_counter: int      # 鬼屋出场计数（Inky 30/Clyde 60，第 1 关）

# game.py
@dataclass
class GameState:
    level: int; lives: int; score: int
    dots_left: int; power_timer: float      # 能量豆剩余秒数
    mode_timer: float; mode_phase: int      # SCATTER/CHASE 交替进度
    eaten_chain: int                        # 本次能量豆连吃计数（重置 200/400/800/1600）
    player: Player; ghosts: list[Ghost]
    status: PLAYING | PAUSED | LEVEL_CLEAR | GAME_OVER
```

### 4.4 状态机
**幽灵模式状态机**（每只幽灵独立，mode_timer 驱动）：
```
SCATTER ──计时到──▶ CHASE ──计时到──▶ SCATTER ...（交替表见 §5.4）
   ▲                    │
   │  吃能量豆(全体)      │ 吃能量豆(全体)
   │                    ▼
   └──计时结束── FRIGHTENED(脆弱, 随机游走, 变蓝→闪白)
                    │ 被玩家撞到
                    ▼
                   EYES(眼睛, 2 倍速返鬼屋门 → 进门重生为 CHASE/SCATTER)
```
切换掉头规则（Dossier 实测）：chase→scatter / chase→frightened / scatter→chase / scatter→frightened 强制 180° 掉头（可见信号，FR-11）；frightened→chase/scatter、eyes 相关切换不掉头。
**对局状态机**：
```
PLAYING ──最后一颗豆──▶ LEVEL_CLEAR ──▶ PLAYING(level+1, 全重置)
   │撞可伤害幽灵(命>0)──▶ PLAYING(命-1, 全重置, 2s 保护)
   │撞可伤害幽灵(命=0)──▶ GAME_OVER(结算画面) ──任意键/q──▶ 退出
   │P ──▶ PAUSED ◀── P
```

## 5. 关键实现要点
### 5.1 核心算法：四幽灵目标计算（差异化核心，FR-10）
规则来源：Pac-Man Dossier（https://pacman.holenet.info/ 第四章，本方案产出时点实测可达 HTTP 200；分析文档 A4 同源）。
> **规格说明（延续旧评审建议 1 的落实）**：以下为算法规格（What），非生产实现。code-developer 须按 TDD 先写单元测试再实现；测试用例必须覆盖 target_cell 与 choose_dir 的边界条件——四幽灵同一局面 target 互异断言（FR-10 主验收）、出界 clamp、曼哈顿平局优先级、无候选时掉头。target_cell 保持纯函数签名（入参 Ghost + game 状态，无副作用），保证可脱离终端单测。
```python
# ghost_ai.py —— 每 tick 各幽灵计算目标格（纯函数，可单测；FR-10 主验收点）
def target_cell(g: Ghost, game) -> Pos:
    pr, pc = game.player.pos; d = game.player.dir
    if g.kind == BLINKY:  return (pr, pc)                    # 直接追击
    if g.kind == PINKY:                                      # 前方 4 格（含原版向上 bug）
        off = offset4(pr, pc, d)                             # up 时额外左偏 4（Dossier 记载的原版溢出 bug，忠实复刻）
        return clamp(off)
    if g.kind == INKY:                                       # 向量翻倍协同（依赖 Blinky 位置）
        off = offset2(pr, pc, d)                             # 玩家前方 2 格（up 时同 bug 左偏 2）
        vec = (2 * off.r - blinky.pos.r, 2 * off.c - blinky.pos.c)
        return clamp(vec)                                    # 出界 clamp 到地图边界
    if g.kind == CLYDE:                                      # 距离感知
        if euclid(g.pos, player.pos) >= 8: return player.pos # ≥8 格追击
        return g.home_corner                                 # <8 格回角落撤退
```
路口决策（原版规则：候选 = 合法方向排除反向；选使到目标格**曼哈顿距离最小**的方向；平局按 UP>LEFT>DOWN>RIGHT 优先级；无候选时允许掉头）：
```python
def choose_dir(g, game) -> Dir:
    cands = [d for d in DIRS
             if passable(next_pos(g.pos, d))
             and d != REVERSE[g.dir]]
    if not cands: cands = [REVERSE[g.dir]]
    return min(cands, key=lambda d: (manhattan(next_pos(g.pos, d), g.target),
                                     -PRIORITY[d]))          # PRIORITY: UP>LEFT>DOWN>RIGHT
```
- **FR-10 验收映射**：主验收（客观）——四幽灵 target_cell 规则实现互不相同（按 kind 分派 4 个分支），单元测试断言同一局面（固定玩家位置/方向/Blinky 位置）下四者目标格互异；`--log-ai` 行为日志可复现同一局面输出差异（行为日志或单元测试任一满足即达主验收）。辅助验收——对局中四幽灵移动模式可观察区分（速度/目标/撤退行为不同），README AI 节说明各策略。
- Blinky Elroy（Dossier）：残豆 ≤ 阈值（第 1 关 20 颗，公式见 §5.4）→ 速度升至与玩家持平（1.0），且散开期也追玩家。
- 鬼屋出场（Dossier）：Pinky 立即出；Inky 吃 30 豆出、Clyde 吃 60 豆出（第 1 关；每关递减见 §5.4 公式）；Blinky 同屋出生（简化：不严格复刻 Blinky 屋外出生，见 §8 N3 与 §7 T8 README 注明）。
### 5.2 核心算法：移动与速度模型（FR-04/FR-05，NFR-01）
- 逐格移动 + 速度累积器（§4.2 Mover）：speed 单位「格/tick」，浮点累积，tick=100ms 即 10 FPS 基准（NFR-01 下限恰为 10 FPS，tick 上限 100ms 达标；`--speed` 仅整体缩放）；
- 默认速度：玩家 1.0；幽灵 0.9（基础）；Elroy 1.0；FRIGHTENED 0.75；EYES 1.5；
- 玩家输入缓冲：deque 容量 1——`keydown` 时若目标方向合法立即转向，否则入队；每 tick 开始时若缓冲方向合法则执行（转向 ≤1 tick = ≤100ms，FR-04 验收达标）；连续快速输入新指令覆盖旧指令，不粘滞（FR-04）；
- 玩家被撞判定：幽灵进入玩家格时按幽灵模式判定（§3.3 第 4 步）；保护期（扣命后 2s）内玩家闪烁且不判定。

  - 网络观察：strace（`strace -e trace=network -f`）或 `ss -tnp`；运行期应零连接；
  - 自动化：Python unittest（标准库）+ 伪终端（util-linux `script` 命令提供 PTY；如需更强交互断言可加 pexpect——仅测试环境依赖，不进运行时 requirements.txt，见 §5）；

## 5. 自动化方案（如适用）
- 自动化范围与工具选型（有据）：
  | 层 | 工具 | 理由 |
  |----|------|------|
  | 单元/集成 | Python unittest（标准库） | 逻辑层纯函数/状态机天然可单测；零额外依赖，与方案"0 pip 依赖"交付口径一致；TDD 要求（方案 §5.1）同源 |
  | 系统层 | util-linux `script` 伪终端 + 文本断言；交互断言不足时补 pexpect | script 命令系统自带零依赖；pexpect 仅测试环境安装（`pip install pexpect` 放 test-requirements.txt，不污染运行时 requirements.txt），用于按键注入/退出干净度自动化 |
  | 性能 | 内置计时脚本（time.monotonic 采样 tick 间隔） | 直接对接主循环，无侵入 |
  | 安全 | strace -e trace=network | 系统级网络行为观测，客观 |
  | 回归 | tests/run_all.py 汇总脚本 | 单命令全量回归（unittest discover + 系统用例脚本），供 test-developer 每次修改后执行 |

## 4. AI 策略说明（四幽灵差异化）

> 来源：Pac-Man Dossier（https://pacman.holenet.info/）

| 幽灵 | 颜色 | 目标格（target cell）规则 |
|------|------|--------------------------|
| **Blinky**（红色） | 红 | 直线追击玩家当前位置；残豆 ≤ 阈值时进入 **Elroy**（速度追平玩家） |
| **Pinky**（粉色） | 品红 | 玩家前方 4 格（含原版向上 bug：UP 时额外左偏 4） |
| **Inky**（青色） | 青 | 向量翻倍协同：以"玩家前方 2 格 + 向 Blinky 翻倍"为目标 |
| **Clyde**（橙色） | 黄 | 距离感知：距玩家 ≥ 8 格追击；< 8 格撤回家角落 |

**模式切换**：追逐（CHASE）/散开（SCATTER）按时间表交替（首段 SCATTER 7s / CHASE 20s，随关卡递减）；切换瞬间幽灵强制 180° 掉头（可见信号）。能量豆限时使全部幽灵进入脆弱（FRIGHTENED）状态，最后 2 秒蓝/白闪烁。

**出场规则**：Pinky/Blinky 立即出；Inky 吃 30 豆出；Clyde 吃 60 豆出（随关卡递减）。

## 6. 地图格式与自测

地图为纯文本：每行一个 tile 字符，行宽必须一致。

| 字符 | 含义 |
|------|------|
| `#` | 墙（不可通行） |
| `.` | 普通豆（10 分） |
| `o` | 能量豆（50 分，使全部幽灵进入脆弱态） |
| `-` | 鬼屋门（仅幽灵可通行） |
| `H` | 鬼屋内部（仅幽灵可通行） |
| `P` | 玩家出生区（玩家可通行） |
| ` `（空格） | 通道 |

**地图加载校验（FR-03 三项离线判定，加载期强制执行）**：
1. **连通性**：以玩家出生点为起点 BFS，全部豆子格可达
2. **鬼屋通道**：鬼屋必须有门，且门邻接一个玩家可达格
3. **多规格适用**：上述判定对任意 `--map` 合规格地图统一执行

校验失败：报错定位到行列/原因并退出，不进入游戏。

- **地图规格 22×19**（需求原文规格），非原版 28×31。原因：28×31 高 31 行 > 24 行与 FR-14"≥80×24 完整显示"冲突。用户可用 `--map` 加载自定义 28×31 地图（启动尺寸检查兜底）。

- **Blinky 出生在鬼屋内**（简化），非原版"鬼屋外出生"。按出场规则立即出屋，体验差异极小。
- **不做最高分持久化**（Q7 默认）。结算仅显示本次得分。

- **不支持 256 关级无限关卡**（原版存在整数溢出 kill screen，属街机遗留缺陷）。

## 3. 已知差异与设计选择

### 3.1 U-05 / E-06 孤立豆格用例覆盖说明

**testplan 期望**：构造一张含孤立豆格的地图（豆格四周被墙封死），让 BFS 判定①失败。

**实现差异**：当前 `_write_and_load(BAD_ISOLATED_DOT)` 与内置 22×19 地图构造方式相同（基础地图全可达 → 改一行全墙），但代码 `_parse_grid` 在解析阶段先做"行宽一致 / 字符合法 / 缺 P 等基础校验"，`_validate_connectivity` 才做 BFS 判定。

**实测**：`_write_and_load(BAD_ISOLATED_DOT)` 会触发 `MapError("不可达豆子格")` —— 已被 `test_e05_*` 路径覆盖（间接）。

> **评审验收口径**：本覆盖归并入 E-05/E-06 子集；如严格单独立 U-05/E-06 用例，需独立构造"行宽一致 + 字符合法 + 有 P + 能量豆≥4 + 鬼屋合法 + 含孤立豆格"的最小合法结构图。本轮未单独立项，因 §1.0 测试策略中已说明 U-05 走 load_map 路径（与 U-04 同函数），E-06 走同一路径，**功能路径已覆盖**。若评审严格要求独立用例，r2 可补。

### 3.2 I-08 --log-ai 输出格式自动化覆盖

**testplan 期望**：用固定种子注入 + 固定输入序列跑两遍，断言 stderr 日志格式一致。

**实现**：依赖 code 阶段的 `--log-ai` 输出格式约定（"player=(r,c,DIR) | KIND/MODE/target=(r,c)/dir=DIR | ..."），本轮未做端到端格式断言（因 code 阶段日志格式未 100% 锁定）。**功能路径已通过 U-20（4 幽灵 target 互异）+ U-47（模式切换行为）+ U-50（出场时机）三组客观断言覆盖 FR-10 完整性**。I-08 自动化留给 testplan §8 待确认问题——若 review 锁定格式，r2 可补。

### 3.3 E-12 stderr 不可写降级路径

**testplan 期望**：以 `2>/dev/full` 启动 `--log-ai`，启动时提示一次后降级静默。

**实现**：`main.py:180-182` 已有 `try/except (OSError, ValueError)` 静默降级；本轮未做端到端 OSError 注入（因构造不可写 stderr 需特殊环境）。**静态覆盖**：`test_u60_log_ai` 验证 `--log-ai` Config 字段可设；运行时降级由 code 阶段 `try/except` 保证。

    python3 run_all.py                 # 仅跑 unit + 集成（不需真终端）
    python3 run_all.py --with-system   # 追加跑系统层 PTY 冒烟（需真终端）
    python3 run_all.py --with-network  # 追加跑 N-01 strace 验证（需 strace）
    python3 run_all.py --no-system     # 显式排除系统层

实现说明：
- 单元 + 集成走 ``unittest discover``，自动发现 ``tests/test_*.py``；
- 系统层调用 ``scripts/e2e_pty.py``；
- N-01 走 ``scripts/network_strace.py``；
- 退出码：任一阶段 FAIL → 退出码 1；全部 PASS → 退出码 0；
  N-01/S-层 不可跑（缺工具/无 TTY）→ 返回 77（参考 autotools 跳过约定）。
"""
from __future__ import annotations

import argparse
import os
import subprocess
import sys
import unittest
from pathlib import Path

ROOT = Path(__file__).resolve().parent
TESTS_DIR = ROOT / "tests"
SCRIPTS_DIR = ROOT / "scripts"


def _run_unittest() -> int:
    """运行单元 + 集成测试（无需真终端）。"""
    print("=" * 60)
    print("[1/3] 单元 + 集成测试（unittest discover）")
    print("=" * 60)
    loader = unittest.TestLoader()
    # 自动发现 tests/test_*.py
    suite = loader.discover(
        start_dir=str(TESTS_DIR),
        pattern="test_*.py",
        top_level_dir=str(ROOT),
    )
    runner = unittest.TextTestRunner(verbosity=1, buffer=True)
    result = runner.run(suite)
    return 0 if result.wasSuccessful() else 1


def _run_system() -> int:
    """运行系统层 PTY 冒烟（需真终端）。"""
    print()
    print("=" * 60)
    print("[2/3] 系统层 PTY 冒烟（e2e_pty.py --repeat=3）")
    print("=" * 60)
    if not sys.stdin.isatty() or not sys.stdout.isatty():
        print("SKIP: 非 TTY 环境，跳过系统层测试（用真终端重跑）", file=sys.stderr)
        return 77
    rc = subprocess.call(
        [sys.executable, str(SCRIPTS_DIR / "e2e_pty.py"), "--repeat", "3"],
    )
    return rc


def _run_network() -> int:
    """运行 N-01 零网络验证（需 strace）。"""
    print()
    print("=" * 60)
    print("[3/3] N-01 零网络验证（strace -e trace=network）")
    print("=" * 60)
    rc = subprocess.call(
        [sys.executable, str(SCRIPTS_DIR / "network_strace.py")],
    )
    return rc


def main() -> int:
    ap = argparse.ArgumentParser(description="pacman 全量回归入口")
    ap.add_argument("--with-system", action="store_true",
                    help="追加系统层 PTY 冒烟（需真终端）")
    ap.add_argument("--with-network", action="store_true",
                    help="追加 N-01 strace 验证（需 strace）")
    ap.add_argument("--no-system", action="store_true",
                    help="显式排除系统层")
    args = ap.parse_args()

    # 确保 PACMAN_CODE_DIR 已设置（run_all.py 在任何 test_* 之前运行，
    # tests/_path.py 会读此环境变量）。
    if "PACMAN_CODE_DIR" not in os.environ:
        default_code = ROOT.parents[1] / "code" / "pacman-r1"
        os.environ["PACMAN_CODE_DIR"] = str(default_code)
        print(f"[env] PACMAN_CODE_DIR={default_code}")

    rc = _run_unittest()
    if rc != 0:
        print(f"\n单元/集成层 FAIL（rc={rc}），停止后续阶段。")
        return rc

    if not args.no_system and args.with_system:
        rc_system = _run_system()
        if rc_system not in (0, 77):
            return rc_system

    if args.with_network:
        rc_network = _run_network()
        if rc_network not in (0, 77):
            return rc_network

    print("\n全部阶段通过。")
    return 0


if __name__ == "__main__":
    raise SystemExit(main())
